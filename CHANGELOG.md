# Changelog

All notable changes to Construct are documented here. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/) and the project follows [Semantic Versioning](https://semver.org/).

## [Unreleased]

### Added

- **Boundary registration is now an authenticated handshake.** `POST /api/embed/boundary/register` validates parent URL reachability and verifies an HMAC signature over `childInstanceId|nonce` when `CONSTRUCT_BOUNDARY_SECRET` is set. Conflicting parents are rejected unless `CONSTRUCT_BOUNDARY_ALLOW_OVERRIDE=1`; rotated configs are archived to `~/.construct/boundary.<ts>.json`. The bound state lives at `~/.construct/boundary.json` with `0600` permissions. Closes the multitenancy boundary stub.
- **Provider adapter extension contracts are now first-class.** `lib/cache-strategy-google.js` exposes `setCachedContentResolver(resolver)` so provider plugins can supply Gemini cachedContent resources without Construct owning the API call. `lib/providers/auth-manager.mjs` exposes `registerRefreshAdapter(provider, adapter)` for vendor-specific token rotation. `lib/provider-capabilities.js#probeProviderCapabilities` dispatches to an adapter's optional `probe(modelId)` export. Construct stays provider-agnostic; vendor integrations plug in through these contracts.
- **`construct reflect` auto-derives a summary when `--summary` is omitted.** Falls back to a digest of `.cx/context.md` plus the most recent session-summary observation. The auto-derived path is tagged `source:auto-derived` on the captured observation with a lower confidence (0.65 vs 0.9) so downstream consumers can distinguish operator-authored from agent-derived feedback.
- **Contract enforcement is now a real gate.** `agents/contracts.schema.json` defines the shape of `agents/contracts.json`; `lib/contracts/validate.mjs` exposes `validateContractsFile` (sync-time + CI) and `validateHandoff` (runtime). `construct lint:contracts` is the new CLI command. `npm run lint:contracts` and a matching `lint-contracts` CI job validate every push that touches `agents/`. Sync (`scripts/sync-agents.mjs`) fails fast when contracts diverge from the registry or reference schemas that no longer exist.
- **`workflow_contract_validate` MCP tool** routes a producer→consumer handoff through `validateHandoff`. Honors `CONSTRUCT_CONTRACT_ENFORCEMENT=warn|block` (default `warn`); `block` returns `BLOCKED_CONTRACT` with errors so the workflow refuses to advance.
- **Cross-surface consistency watcher** (`lib/doctor/watchers/consistency.mjs`). Five bundled drift checks run on a 15-minute cadence: hook manifest references resolve to real files; MCP tool exports match the dispatch table; `agents/role-manifests.json` keys resolve to registry personas; persona `promptFile` references exist on disk; `agents/contracts.json` validates (when the W2 validator is present). Blocking findings escalate; warnings record only. New `construct doctor consistency` CLI runs the checks once and exits non-zero on blocking findings.
- **Schema migration scaffolding** (`lib/migrations/`). `CURRENT_SCHEMA_VERSION` is the contract between the binary and machine-readable artifacts (registry, contracts, role-manifests, project config). New `construct migrate` CLI plans + applies migrations, defaults to dry-run preview with `--dry-run`. `checkCompatibility(artifactVersion)` surfaces three outcomes — compatible, needsMigration, needsUpgrade — so callers can route operators to the right action. v1 baseline stamps pre-versioned artifacts with `version: 1` without changing shape.
- **`lib/version.mjs`** centralizes installed-version reads and exposes `parseSemver` / `compareSemver` so doctor watchers and migration code stop duplicating `package.json` parsing.
- **Daemon safeguard contract** (`lib/daemons/contract.mjs`). `createDaemon(spec)` enforces bounded lifetime, idle shutdown, heartbeat, single-writer lock, killswitch env, and resource caps. `classifyPacket()` routes per-item TTL + retry-budget decisions. Every long-running Construct process is required to use this contract.
- **Intake daemon** (`lib/intake/daemon.mjs`). Polls `.cx/inbox/`, classifies new files, writes packets to `.cx/intake/pending/`, dead-letters TTL-exceeded or retry-exhausted items to `.cx/intake/dead-letter/`. Killswitch: `CONSTRUCT_INTAKE_DAEMON=off`.
- **Post-execution rule verifier hook** (`lib/hooks/rule-verifier.mjs`). Stop hook that audits the session transcript for consequential actions (commits, pushes, edits to protected files) and classifies whether each had a preceding approval signal. Intent-based — no specific word is required; the classifier is pluggable for LLM-graded inference. Records `.cx/audit.jsonl` entries with verdict pass / fail / inconclusive.
- **PR auto-review workflow** (`.github/workflows/pr-review.yml`). On `pull_request: [opened, synchronize, ready_for_review]` runs `construct review --persona=cx-reviewer` and posts findings as a single PR comment. Read-only — never commits, never auto-approves.

### Changed

- **Comment lint blocks misleading "future implementation" wording.** New banned patterns: `phase [abc] follow-up`, `in a real implementation`, `would go here`, `coming soon`, `not yet supported`. Hits enforce on PostToolUse and via `construct lint:comments`. Existing offending comments rewritten honestly (no behavior change).

### Removed

- **Dead `getPendingActivations` export from `lib/hooks/proactive-activation.mjs`.** Had no consumers and carried a misleading "in a full implementation" comment.

### Fixed

- **Docs site build (Fumadocs) was breaking on unquoted colons in frontmatter values.** Quotes every affected `description:` and `title:` line so the YAML parses cleanly. Restores the Pages deploy.

## [1.0.6] - 2026-05-23

### Added

- **MCP parity for the org profile and learning surfaces** (`lib/mcp/tools/profile.mjs`). The construct-mcp stdio server now registers 11 new tools wrapping the PR #67 capabilities so subagents reach them without shelling out: `profile_show`, `profile_list`, `profile_drafts`, `profile_health`, `outcomes_summary`, `outcomes_record`, `knowledge_add`, `profile_create`, `profile_archive`, `sandbox_list`, `learning_status`. Read-only tools are direct calls; mutating tools require `confirm=true` matching the existing storage_reset pattern; `profile_archive` additionally requires a substantive `reason`. `optimize_apply` and `optimize_rollback` stay CLI-only because they mutate registry state. Refs `construct-pxi`.
- **GraphRAG global query over the entity graph** (`lib/knowledge/graph.mjs`). New retrieval primitive answers "how does X relate across the project?" questions that pure semantic search handles poorly. Reads the existing entity store, builds an undirected graph from `relatedEntities[]`, detects communities, ranks them against the query via BM25 over central-member summaries, and returns structured communities with top members. Exposed to subagents as the `knowledge_graph_ask` MCP tool. Schema migration `db/schema/006_graph.sql` adds the Postgres projection for team and enterprise deployments; the JSONL entity store stays the source of truth in solo mode. Refs `construct-sl7`.
- **`construct profile set` previews structural changes before writing.** Shows a role / intake taxonomy / department diff between the current and target profile, supports `--dry-run` to preview without writing and `--yes` to skip the confirm prompt. Selecting the already-active profile is now a clean no-op. Refs `construct-78v`.
- **`construct profile archive` previews the destructive move before running.** Gathers a reason interactively when missing, lists the exact files that move and what stays (observations and outcomes are preserved), and confirms before any rename. Supports `--dry-run` and `--yes`. The 8-character minimum reason is enforced up front. Refs `construct-78v`.
- **Functional test for MCP parity** (`tests/functional/mcp-parity.functional.test.mjs`). Boots the real `lib/mcp/server.mjs` over stdio, performs the JSON-RPC handshake, and asserts each new surface is reachable and writes the expected durable artifact when confirmed. Closes the loop the unit tests can't see.

### Changed

- **Project documentation now follows `docs/STYLE.md` end-to-end.** A style pass landed across `docs/`, `agents/prompts/`, `skills/`, `templates/`, `rules/`, `commands/`, `examples/`, and the root project docs. CHANGELOG history and `CLAUDE.md` remain exempt per the existing style rules.
- **`lint:prose` is now scope-correct.** Fenced code blocks and inline code spans are excluded from prose policy (code samples are not prose), and agent-platform sync targets (`.claude/`, `.codex/`, `.opencode/`) plus nested `node_modules/` are properly skipped.

### Removed

- **Two completed migration scripts**. Both ran once against the tree they targeted and the work has landed; the resulting test-suite references to them are also cleaned up.

### Fixed

- **mcp-manager test flake on Ubuntu node 22**. `makeRepoCopy` carried `.cx/` into the test fixture, and a stale `.cx/sync.lock` PID could collide with a live process on the runner. The `.cx` directory is now excluded from the copy so sync tests are self-contained.

## [1.0.5] - 2026-05-22

### Added

- **A1 session-end auto-reflect hook** (`lib/hooks/session-reflect.mjs`). Closes the manual-reflect gap. A Stop hook now runs at every session end, reads the transcript, and writes a deterministic `session-summary` observation into `.cx/observations/` via the existing `observation-store` API. The extractor (`lib/reflect/extractor.mjs`) is pure-function, O(n) over transcript lines, no LLM call. Hard 500ms wall-clock budget. Captures session id, project, and current git sha. Skips trivial sessions (no tool calls + very short final text). Opt out with `CONSTRUCT_REFLECT_AUTO=off`. `lib/reflect.mjs` exports `runReflectAuto({ transcriptPath, cwd, sessionId, durationMs })` for direct invocation. Registered in `platforms/claude/settings.template.json` as `stop:auto-reflect`. Refs `construct-h47`.
- **A2 research persistence** (`lib/knowledge/research-store.mjs`). `construct knowledge add --source=research --slug=<id> --topic="..." --confidence=<confirmed|inferred|weak>` ingests stdin into `.cx/knowledge/external/research/<slug>.md` with frontmatter (topic, confidence, sources, expiresAt, profile). Schema rejects `confidence=confirmed` without sources. Indexed for future hybrid search. The `commands/understand/research.md` prompt now ends with the persistence step. Refs `construct-32d`.
- **A3 specialist outcome capture** (`lib/outcomes/record.mjs`, `lib/outcomes/aggregate.mjs`). Every specialist outcome can be recorded into `.cx/outcomes/<role>.jsonl`. Aggregator produces `_summary.json` with per-role rolling success rate and 30-day window. `lib/intake/classify.mjs` now consumes `outcomeBoost(cwd, role)` as a tiebreaker capped at ±0.05 (regression-tested: clear keyword winners never get inverted). Refs `construct-bya`.
- **B1 profile schema and four principled profiles** (`schemas/profile.schema.json`, `profiles/{rnd,operations,creative,research}.json`, `lib/profiles/loader.mjs`). First-class org profile concept. Default is `rnd`, backward-compat with every existing project. Four profiles are organized by work loop (build / fulfill / produce / investigate) rather than industry. `construct.config.json` gets a `profile` field. Refs `construct-cuc`.
- **B2 profile-aware intake classifier** (`lib/intake/classify.mjs` refactor, `lib/intake/tables/{rnd,operations,creative,research}.mjs`). The classification table moved per-profile. RND behavior is locked byte-for-byte by `tests/intake/golden-rnd.test.mjs` written before the refactor. `classifyRdIntake({ profile, cwd })` accepts a profile id; default behavior unchanged for existing callers. Refs `construct-qto`.
- **B3 formalized flavor overlays + custom-profile escape hatch** (`schemas/flavor.schema.json`, `lib/flavors/loader.mjs`, `scripts/migrate-flavors.mjs`, `lib/profiles/validate-custom.mjs`, `scripts/lint-profiles.mjs`, `npm run lint:profiles`). All 53 overlays in `skills/roles/` migrated to declare `profiles: [rnd]` + `cap: 1`. Per-role flavor cap of 6 enforced. User-defined `.cx/profile.json` with `custom: true` is validated against the schema (max 8 stages, max 12 intake types, max 40 roles, classificationTable must live under `.cx/`). Refs `construct-heg`.
- **Learning telemetry dashboard** (`npm run learning:status`). One-screen table: active profile, observations + last-24h delta, research findings, per-role outcome rates. Single answer to "is this thing actually learning?" Refs `construct-mov`.
- **Functional testing discipline** (`tests/functional/`, `npm run test:functional`). Permanent home for end-to-end checks that exercise a feature in an isolated tmpdir against real code, no mocks. A1 and B1 ship with functional tests today; every multi-component change going forward must add one. See `tests/functional/README.md` and the new rule in `CLAUDE.md`.
- **Prose lint** (`scripts/lint-prose.mjs`, `npm run lint:prose`, `.proseignore`). No em-dashes in user-facing markdown. Default scope is changed-files-only so the rule prevents regressions without forcing a mass historical rewrite. `docs/STYLE.md` documents the voice and punctuation rules.
- **`docs/STYLE.md`** (new). Voice, punctuation, structure rules for everything in this repo. `CLAUDE.md` and `CONTRIBUTING.md` both reference it.
- **Open source side-project framing** in `README.md` and `CONTRIBUTING.md`. The README opens with a personal note ("I am not a developer, this is a side project"). Tone now consistent across high-traffic docs.
- **`construct profile` subcommand**. `show`, `list`, `set <id>` for switching the active org profile. `set` writes `construct.config.json` through the validated config writer.
- **A3 production trigger**: `lib/hooks/agent-tracker.mjs` now calls `recordOutcome` on every Task SubagentStop, so `.cx/outcomes/<role>.jsonl` fills in real use, not just synthetic test calls.
- **Profile-aware sync**: `scripts/sync-agents.mjs` filters `registry.agents` by the active `profile.roles`. RND lists all specialists so behavior is unchanged for the default; non-RND profiles emit only their declared roles.
- **Profile-aware intake routing**: `lib/intake/prepare.mjs` resolves the active profile and passes both `profile` and `cwd` into `classifyRdIntake`, so production daemon classification follows the project's chosen loop and gets the A3 outcome boost.
- **`construct status` surfaces learning loops**: appended block with active profile, observation count + 24-hour delta, research file count, outcome-role count.
- **Pre-push gate runs `lint:prose` and `lint:profiles`**. CI workflows added: `lint-prose`, `lint-profiles`. The new rules now fail builds at push time and on every PR.
- **CI changes filter expanded** to include `profiles/**` and `schemas/**` under both `code` and `agents` paths so edits there actually trigger the relevant jobs.
- **Profile lifecycle as a research artifact, not a JSON exercise** (`docs/concepts/profile-lifecycle.md`, `lib/profiles/lifecycle.mjs`). New profiles go through discover (cx-ux-researcher), frame (cx-product-manager), architect (cx-architect), validate (cx-evaluator), promote, monitor, archive. `construct profile create <id> --role=<id> --department=<id>:<name>` scaffolds the draft profile, a requirements brief, one persona artifact per declared role (with the canonical Goals / Frustrations / Decision rights / Handoffs / Output contract / Failure modes / Evidence sections), and one charter doc per declared department. `construct profile drafts` lists in-progress drafts. `construct profile health <id>` reports per-profile observation counts and per-role outcome rates over a window. `construct profile archive <id> --reason="..."` retires a curated profile cleanly into `archive/profiles/<id>/`; observations and outcomes stay durable. `CLAUDE.md` requires the lifecycle for anything that lands in the curated catalog.
- **Persona and skill research methodology** (`docs/concepts/persona-research.md`, `templates/docs/persona-artifact.md`, `templates/docs/skill-artifact.md`). Grounded in Goodwin and Cooper for persona patterns, Galbraith STAR and Lawrence-Lorsch differentiation for departmental structure, and Bloom-style observable competencies for skills. Each persona declares decision rights, handoffs, output contract, failure modes, and evidence sources. Each skill declares scope, observable outcome, provenance, and the roles that use it. Without evidence the artifact is rejected at review.
- **Departmental structure on every profile**. The flat role list was misleading; real orgs delegate by department. Schema now requires `departments[]` with a non-trivial charter (>= 20 chars) per entry, and lint:profiles enforces that every declared role belongs to exactly one department in each profile. The four curated profiles (rnd, operations, creative, research) have been migrated to use departments grounded in their actual work loop.
- **Schema caps raised to reflect real org headcount.** Roles per profile: 40 → 80. Intake types: 12 → 24. Stages: 8 → 12. Department roster: 20 per department, 12 departments per profile. The earlier caps were arbitrary and would have forced bad shoehorning for any non-trivial org.
- **A4 evaluator-optimizer safety gate** (`scripts/optimize.mjs`). Inverted the default from auto-apply to preview-only. `--apply` writes a `.bak` next to the skill file before mutation and logs to `~/.cx/prompt-history/<agent>.jsonl`. Apply is rate-limited to once per agent per 7 days. `--rollback` restores from the latest backup. `lib/hooks/session-optimize.mjs` now passes `--dry-run` so hook-driven runs never modify prompts. New functional tests cover the gate.
- **Sandbox command** (`lib/sandbox.mjs`, `construct sandbox create|list|delete|prune`). Lightweight isolated tmpdirs under `~/.cx/sandboxes/<id>/` for specialist dry-runs and QA validation without polluting the working repo. Each sandbox gets a minimal `.cx/`, a stub `context.md`, and a `construct.config.json` (optionally with a profile id).
- **Outcomes tagged with active profile** in `lib/hooks/agent-tracker.mjs` so per-profile `construct profile health` rollups have real data, not just a project filter.
- **observation-store `extras` field**. Structured metadata travels in a first-class slot instead of being stuffed into `content` as appended JSON. Plain objects only, 2 KB cap. `lib/reflect.mjs` migrated; existing callers unaffected.
- **`construct init --profile=<id>`**. Persists the active profile into `construct.config.json` during first-time project setup. Validates against the curated catalog; unknown ids are rejected with the available list.
- **`construct drop`** is wired to the existing `lib/drop.mjs` implementation. The catalog has advertised it for a while; now it actually runs.
- **`construct docs <check|verify|update|site>`** parent dispatcher. The catalog had this listed but only the colon-namespaced forms (`docs:verify`, etc.) were callable. Both forms work now.
- **CLI catalog accuracy test** (`tests/cli-catalog-accuracy.test.mjs`). Every catalog entry must have a handler; every handler must be in the catalog or in an explicit allowlist. Caught the `docs` and `drop` gaps above.
- **Pre-release channel automation** in `.github/workflows/release.yml`. Semver pre-release tags (`v1.0.5-alpha.1`, `-beta.N`, `-rc.N`, or anything else with a `-` suffix routed to `next`) are detected and routed: npm publishes with `--tag <channel>` (so `latest` is not moved); Docker pushes `:<version>` and `:<channel>` but not `:latest`; Homebrew tap bump is skipped; the GitHub Release is marked pre-release. Pattern documented in `docs/maintenance/release-and-deploy.md` § Pre-release channels and referenced from `docs/maintenance/release-policy.md`.

### Fixed

- **Profile loader never read `construct.config.json`**: every caller passed only `cwd`, so the `profile` field set by `construct profile set` was silently ignored. `resolveActiveProfile` now reads the config file itself with precedence `explicit arg > .cx/profile.json (custom) > construct.config.json > rnd`. Locked by regression tests in `tests/profiles/loader.test.mjs`.

- **Doctor: copilot adapter parity false-drift**. `lib/parity.mjs` `checkCopilot` was the only surface that filtered out `internal: true` agents from the expected set while the sync script writes all 29 to `~/.github/prompts/`. The check now uses the shared `entriesForSurface` helper, matching Claude, OpenCode, and Codex. `construct doctor` is now 0 failed where it had been 2 failed pre-A1.
- **Doctor: git hooks unwired**. `core.hooksPath` set to `.beads/hooks` to activate the pre-commit policy gates.

### Fixed

- **Release publish: `setup-node@v6` + `registry-url` injects `github.token` as `NODE_AUTH_TOKEN`**, overriding npm's native OIDC Trusted Publishers exchange and causing a 404 on every tag push. Fix: remove `registry-url` from the `setup-node` step; configure the registry separately so npm can perform the OIDC exchange unobstructed. No `NPM_TOKEN` secret required or used.
- **Release publish: `npm whoami` gate added** before packaging begins — auth failures surface in seconds rather than after uploading 640 files.
- **Pre-release preflight script** (`scripts/pre-release-check.mjs`, `npm run release:preflight`): validates clean tree, on-main, CHANGELOG entry, tests, comment policy, docs:verify, npm audit, and `npm pack --dry-run` locally before tagging so CI is never the first to find a release problem.
- **Failed CI release runs purged**: 14 failed/cancelled release workflow runs deleted from Actions history.

## 1.0.0 — 2026-05-08

Initial public release.

Construct ships as an agent orchestration layer for OpenCode, Claude Code, and other coding surfaces — runnable locally for individuals — with a single user-facing persona that routes work across specialist agents and keeps shared project state aligned.

### Highlights

- **Distribution** — three install modes: project-pinned npm devDependency, global npm install, and bootstrap shims (`.construct/run.mjs` + `bootstrap.sh` + `bootstrap.ps1`) for non-Node projects. `construct init --devcontainer` for VS Code teams.
- **Provider system** — capability-driven contract with five built-in providers (GitHub, Atlassian Jira, Atlassian Confluence, Slack, Salesforce), per-provider circuit breakers, and a stable plugin contract for custom providers.
- **Plugin retrieval engine** — six-layer plugin contract (Embedder, Chunker, Indexer, Fuser, Reranker, Compressor) with RRF + MMR defaults and an eval harness covering Recall@k, MRR, and NDCG.
- **Security middleware** — CSRF double-submit, CORS allowlist, token-bucket rate limiting, structured JSON-line logger. Multi-token dashboard auth with per-token roles.
- **Reliability** — runtime contract enforcement (`enforcePacket` with chain-hashed JSONL violation log), embed daemon supervision (launchd / systemd / Task Scheduler), full system backup with SHA-256 manifest.
- **Storage** — hybrid file-state + Postgres+pgvector + JSON vector index fallback, configurable embedding models (local ONNX, OpenAI, Ollama, hashing).
- **AWS deploy** — Terraform modules for ECS/Fargate ≥ 2 tasks behind ALB with sticky sessions, RDS with pgvector parameter group, Secrets Manager, CloudWatch alarms, multi-stage hardened Dockerfile.
- **CI/Release** — matrix CI (ubuntu/macos × Node 20/22 + real Postgres + gitleaks), release pipeline producing Node SEA binaries per OS/arch, Docker GHCR push + Trivy scan, npm publish with provenance.
- **Documentation** — full doc set: getting-started, installation guides, provider guides, operations runbooks, security, AWS deploy, CLI/config/hooks/MCP-tools reference. Deprecation infrastructure and semver policy.

### Hard release-gate contracts

Every commit and PR is enforced against the same five local gates and the canonical commit + PR templates:

- `npm test`
- `node bin/construct lint:comments`
- `node bin/construct docs:verify`
- `node bin/construct docs:update --check`
- `npm run lint:templates`

These are encoded in `rules/common/release-gates.md`, summarized in `AGENTS.md`, and reflected in the CI matrix.
