# Changelog

All notable changes to Construct are documented here. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/) and the project follows [Semantic Versioning](https://semver.org/).

## [Unreleased]

### Added

- **Opt-in 1Password service-account path for non-interactive secret resolution (`lib/providers/secret-resolver.mjs`).** When `OP_SERVICE_ACCOUNT_TOKEN` is set, `op read`/`op run` resolve secrets with no desktop app, biometric, or `op signin` — the right primitive for Construct's multi-process/daemon/headless shape (verified against 1Password's current docs: service accounts are available on Individual/Family plans, and the token makes the CLI non-interactive). The resolver now forwards the token from the caller's env into the `op` subprocess so a runtime can source it from the OS keychain instead of plaintext, and the `OP_NOT_SIGNED_IN` guidance names the service-account alternative. The desktop app integration remains the default when no token is set (backward-compatible; existing `resolveOpRef` callers unaffected). `construct doctor credentials` now reports the active auth mode (`describeOpAuthMode` — `service-account` vs `desktop-session`, including whether the desktop session is signed in, so a cold session that would prompt repeatedly is visible), and the credentials cookbook documents the token with its vault/rate-limit caveats (`construct-192h.6`). Note: a service account cannot read the built-in Personal/Private vault and the Individual tier is rate-limited to ~1k reads/day, so a rate-limit-safe resolve-once model for short-lived processes is tracked in `construct-trxz.11`. Proven by `tests/secret-resolver-service-account.test.mjs`.

### Fixed

- **Service spawns now receive the merged `liveEnv` (`construct-192h.8`).** `lib/service-manager.mjs` computed `liveEnv` (config.env merged over `process.env`) but spawned cm/opencode/copilot-bridge **without** it, so config.env-only vars — including `CONSTRUCT_OP_ENV_FILE` and `OP_SERVICE_ACCOUNT_TOKEN` — never reached those children (only doctor/oracle got the env). All five services now spawn with `liveEnv`, matching the doctor/oracle shape, so the service-account token reaches every `op run`. Proven by `tests/service-manager/spawn-env.test.mjs`.
- **A single `op run` at the `construct dev` parent replaces the per-service wrap (`construct-trxz.11`, realizes ADR-0049's "resolve at a stable parent").** The first Design A wiring launched each of ~5 daemons under its own `op run`, relying on 1Password's session to dedupe the prompt across five launches (never proven) and, under a service-account token, multiplying reads (~5 services × the catalog's refs each startup — a real concern against the Individual tier's ~1k reads/day). `construct dev` now re-execs itself once under a single `op run --env-file …` (`maybeReExecUnderOpRun`, `lib/providers/op-run.mjs`): every `op://` reference resolves one time (one biometric unlock) into the parent env and the detached daemons inherit the resolved keys. A `CONSTRUCT_OP_RUN_ACTIVE` sentinel makes the per-service `wrapWithOpRun` a no-op inside the re-exec'd parent so nothing nests a second `op run`; the per-service wrap is retained as the fallback for daemons started outside `construct dev` (a doctor/oracle restart from a hook). **Reworks `construct-trxz.3`:** `op run` masks the process it directly wraps, so under the single parent the `construct dev` output is masked but the detached daemon log files (local-only, under the state dir) are not — the accepted, documented cost of resolving once, with the per-service fallback still masking any daemon it wraps directly. Un-opted path (no `CONSTRUCT_OP_ENV_FILE`, or `op` absent) is byte-for-byte unchanged and never invokes `op`. Proven by `tests/functional/op-run-wrap.functional.test.mjs` and `tests/functional/service-op-run-wiring.functional.test.mjs`; ADR-0049 updated.

- **Provider execution timeouts corrected from impossible defaults (`construct-o6t8.1`, `construct-o6t8.2`).** The provider worker's HTTP timeout defaulted to **200 ms** (`lib/orchestration/worker.mjs`), aborting every real LLM call before it could return; the remote-orchestration client hard-coded the same 200 ms on its run POST and left the status poll entirely unbounded (`lib/mcp/tools/orchestration-run.mjs`). Both now use sane, env-overridable defaults grounded in two code-confirmed references — `openai/openai-python` and `anthropics/anthropic-sdk-python` both default the overall request timeout to 600 s — landing on a conservative 120 s worker floor (`CONSTRUCT_PROVIDER_TIMEOUT_MS`) and a 30 s remote per-request bound (`CONSTRUCT_ORCHESTRATION_TIMEOUT_MS`), with the status poll now carrying the same `AbortSignal.timeout`. Both read the override with a parse-then-default-when-unset pattern so an explicit `0` is honored rather than coerced away by `||`. A timed-out remote request now reports `"…timed out after <N>ms"` instead of the misleading `"…not reachable…"` — a status-honesty fix beyond the timeout itself.
- **Timeout test fixtures no longer manufacture or depend on the production default (`construct-neq9.6`).** `tests/audit/f09-orchestration/provider-timeout.test.mjs` (and its `.red` sibling) and `remote-per-request-timeout.test.mjs` pinned their determinism on the old 200 ms production default; they now set an explicit small `CONSTRUCT_PROVIDER_TIMEOUT_MS` / `CONSTRUCT_ORCHESTRATION_TIMEOUT_MS`, so the proof of boundedness is independent of the shipped default — closing the fixture-driven-default anti-pattern where a test's settle-bound had silently defined a production value.
- **Corrected inaccurate user-facing error and remediation strings (`construct-xj96.*`).** Hints that named non-existent commands or stale paths now name real ones: `construct workflow init` → the real `workflow` subcommands (`lib/workflow-state.mjs`, `lib/oracle/gaps.mjs`, `lib/intake/session-prelude.mjs`); `construct census` / `construct outcomes aggregate` removed (`lib/oracle/gaps.mjs`); legacy `~/.construct/config.env` advice repointed to the XDG path (`bin/construct`, `lib/cli-commands.mjs`); a bogus `CONSTRUCT_ASR_BACKEND` suggestion (`lib/document-extract.mjs`, `bin/construct`) and an unreachable Langfuse auto-config block (`bin/construct`) removed; `construct setup` → `construct install`; `doctor hooks` → `hooks:health` (`lib/hook-health.mjs`); the `MODEL_UNRESOLVED` degradation reason's double period fixed (`lib/embedded-contract/execution.mjs`); the `--max-stored` observation-cap remedy and stale scope-lifecycle doc citations repointed. Each verified by an `rg` showing zero remaining bad references at the named sites; the `postgres` store enum was intentionally kept (ADR-0021 Mode-C) with only its false remediation text corrected.
- **Completed the honest terminal-state taxonomy on every surface (`construct-fbxv`, AP5 validation pass).** The runtime now reports `degraded` for any degraded run that is not prepare-only — including a run that *executed* with a capability gap (`webUnavailable`), which previously surfaced as bare `completed` with only a side flag (`lib/orchestration/runtime.mjs`). `shapeRun` (`lib/mcp/tools/orchestration-run.mjs`) and `executeRun` now derive identical statuses, and `shapeRun` still re-derives `degraded` for legacy runs persisted as bare `completed`. The remote poll-loop `TERMINAL` set gained `degraded` and `completed-prepare-only`, so a finished degraded/prepare-only remote run is no longer polled to the deadline and misreported as *"still executing"*. `hostAdapterMetadata` now surfaces the top-level `run.degraded`/`degradationReason` (not just `execution.degraded`), fixing the `orchestrate run --json` blind spot (`construct-fbxv.5`). The ACP completed-event message no longer describes an executed run as *"prepared tasks — inline backend, no specialist execution"* — it maps `completed`/`completed-prepare-only`/`degraded`/`completed-with-failures` honestly (`lib/acp/server.mjs`).
- **Closed a trust-boundary regression on the remote `orchestration_status` path.** `statusViaService` (`lib/mcp/tools/orchestration-run.mjs`) shaped remote run data but skipped the ADR-0050 fail-closed web-evidence grader that `runViaService` applies, so a remote/team service could return `webEvidence` pre-marked `trust:'trusted'` and it would reach the host ungoverned. Every status response now runs through `governRemoteWebEvidence` before `shapeRun`, exactly as the run path does.
- **Consolidated numeric-env parsing and fixed two latent defects from the defaults work (`construct-o6t8.3`).** `resolveMsSetting` was renamed `resolveNonNegativeSetting` — it resolves byte caps, counts, and loop bounds, not only milliseconds. The provider-worker timeout dropped a bespoke `Number(env)` parse that turned a garbage `CONSTRUCT_PROVIDER_TIMEOUT_MS` into `NaN` (an `AbortSignal.timeout(NaN)` aborts every provider call instantly) or a negative value into a giant delay; it now uses the shared resolver (garbage/negative → the exported `PROVIDER_TIMEOUT_DEFAULT_MS` = 120 s, explicit `0` honored). The embed daemon's log-rotation callback called the helper without importing it — a `ReferenceError` that broke rotation on daemon start — now fixed. The remote-timeout client's private duplicate parser was replaced with the same shared helper.
- **Removed a duplicated, unreachable `anthropic`/`openrouter` branch pair** in `resolveWebCapability` (`lib/orchestration/web-capability.mjs`) left by a botched edit.
- **The intent verifier's presence gate no longer triggers a 1Password prompt on the routing hot path.** `isApiKeyConfigured` (`lib/intent-classifier.mjs`) now uses `hasSecret` instead of the materializing `resolveSecret`, so deciding whether to run the *background* verifier never spawns `op read`; key materialization stays lazy in `defaultModelCaller` where a call is actually made.
- **`construct publish --recording=<name>` and `--figures` now change behavior instead of being silently dropped (`construct-xj96.11`).** The parser was extracted to a testable `parsePublishArgs`, the two declared-but-unhandled flags are wired to `runPublish`, and unknown `--` flags are surfaced as a warning rather than discarded (`lib/publish.mjs`).
- **Repointed the last stale `construct graph build` references** (real: `construct matrix build`) in two lib file headers (`lib/graph/staleness.mjs`, `lib/doctor/watchers/graph-staleness.mjs`) and the dead `scope-lifecycle` README link (real: `profile-lifecycle`). Residual cookbook/ops-doc stale-command and legacy `~/.construct` path guidance is captured in `construct-1p2a`.

## [1.4.2] - 2026-07-01

### Fixed

- Made the F08 `[R35]` excessive-agency audit test hermetic: it now asserts on the exported grant source (`COPILOT_AGENT_TOOLS`) instead of reading the committed `.github/agents/construct.agent.md`, which is regenerated/pruned by concurrent repo-root syncs (including the tool-repo `npm ci` postinstall on a runner without Copilot) and so raced during the release gate. Host-config-parity still verifies the generated file matches the source; the test keeps a presence-guarded cross-check.
- Keyed the registry loader cache on `rootDir` (`lib/registry/loader.mjs`), fixing an intermittent CI failure where the certification scenario fixtures reported a specialist (cx-engineer) missing its `refusalBoundaries`. The module-level cache was keyed only on the org dir's mtime and the legacy-overlay mtime — two roots (the repo and a tmpdir test root) can share those, so one root's registry could bleed into a later `loadRegistry` call for a different root, yielding a specialist without its `promptFile` and therefore without the prompt-derived `perspective.failureMode`. The cache key (and `clearCache`) now include `rootDir`, so a load for a different root can never return another root's cached registry. Tracked as the flaky-cert bead.

### Added

- Gave the orchestration worker a scoped, governed **live web capability** for web-capable specialists, closing the capability-honesty seam where the orchestrator promised "web access lives with the researcher" but no execution path wired it (construct-bcbo.15, ADR-0050). A four-agent adversarial investigation confirmed every orchestration path ran specialists as tool-less completions, so a researcher told to "fetch every URL" with no fetch tool could only refuse or fabricate — a collision with the no-fabrication rule. The fix adds a typed **WebGrant** resolver (`lib/orchestration/web-capability.mjs`) in strict priority: **governed** (`WEB_SEARCH_URL` set → the worker runs a client tool-use loop executing Construct's own `webSearch()`, so F08 `trust:'untrusted'` + Admiralty grading hold by construction), **provider-native** (no `WEB_SEARCH_URL` → Anthropic's `web_search_20250305` or OpenRouter's `openrouter:web_search` server tool — the deprecated `:online`/web-plugin forms are not used — with every citation re-graded through the single grader), **host-delegated** (explicit opt-in), and **unavailable** (a typed `capability-unavailable` that forces an honest insufficient-evidence refusal and degrades the run). The F08 grader was extracted to `lib/mcp/tools/web-search-governance.mjs` as the **single chokepoint**: it is the only producer of web evidence on every path, so a citation can never reach a specialist ungoverned or mislabeled as trusted. Only specialists that declare `liveWebAccess: true` (the researcher) get the tool — least-privilege; `claudeTools` is not the signal because most specialists carry `WebSearch`/`WebFetch` as a broad Claude-host grant. The remote orchestration service (out-of-repo) is handled fail-closed: `runViaService` re-runs `governWebResults` on ingress (`governRemoteWebEvidence`) so a foreign server cannot inject trusted or ungoverned web text, marking the run degraded when it had to re-govern. The orchestrator micro-prompt and the cx-researcher persona were corrected to stop asserting a capability that may not be wired and to require an honest "could not reach the web" over a fabricated citation. Supersedes the ADR-0020/0021 lens boundary for web-capable specialists only; inline/prepare-only and non-web specialists are unchanged. Proven by `tests/orchestration-web-capability.test.mjs` (resolver priority), `tests/orchestration-worker-web.test.mjs` (all four grant modes + round cap + honesty guard, mocked providers), and `tests/orchestration-remote-web-guard.test.mjs` (fail-closed remote ingress). Live end-to-end web needs the operator's provider keys; the mechanism, governance, and honesty guard are proven with mocked providers.

### Security

- Extended the secret audit trail into the long-lived processes that resolve credentials outside the CLI (`construct-trxz.13`, closing the F02 residual). `enableSecretAuditTrail()` was wired only at the CLI entrypoint (`bin/construct`), so an op read performed inside a separate process escaped the durable trail. Wired the sink at the entry of every long-lived Construct process: the **MCP server** (`lib/mcp/server.mjs`) and the **embed daemon** (`lib/embed/worker.mjs`) genuinely resolve provider credentials in their own process — the MCP server via provider-backed orchestration (`executeRun` → `runTaskViaProvider` → `resolveSecret`) and provider tools, the embed daemon via `resolveLLMKey` on snapshot ticks — closing the real gap; the **doctor** (`lib/doctor/index.mjs`) and **oracle** (`lib/oracle/daemon-entry.mjs`) daemons wire it defensively so a future provider-touching tick is covered. A transitive-import reachability sweep over every process entrypoint in `lib/` confirmed no other long-lived process resolves credentials outside the CLI: the team worker (`lib/worker/entrypoint.mjs`) executes jobs as subprocesses and resolves nothing in-process; the ACP server runs inside `construct acp` (already CLI-covered); and the remaining hits resolve only the non-secret `OLLAMA_BASE_URL`/`OLLAMA_HOST` local URL or reach a dead code path (`refreshLiveOpenRouterCatalog`, which has zero callers). The sink is idempotent and best-effort (`emitAudit` swallows sink errors), so wiring never affects a daemon's behavior or a secret resolution. Proven by `tests/functional/secret-audit-daemon-wiring.functional.test.mjs`: a real spawned process resolves an `op://` reference through a stub `op` and asserts a value-free `op_read` record lands on the daemon-scoped trail (`doctorRoot()/audit-trail.jsonl`) with the secret value never present, plus a coverage guard that every wired entrypoint keeps the wiring.

Proven by `tests/audit/f02-secrets/generated-file-leak-scan.test.mjs`; `mcp-secret-ref.test.mjs` and `mcp-add-no-plaintext.functional.test.mjs` updated from the deferred contract to the flip. **[R14] precedence parity**: `resolveSecret` (`lib/providers/secret-resolver.mjs`) returned a directly-passed `env` value ahead of every file tier, while `loadConstructEnv` ranks the config files above `process.env` to defeat stale shell exports — so the same key present in both `process.env` and `config.env` with different values resolved to different credentials depending on the code path. ## [1.3.0] - 2026-06-29

This release makes OpenCode the primary conversation surface, retires the web/dashboard tier in favor of a terminal-first architecture, and consolidates the legacy registries into a single unified registry (RFC-0004). It contains two breaking changes — see **Removed**.

### Added

- Agent-reachable MCP tool surface: `find_tool` intent-driven tool discovery (ADR-0048), an artifact loop, and OpenCode auth hardening.
- Intent-driven, team-aware orchestration: requests route to teams with blocked-decision handling; typed team integration sources drive scoped `provider_fetch` reads.
- Oracle governance: swarm dispatch, a `cross-team-handoff-blocked` synthesized signal, and team governance oversight.
- Demo plug-in layer: `demo init --from-project`, an expanded canonical catalog of 6 terminal scenarios, and a self-demo guided tour via bare `construct`.
- `construct` CLI primitives: a `display-width` primitive and a shared presentation core with clickable links and chat ticker/wrap fixes.
- `registry:validate --unified` gates the unified registry (RFC-0004 Phase 1.4).

### Changed

- OpenCode is now the first-class conversation surface. `construct sync` installs the front-door agent, MCP wiring, and runtime plugin; the `construct` CLI remains setup/admin/headless infrastructure.
- The previous local conversation-loop capability has been replaced by `surfaces.opencode-primary` in the capability registry.
- All registry consumers (MCP `list_teams`/`get_team`, policy-inventory, staleness graph, doctor watchers) now read the unified registry instead of the legacy `contracts.json`/`teams.json` files.
- Demo execution is recording/tour oriented: VHS and Playwright surfaces are supported, with printed script steps as fallback.
- Research-shaped host conversations now classify through `orchestration_policy` and execute through `orchestration_run`; the OpenCode front-door prompt no longer implies that `workflow_invoke` itself performed evidence gathering.

- PDF artifact generation now preserves ordered-list numbering, loosens body and heading spacing, and widens page margins so published PRDs, decisions, research briefs, and generic PDFs read like release-grade documents instead of cramped exports.
- Bare `construct` launches chat; `construct chat` is deprecated.
- CI gates run through thin `npm run` wrappers over `bin/construct`; the workflows no longer re-spell the underlying commands.

### Removed

- **Breaking:** the `chat --web` browser launcher has been removed. Construct chat is terminal-only; there is no web/browser surface to launch.
- **Breaking:** the legacy `contracts.json` contract files have been deleted. Readers now resolve contracts from the unified registry; any consumer reading `specialists/contracts.json` directly must migrate to the unified-registry shape.
- Retired the dashboard web app and HTTP server, the native desktop chat window, and the dead Ink TUI — Construct is terminal-first (ADR-0039/0041 amended).
- Removed Construct's local conversation UI implementation, related package surface, docs page, and surface-specific tests.
