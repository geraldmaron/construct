# Changelog

All notable changes to Construct are documented here. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/) and the project follows [Semantic Versioning](https://semver.org/).

## [Unreleased]

### Added

- Wired post-export output validation into the publish path. `lib/output-quality.mjs` runs after a successful export and is the production consumer for the asset-quality validators that previously had only test callers: `export-validate` (real PDF page count, content roundtrip against the source headings, on-disk reference integrity), `brand-contrast` (WCAG AA palette assertion, advisory), and — at `render-smoke` and higher gate levels — `render-evidence` (screenshot capture). The gate level comes from the artifact's quality contract; every check degrades with a typed reason when its tool is absent, and only a real document-scoped validity failure marks the result not-ok. `construct publish` now prints validity, content-preservation, and render-capture lines. This clears the `module-test-only` audit findings for those modules by genuine wiring rather than baseline grandfathering; `visual-review` (a human-verdict recorder that cannot be auto-called without forging a verdict) is recorded in the deadcode audit's documented allowlist with its reason instead.

- Rendered fenced diagrams in PPTX export. The pptxgenjs deck builder previously had no case for fenced code, so ` ```mermaid `/` ```d2 ` source fell through into a body-text block — both overflowing the slide and silently dropping every diagram. `slideBlocks` now parses fences into `diagram`/`code` blocks; diagram blocks render to a monochrome sketch PNG (mmdc with the hand-drawn theme, `d2 --sketch`) embedded and scaled to fit the slide's remaining height, and a missing renderer records a typed error (failing closed if every diagram fails) rather than dropping the figure. `splitSlides` also treats a level-1 `#` heading as a slide boundary (pandoc slide-level 1, fence-aware) so a `#`-delimited deck splits per slide in PPTX the same way it does in the HTML deck. Covered by two new `tests/deck-export-pptx.test.mjs` cases.

### Fixed

- Navigated the `construct-asset-quality` research notes and corrected two speculative command references. The notes directory and its `subagents`/`synthesis` subdirectories now carry `meta.json` files (and are listed in the parent research nav), clearing the `unnavigated-doc-dir` audit findings; the `construct loop` and `construct lint:presentation` mentions — neither is a real command — were reworded to describe the authoring loop and the release-gate presentation lint, clearing the `review-doc-reference` findings.

- Deck HTML export rendered every content slide unstyled. Pandoc emits slides as `<section class="level1">`, but `construct-deck.html` styled only `section.slide`, so the slide frame, padding, and accent applied to the title slide alone. Retargeted the slide CSS to `.deck > section` (covers the title slide and pandoc's sections), reduced the type scale ~30% so slides read as refined rather than billboard-sized, and added a `.deck > section > img` rule that fits bare diagram images (which Pandoc does not wrap in `<figure>`) to the slide's remaining height — a tall sequence diagram was previously clipped by the slide's `overflow:hidden`.

- Implemented placeholder and empty-section presentation lint (`construct-cuxq.2.2`): `lintDocPresentation` now flags unresolved placeholders (`{{…}}`, `[object Object]`, TODO/TBD/FIXME/XXX) and empty sections (a heading with no content before the next same-or-higher heading). Both are gate-blocking through the existing release-gate wiring; all 27 golden fixtures stay clean, and the two `construct-cuxq.10.1` anti-fixtures plus the `construct-cuxq.2.1` pending tests are now enforced.
- Added isolated presentation-lint coverage (`construct-cuxq.2.1`): `tests/asset-quality/presentation-lint.test.mjs` exercises `lintDocPresentation` directly (it previously ran only as a release-gate side effect) — existing rules enforced, with unresolved-placeholder and empty-section cases pending `construct-cuxq.2.2`.
- Added post-export document validation (`construct-cuxq.5.1`, `construct-cuxq.5.2`): `lib/export-validate.mjs` adds `validatePdf` (real page count via `pdfinfo`), `contentRoundtrip` (extracts exported text per format and compares the source's key headings to catch dropped content), and `referenceIntegrity` (local image/link targets must resolve on disk) — replacing the prior `>1KB` file-size heuristic. Each emits a typed degradation when its tool is absent rather than passing silently. Verified end-to-end on a real rendered PDF (2 valid pages, 100% phrase preservation). Absorbs the `construct-amfg` PDF-fidelity work.
- De-branded generated output artifacts (`construct-cuxq.7.2`): removed the literal "Construct" wordmark from the PDF running footer (`construct-brand.typ`), the "Construct brief" footer label (`construct-pdf.typ`), and both HTML/deck title fallbacks and footers (`construct-web.html`, `construct-deck.html`) — generated documents now carry only the user's own title, classification, and date. Made the web masthead title a semantic `<h1>` (was a `<div>`), and removed Pandoc `$variable$` syntax from the HTML template comments, which Pandoc was interpolating — eliminating a latent bug that duplicated the entire document body inside the leading comment of every HTML export. Verified on rendered PDF/HTML/deck: zero template-imposed "Construct", a single `<h1>`, and proper `h1 → h2 → h3` order.
- Added a WCAG contrast validator and spacing scale (`construct-cuxq.7.1`): `lib/brand-contrast.mjs` computes WCAG 2.1 contrast ratios and validates the load-bearing brand text palette against AA — all text pairs pass, and `ink.faint` is confirmed decorative-only (2.86:1) and held out of the text set rather than promoted. `lib/brand-tokens.mjs` gains a single `SPACING_SCALE` so PDF (Typst em), CSS (rem), and templates derive from one rhythm instead of drifting.
- Completed the visual-review contract (`construct-cuxq.3.4`): `lib/visual-review.mjs` adds a rubric registry (document/deck/diagram) and `recordVisualReview`, which produces a `visually-reviewed` evidence object only from non-degraded `screenshot-captured` evidence plus a valid rubric and verdict — never inferred from source. The verdict rides in the proof; a passing or failing review both record that a review occurred. With `3.1`–`3.4` this closes Epic 3 (rendered output inspection & visual review).
- Wired render output into the completion ledger (`construct-cuxq.3.3`): `lib/render-evidence.mjs` renders an artifact to images under a stable `.cx/render/` path and returns a `screenshot-captured` evidence object — a successful render carries the image paths plus a sha256 content digest and advances the ladder, while a degraded render carries the typed degradation reason and is recorded without advancing.
- Added the render pipeline (`construct-cuxq.3.2`): `lib/render-pipeline.mjs` — a declarative per-format renderer registry (PDF/HTML/PPTX → page/slide PNGs, Mermaid/D2 → SVG/PNG) with availability detection that reuses the now-exported `whichBin` probe and emits a typed degradation reason (from the shared enum) when a renderer is absent. The live render runs only when its tools resolve on PATH; missing tooling surfaces a typed reason rather than a silent pass.
- Wired the five gate levels into the release gate (`construct-cuxq.11.1`): `lib/artifact-gate-levels.mjs` declares the cumulative level → check-category map (`fast` → `human-reviewed`), where each category is `available` (a check runs today) or `pending` (names the bead that implements it). `runGateAtLevel` resolves an artifact's level from its `qualityContract`, runs the available source-lint check, and reports the higher-tier categories still owed instead of silently passing them. `fast` stays source-only and ms-fast.
- Implemented the artifact completion ledger (`construct-cuxq.9.2`): `lib/artifact-completion.mjs` adds evidence objects and a no-forgery ledger — a state enters only through a valid evidence object, and a degraded entry records a typed degradation reason without advancing the ladder. `runArtifactWorkflow` now reports a deterministic `completion` ledger and `completionState`, recording `exported` when a real file is produced and a typed degradation on export failure. Timestamps are injected (null by default) so identical runs stay byte-equal.
- Added the canonical completion-state vocabulary (`construct-cuxq.1.2`): `lib/artifact-completion-states.mjs` exports the single ordered 12-rung ladder plus `isCompletionState`/`completionRank`. The manifest validator now checks `qualityContract.requiredStates` against it, a parity test keeps the JS enum byte-identical to the schema's `completionState` enum, and the workflow completion-truth guard derives its evidence-required rungs from the same source.
- Activated a registry-first artifact quality contract (`construct-cuxq.1.1`): the manifest schema gains an optional `qualityContract` (`gateLevel`, `requiredStates`, `perFormat`) plus shared `gateLevel` and `completionState` enums. `workflowDefaults` carries a `standard`/`exported` default that all 27 artifacts inherit, with `prd` and `one-pager` overriding to `render-smoke`. `resolveArtifactWorkflowContract` resolves the contract and `validateArtifactManifest` rejects out-of-enum gate levels; the golden gate matrix stays byte-deterministic.
- Added a render-degradation guard (`construct-cuxq.3.1`): `tests/asset-quality/render-degradation.test.mjs` locks `document-export` `detect()` as typed degradation — missing renderers surface a `missing[]` list, a `present:false` flag, and an install hint; unsupported formats return a typed message — never a silent pass. Still-silent paths (diagram engine fallback, headless Chrome) are pending `construct-cuxq.6.2`/`.3.2`.
- Added a completion-truth guard (`construct-cuxq.9.1`): `tests/asset-quality/completion-truth.test.mjs` locks the workflow no-forgery invariant — `runArtifactWorkflow` never reports a review/visual/approval completion rung without evidence, and `completed-local-steps` requires a produced file — with pending markers for the evidence-gated ladder (`construct-cuxq.9.2`, `.1.2`, `.8.1`).
- Seeded the generated-asset quality fixture corpus (`construct-cuxq.10.1`): intentionally-bad anti-fixtures under `tests/fixtures/asset-quality/` driven by a declarative registry (`anti-fixtures.json`), with `tests/asset-quality/anti-fixtures.test.mjs` asserting each anti-fixture is rejected by its target audit (`lintDocPresentation`, `auditDeckMarkdownLayout`). Placeholder and empty-section cases are explicitly skipped as pending `construct-cuxq.2.2`, so the coverage gap stays visible rather than silently passing. Known-good goldens are unchanged.
- Added an orchestration readiness preflight for GitHub issue #323. `construct orchestrate preflight --json` and the flat MCP `orchestration_readiness` tool now report whether `orchestration_policy` and `orchestration_run` are attached/reachable, with a typed `reasonCode`, deterministic next step, redacted diagnostic bundle, and local readiness event.

## [1.3.2] - 2026-06-29

### Fixed

- `tests/certification/artifacts/gate-matrix.json` no longer churns on every run. `writeArtifactGateMatrixDoc` stamped a `generatedAt: new Date().toISOString()` into this tracked artifact, so the artifact-gates test rewrote it with a fresh timestamp each run — producing a perpetual timestamp-only diff. The field was write-only (never read; the matrix content is the signal), so it's dropped and the committed file is now deterministic.

### Security

- GitHub MCP wiring now defaults to **OAuth**, matching GitHub's hosted remote server (`https://api.githubcopilot.com/mcp/`) and the 2026 MCP standard (OAuth 2.1 + PKCE for remote HTTP servers). `construct mcp add github` writes a URL-only entry with **no Authorization header and no token on disk**; the host (Claude Code `claude mcp login github`, OpenCode `opencode mcp auth github`, VS Code/Cursor sign-in prompt) runs the one-click browser flow and stores the credential in its own secure store. This removes the previous behavior of embedding the literal `gh` token verbatim into every host config (`~/.claude/settings.json`, `.claude/settings.json`, `~/.config/opencode/opencode.json`, `.vscode/mcp.json`).
- A PAT remains available as an explicit opt-in fallback for headless/CI via `construct mcp add github --token`. Even then the credential is emitted as a host-resolved env reference — Claude `${GITHUB_TOKEN}`, VS Code/Cursor `${env:GITHUB_TOKEN}`, OpenCode `{env:GITHUB_TOKEN}` — never the literal value. `lib/mcp-platform-config.mjs` builds the entries; `tests/mcp-secret-ref.test.mjs` guards both the OAuth (no-header) default and the no-literal-leak property of the PAT path.

## [1.3.1] - 2026-06-29

### Fixed

- Project-mode Claude Code hooks no longer crash when Claude Code runs a hook from a working directory other than the project root. The generated `.claude/settings.json` hook commands now anchor on `node "${CLAUDE_PROJECT_DIR:-.}/.construct/run.mjs"` instead of a bare relative `.construct/run.mjs`, which previously failed with `Cannot find module …/.construct/run.mjs` (cjs/loader) on every Bash tool call when the cwd was `$HOME`. Existing installs self-heal on `construct sync` / `construct upgrade`.
- `construct doctor consistency` no longer reports 38 non-actionable package-internal warnings on a clean init. `roles-drift` was counting a specialist's own `id` and `name` as two owners (every specialist read as "ambiguous after normalization"); `mcp-drift` was scraping every `export function` in `lib/mcp/tools/*.mjs` (sweeping in private helpers like `exec`/`read_json`) and matching against a brittle `name === '<tool>'` dispatch pattern that the `xxxTool`→`'xxx'` naming convention never satisfied. Both checks are now correct at the source, and a genuinely dead `getTeam` import was removed from the MCP server.

### Changed

- `construct doctor consistency` separates operator tiers: user-actionable findings show by default, while package/maintainer diagnostics (`mcp-drift`, `roles-drift`) are summarized as a count and surfaced in full only under `construct doctor consistency --strict` (`--all`/`--debug`). A clean tree now reads `0 warning(s)`.

## [1.3.0] - 2026-06-29

This release makes OpenCode the primary conversation surface, retires the web/dashboard tier in favor of a terminal-first architecture, and consolidates the legacy registries into a single unified registry (RFC-0004). It contains two breaking changes — see **Removed**.

### Added

- Agent-reachable MCP tool surface: `find_tool` intent-driven tool discovery (ADR-0048), an artifact loop, and OpenCode auth hardening.
- Intent-driven, team-aware orchestration: requests route to teams with blocked-decision handling; typed team integration sources drive scoped `provider_fetch` reads.
- Oracle governance: swarm dispatch, a `cross-team-handoff-blocked` synthesized signal, and team governance oversight.
- Demo plug-in layer: `demo init --from-project`, an expanded canonical catalog of 6 terminal scenarios, and a self-demo guided tour via bare `construct`.
- `construct` CLI primitives: a `display-width` primitive and a shared presentation core with clickable links and chat ticker/wrap fixes.
- `registry:validate --unified` gates the unified registry (RFC-0004 Phase 1.4).

### Changed

- OpenCode is now the first-class conversation surface. `construct sync` installs the front-door agent, MCP wiring, and runtime plugin; the `construct` CLI remains setup/admin/headless infrastructure.
- The previous local conversation-loop capability has been replaced by `surfaces.opencode-primary` in the capability registry.
- All registry consumers (MCP `list_teams`/`get_team`, policy-inventory, staleness graph, doctor watchers) now read the unified registry instead of the legacy `contracts.json`/`teams.json` files.
- Demo execution is recording/tour oriented: VHS and Playwright surfaces are supported, with printed script steps as fallback.
- Research-shaped host conversations now classify through `orchestration_policy` and execute through `orchestration_run`; the OpenCode front-door prompt no longer implies that `workflow_invoke` itself performed evidence gathering.
- OpenCode now emits its host-facing MCP tool ids in the front-door prompt (`construct-mcp_orchestration_policy` / `construct-mcp_orchestration_run`) so research routing can execute instead of failing host-side tool validation.
- PDF artifact generation now preserves ordered-list numbering, loosens body and heading spacing, and widens page margins so published PRDs, decisions, research briefs, and generic PDFs read like release-grade documents instead of cramped exports.
- Bare `construct` launches chat; `construct chat` is deprecated.
- CI gates run through thin `npm run` wrappers over `bin/construct`; the workflows no longer re-spell the underlying commands.

### Removed

- **Breaking:** the `chat --web` browser launcher has been removed. Construct chat is terminal-only; there is no web/browser surface to launch.
- **Breaking:** the legacy `contracts.json` contract files have been deleted. Readers now resolve contracts from the unified registry; any consumer reading `specialists/contracts.json` directly must migrate to the unified-registry shape.
- Retired the dashboard web app and HTTP server, the native desktop chat window, and the dead Ink TUI — Construct is terminal-first (ADR-0039/0041 amended).
- Removed Construct's local conversation UI implementation, related package surface, docs page, and surface-specific tests.
