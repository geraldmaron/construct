# Changelog

All notable changes to Construct are documented here. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/) and the project follows [Semantic Versioning](https://semver.org/).

## [Unreleased]

### Removed

- **All hook skip / quiet env vars deleted; auditing a mechanism that shouldn't exist is wasted code.** `CONSTRUCT_SKIP_COMMENT_LINT`, `CONSTRUCT_SKIP_PR_LINT`, `CONSTRUCT_ALLOW_CLAUDE_PUSH`, `CONSTRUCT_SKIP_PREPUSH`, `CONSTRUCT_SKIP_DOCS`, `CONSTRUCT_QUIET_REGISTRY_REMINDER` are gone. The earlier `chore/pre-push-shrink-and-ci-concurrency` branch added an audit log + protected-branch refusal + doctor warning around these — treating bypass-audit as best practice. It isn't. Auditing the skip tells you who skipped; it doesn't address why a quality gate fires when it shouldn't. A skip env var on a quality gate is an admission the policy is wrong, the gate is over-scoped, or the team will route around it. The principle: hooks fire unconditionally. If a check fires wrong, fix the check. Files retired with the skip vars: the `logBypass` writer in `lib/hooks/pre-push-gate.mjs`, the inline-env-var parser (only existed to honor bypasses), the doctor "Pre-push bypasses in last 7 days" check in `bin/construct`, `~/.construct/audit/prepush-bypass.log`, `tests/hooks/pre-push-gate-bypass.test.mjs`, and `lib/policy/unified-gates.mjs` (whole-file dead infrastructure built around 4 hypothetical bypass-able policies + a `CONSTRUCT_SKIP_ALL_GATES` kill switch; not referenced from anywhere except a broken `policy:list` command that imported a non-existent `formatPolicyList`). The notice-quiet (`CONSTRUCT_QUIET_REGISTRY_REMINDER`) was the only var with a legitimate use case (silent reminders in CI); it's replaced with auto-detection (`CI=true` or `NODE_ENV=test`). `process.stderr.isTTY` is intentionally NOT used as a signal — Claude Code captures hook stderr rather than passing it through to a TTY, so a TTY check would silently kill the reminder in real interactive sessions. New regression test `tests/hooks/no-skip-vars.test.mjs` greps `lib/hooks/*.mjs` for `CONSTRUCT_SKIP_` / `CONSTRUCT_ALLOW_` / `CONSTRUCT_QUIET_` and fails on any match outside an explicit (initially empty) allowlist. Coverage: also rewrote `tests/hooks/registry-sync-reminder.test.mjs` (5 cases) for the auto-detect path. Stale agents/specialists rename fixed at `bin/construct` for `policy show` while touching the file.

### Added

- **Profile `capabilities.intake` archetype: init scaffolding + runtime CLI + manifest dedup + attribution provenance + atomic poll lock.** Closes issue #104. Profiles whose `capabilities.intake.inbox` is `true` (curated `rnd` and `research`; `operations` and `creative` stay opt-in) cause `construct init` to scaffold `inbox/` at the project root with a permissive `.gitignore` (`*` plus `!.gitignore` — raw drops never enter source), seed `.cx/intake/manifest.json` with the empty SHA-256 dedup shape, and flip a new `includeArchetypeInbox: true` flag in `.cx/intake-config.json`. The flag is symmetric with the existing `includeProjectInbox` / `includeDocsIntake` toggles, so `parentDirs` stays reserved for user-explicit opt-ins (preserving the regression guard from `tests/init-intake-defaults.test.mjs`). `resolveInboxDirs` honors the new flag. `capabilities.intake.attribution: true` adds a two-field provenance stamp (`createdBy` from `git config user.name <user.email>`, `createdByAgent` from `CONSTRUCT_AGENT_ID || CLAUDE_AGENT_ID`) to `AGENTS.md`, `plan.md`, `.cx/context.md` (markdown frontmatter) and `.cx/context.json` (top-level fields), with `CONSTRUCT_ATTRIBUTION_DISABLE=1` as the opt-out for tests and privacy-sensitive setups. `gatherAttribution({ cwd })` scopes the git-config lookup to the project root so non-spawned callers (the daemon, tests) get the right identity. New runtime CLI `construct intake process [--dry-run] [--wait[=<sec>]]`: a thin one-shot wrapper around the same `InboxWatcher.poll()` the daemon runs, exits when the queue is empty. **Concurrency is closed at the source, not papered over at the CLI.** `InboxWatcher.poll()` now wraps its body in `acquirePollLock` / `releasePollLock` (`lib/intake/poll-lock.mjs`, pid-stamped lockfile at `.cx/runtime/inbox-poll.lock`, stale detection via PID liveness and timeoutAt — API shape mirrors `lib/beads-lock.mjs` for cohesion). Two concurrent pollers — the embed daemon and a manual `intake process`, two parallel daemons, two CLI invocations — serialize cleanly; the second caller fails fast with `POLL_LOCK_BUSY` (exit 2 with an error naming the holder pid/actor/startedAt and surfacing `--wait` / `construct down` as remediation) or blocks for up to `--wait=<sec>` seconds. `--dry-run` skips the lock entirely. Dedup is layered: the existing path+mtime state file is the fast path; SHA-256 manifest check on top catches identical content under a renamed path. `InboxWatcher.poll` records the SHA, source path, intake id, and attribution on each successful ingest. Intake packets written to `.cx/intake/pending/` carry `createdBy` / `createdByAgent` / `createdAt` when the manifest is present. New helpers: `lib/intake/manifest.mjs` (`loadManifest` / `saveManifest` / `recordFile` / `hasFile` / `sha256Of`, atomic write-rename so a crash mid-write cannot half-write the manifest); `lib/intake/attribution.mjs` (`gatherAttribution` / `stampAttribution` / `touchAttribution`); `lib/intake/poll-lock.mjs` (`acquirePollLock` / `releasePollLock` / `readPollLock` / `isPollLockStale`). `lib/doc-stamp.mjs` `stampFrontmatter()` now accepts an optional `attribution` arg and preserves the original `created_by` on re-stamp by a different author, writing `last_modified_by` instead. Also fixes a pre-existing bug in `lib/init-unified.mjs:815` where re-running `construct init --profile=<id>` against an existing `construct.config.json` wrote the loader's wrapper object back to disk (failed schema validation on `version: required`) — the code now persists the original `.raw` JSON with only the profile field updated, so user customization survives idempotent re-init. Coverage: `tests/intake-manifest.test.mjs` (7 cases — empty contract, hashing determinism, idempotent record, corrupted-file recovery, atomic write), `tests/intake-attribution.test.mjs` (6 cases — disabled path, env-precedence, stamp/touch), `tests/intake-poll-lock.test.mjs` (9 cases — acquire/release, foreign-pid release no-op, fail-fast on live holder, stale-pid cleanup, stale-timeout cleanup, wait-then-acquire, predicate behavior, corrupt-file recovery), `tests/doc-stamp.test.mjs` adds 3 attribution cases (initial stamp, re-stamp preserves created_by, no-attribution stays clean), `tests/functional/init-intake-archetype.functional.test.mjs` (5 cases — scaffold + manifest + .gitignore shape, AGENTS.md attribution, attribution disable env, idempotent re-run preserves customized .gitignore, context.json fields populated), `tests/functional/intake-process-archetype.functional.test.mjs` (8 cases — `--dry-run` lists without ingesting, lock-held fail-fast with pid in message, `--wait` waits and acquires after release, stale-lock cleanup, `--dry-run` unaffected by lock, `InboxWatcher.poll` records SHA + attribution, identical-content dedup across renamed paths, intake packets carry attribution, **two parallel polls serialize through the lock — no double-ingest**).

- **Automated main → staging sync workflow** (`.github/workflows/sync-main-to-staging.yml`). Every push to `main` opens a `chore/sync-main-to-staging-<sha>` PR against `staging` via `peter-evans/create-pull-request`. Closes the drift window after a release squash-merge: previously a release PR (e.g. PR #105) would land on `main` but `staging` would have to hand-pick the merge back. The workflow checks `git merge-base --is-ancestor origin/main HEAD` first and no-ops if `staging` already contains `main`. Conflict path: workflow fails with an actionable error pointing at the local resolution steps; branch protection on `staging` stays intact (no direct push from CI). `workflow_dispatch` trigger supported for one-shot alignment.

### Changed

- **Pre-push hooks shrunk to local-only signals; CI is the source of truth.** Both `lib/hooks/pre-push-gate.mjs` (Claude Code PreToolUse) and `.beads/hooks/pre-push` (git native) previously re-ran the full CI matrix locally on every push — `npm test`, `npm run build`, `npm audit`, `construct evals retrieval`, `docs:verify`, `docs:update --check`, `lint:comments`, `lint:agents`, `lint:contracts`, `lint:prose`, `lint:profiles`. Wall time ~65s. The duplication trained the team to use a daily escape hatch, which is the gate-is-skipped-by-default failure mode. Hooks now do only what only the developer's machine can know: refuse `claude/*` branch pushes (Claude Code hook), block re-pushing the exact SHA CI just rejected (both hooks via `gh run list`), lint the PR body on `gh pr create` / `gh pr edit` (Claude Code hook — body doesn't exist until the PR is created). New wall time: ~2s. Test/build/audit/evals/lint coverage is unchanged — every check still runs in `.github/workflows/ci.yml`.
- **CI concurrency cancellation on PR pushes.** `.github/workflows/ci.yml` declares `concurrency: { group: ci-${{ workflow }}-${{ pull_request.number || ref }}, cancel-in-progress: ${{ event_name == 'pull_request' }} }`. Force-pushes to an open PR now cancel the superseded run instead of letting it complete in parallel. Pushes to `main` never cancel — every merged commit gets its own complete run for audit + release purposes.
- **ci-parity test contract inverted.** `tests/ci-parity.test.mjs` previously enforced that every `bin/construct lint:*` invocation in CI also appeared in both local pre-push hooks (the symmetric-gate anti-pattern). The new contract asserts the opposite: `docs:update`, `docs:verify`, `lint:comments`, `lint:agents`, `lint:contracts`, `lint:prose`, `lint:profiles`, `lint:templates`, `evals`, `gates:audit`, `doctor` must NOT appear in either local hook. A sanity check confirms CI still invokes each one (so we didn't drop a check entirely). `dashboard:sync --build` remains a CI-only invocation by the same asymmetry as before.

### Fixed

- **Release-gate test no longer reads polluted real-HOME state.** `tests/functional/release-gate.functional.test.mjs` invoked `construct doctor` against `process.env.HOME` unchanged, so a dev box with legacy v1.0.10 `~/.claude/agents/cx-*.md` files (regenerated mid-suite by `construct sync`) deterministically failed the parity check. The doctor subtest now uses an isolated tmpdir HOME, matching the pattern in `tests/sync-contract.test.mjs:43-78`. Other subtests are unchanged — they don't read user-scope state.
- **Doctor parity check now distinguishes "legacy v1.0.10 install" from "real drift."** `lib/parity.mjs:checkParity()` previously hard-failed when extra `cx-*` agents appeared at user scope, but that's the expected state during a v1.0.10 → v1.0.13+ upgrade (v1.0.10 populated all 28 specialists at user scope before the two-tier sync contract moved them to project scope). The check now reclassifies drift to `status: 'legacy-install'` when *every* extra matches the registry's `cx-*` roster, soft-warns with the `--fix-legacy-agents` hint, and lets the overall doctor exit 0. A single non-registry extra (typo, user-authored file) still hard-fails as `drift`. Same soft-warn applied to the standalone "legacy cx-* files at user scope" doctor counter in `bin/construct:495-501`. Coverage: 2 new cases in `tests/parity.test.mjs` (legacy roster + mixed-with-unknown), 1 updated case (`cx-orphan` instead of `cx-engineer` to pin the still-drifts-on-unknown branch).
- **GitHub Pages deploy no longer fails on workspace-package resolution.** `apps/docs` depends on the local workspace package `@cx/ui` (`packages/cx-ui`). Root `npm ci` resolves it via the `workspaces` config in `package.json`. The Pages workflow ran a redundant second install — `npm --prefix apps/docs install` — that was scoped to `apps/docs/` only, ignoring workspaces, so npm tried to fetch `@cx/ui@*` from the public registry and got a 404. The fix removes the redundant install step from `.github/workflows/pages.yml`; the subsequent `npm --prefix apps/docs run build` only invokes a script and doesn't need its own install. New CI guard `docs site build` in `.github/workflows/ci.yml` runs the apps/docs build on every PR that touches `apps/docs/**`, `packages/cx-ui/**`, `docs/**`, or `.github/workflows/pages.yml` — catches workspace-resolution drift before merge instead of after.
- **Dashboard drift check is now correct in CI and non-duplicated in local pre-push gates.** Three-part fix:
  - **CI** (`.github/workflows/ci.yml:153`): the `dashboard bundle drift` step now runs `node ./bin/construct dashboard:sync --build` (one command — builds, copies into `lib/server/static/`, verifies parity). Earlier the step ran `npm --prefix apps/dashboard run build:next` followed by `dashboard:sync --check`, but `build:next` is the Next.js-only script — it never invokes the post-build copy into `lib/server/static/`, so the subsequent `--check` always tripped on a fresh checkout where the destination is gitignored.
  - **Local gates** (`.beads/hooks/pre-push:104`, `lib/hooks/pre-push-gate.mjs:239`): the standalone dashboard-drift job was removed. Both gates run `npm test`, which includes `tests/functional/dashboard-build.functional.test.mjs` — that test already builds the dashboard end-to-end and asserts on the static export. Running a second `next build` in the same gate races the first on `apps/dashboard/.next/` (intermittent ENOENT on the 500.html rename, ENOTEMPTY on cache wipe, ENOENT on routes.d.ts). The asymmetry is intentional: CI runs the build standalone because it has no shared test runner that builds the dashboard for it; local gates rely on the test for the same coverage.
  - **Parity test** (`tests/ci-parity.test.mjs`): asserts that (a) CI's invocation is exactly `dashboard:sync --build`, not `--check`, and (b) `tests/functional/dashboard-build.functional.test.mjs` exists and runs `next build` (the load-bearing local coverage). The test catches both halves of the contract — if CI's flag drifts back to `--check` or someone deletes the functional test, the regression surfaces locally before push.
- **Postgres test harness no longer races the postmaster's external-socket window.** `tests/functional/_lib/postgres-docker.mjs` now probes the container twice before declaring it ready: once via psql-inside-container (confirms postmaster started) and once via the `postgres` driver from the host (confirms the TCP socket accepts client queries). Without the second probe, the first test query intermittently hit `57P03 the database system is starting up` on slower machines because psql goes through a Unix socket and doesn't catch the brief gap between the postmaster opening the TCP socket and accepting client queries. The host probe retries on `57P03` / `ECONNREFUSED` until the readiness deadline.
- **Pre-push gate's "last CI run failed" check is now SHA-aware.** The old logic ran `gh run list --limit=1` and blocked on any prior failure regardless of HEAD. That created a doom loop: the commit that fixes CI couldn't push without an env-var override. New behavior: read the failed run's `headSha` and only block when `HEAD === headSha` (a re-push of the broken commit). When HEAD has advanced past the failed SHA, the gate prints a non-blocking notice with the prior failure URL and lets push through — CI re-evaluates whether the new commits are the fix. The genuine re-push-the-broken-SHA case has no override; the operator amends or adds a fix commit. Coverage: `tests/hooks/pre-push-gate-prior-ci.test.mjs` (3 cases: blocks on same SHA, allows on advanced SHA, silent on success).
- **`registry-sync` PostToolUse hook no longer auto-executes `construct sync`.** Old behavior: every Write/Edit to `specialists/registry.json` spawned a 12-second `sync-specialists.mjs` subprocess. Tests legitimately mutate `registry.json`, so the hook fired repeatedly during a test run, raced test cleanup, and regenerated platform state mid-suite — meaning `construct doctor --fix-all` could "clear" legacy state and then watch it reappear before the next command. The hook now matches its docstring: emit a one-line stderr reminder telling the developer to run `construct sync` when ready, and exit 0. Non-interactive contexts auto-suppress the reminder (`CI=true`, `NODE_ENV=test`, or `!process.stderr.isTTY` — the wrong-context detection is the right mechanism). Coverage: `tests/hooks/registry-sync-reminder.test.mjs` (4 cases: fires for registry paths, silent for unrelated paths, silent in non-interactive context, exits clean).
- **Cross-project state leakage: per-project writers now route to `<project>/.cx/` instead of `~/.cx/`, and cross-project writers tag every entry with a `projectId`.** Before this change, four append-only writers — `contract-violations.jsonl`, `audit-reads.jsonl`, `agent-log.jsonl`, `intent-verifications.jsonl` — wrote to the user-scope `~/.cx/` directory regardless of which project the call originated from, so contract violations from project A could overwrite the chain hash of a violation in project B and `construct doctor` would report aggregated counts from every project the user touched. New module `lib/project-root.mjs` exports `findProjectRoot(cwd)` (walks upward looking for `.cx/` or `.construct/` marker, stops at `$HOME` so the home dir itself never registers as a project), `projectIdFor(projectRoot)` (deterministic 12-char sha256 of the absolute path), `resolveProjectScope(cwd)`, and `resolveProjectScopedPath(basename, opts)`. The four project-scoped writers above now resolve their log path on every call, so the same writer used across `cwd` changes (tests, harness reuse, daemon batching) routes correctly. The three cross-project writers — `skill-calls.jsonl`, `role-pending.jsonl`, `session-cost.jsonl` — keep their user-scope path but tag each entry with `projectId`, so a reader can attribute usage per project. Doctor adds `--fix-migrate-state` to archive existing `~/.cx/<project-scoped>.jsonl` files to `~/.cx/legacy/<name>.<ts>.jsonl` on upgrade. The `session-cost` channel joins the bounded-logging registry (25 MB cap, 4 segments, gzip). Coverage: `tests/project-root.test.mjs` (8 cases — marker detection, HOME stop, memoization, projectId stability), `tests/functional/cross-project-state-isolation.functional.test.mjs` (4 cases — project A/B isolation, projectId tagging, intent-verifications routes to project, no leak into user-scope), plus a `--fix-migrate-state` case in `tests/functional/doctor-fixes-legacy-state.functional.test.mjs`.
- **Channel-registry-bounded logging across every high-traffic writer under `~/.cx/`.** Same anti-pattern class as the embed-daemon-log 34GB bug: append-only telemetry with no rotation. `lib/logging/rotate.mjs` now exports a `LIMITS` registry that documents the per-channel disk budget (max bytes, segment count, gzip), an `appendBounded(channel, path, line)` helper that refuses to write to an unregistered channel, and per-channel env-var overrides. Seven previously-unbounded writers are now wired through it: `audit-reads.jsonl`, `skill-calls.jsonl`, `agent-log.jsonl`, `role-pending.jsonl` (two call sites: `lib/hooks/agent-tracker.mjs` + `lib/doctor/watchers/bd-watch.mjs`), `intent-verifications.jsonl`, `contract-violations.jsonl`, `warn-flags.txt` (`lib/hooks/bash-output-logger.mjs`). Channels with existing in-file rotation (`lib/hooks/_lib/log.mjs`, `lib/roles/event-bus.mjs`) keep their own logic. Coverage: 4 new test cases in `tests/logging-rotate.test.mjs` (12 cases total) — registry enforcement, env-override resolution, real-channel rotation.
- **Seven stale `agents/registry.json` paths that silently returned null.** Same class as the `lib/server/index.mjs:39` fix earlier in this branch. The `agents/` → `specialists/` rename had been completed in earlier releases but the following call sites lagged: `lib/status.mjs:667`, `lib/auto-docs.mjs:155`, `lib/roles/catalog.mjs:14`, `lib/mcp/tools/telemetry.mjs:73`, `lib/mcp/tools/project.mjs:284` + `:326`, `lib/storage/backup.mjs:128` + `:277`, `scripts/optimize.mjs:130`. Each one read from a non-existent path and downstream code treated the result as "no specialists registered" — silently degraded `construct status`, `docs:update`, MCP `cx_trace`/`workflow_status`/`workflow_needs_main_input` tools, role catalog, backup, and the optimize script. One-line fix per file.
- **Two unbounded-disk bugs in `.cx/` runtime state.** Both beads ship a shared rotation primitive at `lib/logging/rotate.mjs` and dedicated tests at `tests/logging-rotate.test.mjs` (12 cases) + `tests/functional/init-gitignores-cx.functional.test.mjs` (4 cases).
- **Migration story for users upgrading from pre-2.0 installs — fully automatic where possible, doctor-flagged where consent matters.** Most legacy state cleans itself up on the next normal operation: `sweepLegacyPrefixedFiles` removes `~/.claude/agents/cx-*.md` + `~/.codex/agents/cx-*.toml` + `~/.github/prompts/cx-*.prompt.md` on every `--global` sync (auto-fires from the `npm i -g` postinstall); the channel registry rotates oversized append-only files on the next append; the embed daemon's `daemon-log-rotation` scheduler job rotates `~/.cx/runtime/embed-daemon.log` on the next 60s tick. `.gitignore` requires consent because it's a project file the user owns, so `construct doctor` now flags missing `.cx/` coverage and offers `--fix-gitignore`. Three new doctor checks + four `--fix-*` flags: `--fix-gitignore` (append `.cx/` to project `.gitignore`), `--fix-legacy-agents` (invoke `construct sync --global` to sweep), `--fix-embed-log` (force-rotate immediately instead of waiting 60s), and `--fix-all` (run every available fix). User-authored `cx-mytool.md`-style files at user scope survive — the sweep is registry-bounded. Coverage: `tests/functional/doctor-fixes-legacy-state.functional.test.mjs` (4 cases: each fix flag in isolation + the `--fix-all` orchestration).
  - **`construct init` now adds `.cx/` to the project `.gitignore`** (bead `construct-1vv5`). Creates the file if missing, appends with a one-line explanation when one exists, and is idempotent — won't double-add if `.cx/`, `.cx`, `*`, or `**` is already present. Prevents the failure mode where a session-heavy project commits hundreds of churning JSON files per push.
  - **Trace files cap at 100 MB and rotate** (bead `construct-1vv5`). `lib/worker/trace.mjs` now calls `appendWithRotationSync(shardPath, line, { maxBytes })` so every `.cx/traces/<date>.jsonl` shard stays strictly under GitHub's 100 MB single-file ceiling. Rotated segments are named `<date>.<n>.jsonl`. Override via `CONSTRUCT_TRACE_MAX_MB`; `=0` disables (not recommended).
  - **Embed daemon log rotates at 50 MB with 5-segment gzip retention** (bead `construct-88i`). New scheduler job `daemon-log-rotation` in `lib/embed/daemon.mjs` runs every minute, calling `rotateIfOversized('~/.cx/runtime/embed-daemon.log', { maxBytes, maxSegments, gzip: true })`. Fixes the reported 34 GB log file from a stuck `[embed] Telemetry setup skipped` line. Overrides: `CONSTRUCT_EMBED_LOG_MAX_MB` (default 50), `CONSTRUCT_EMBED_LOG_MAX_SEGMENTS` (default 5).

### Changed

- **Per-project event bus + four new lifecycle events that the recommendation pipeline can route through.** `lib/roles/event-bus.mjs` now resolves `events.jsonl` to `<project>/.cx/` when cwd is inside a Construct project (falls back to `~/.cx/` outside one); `CONSTRUCT_ROLES_ROOT` keeps overriding for tests. Closes the cross-project fingerprint-suppression bug tracked as `construct-wwf2`. Four new emitters wire lifecycle signals into the bus so subscribed specialists can act: `recommendation.generated` from `lib/embed/recommendation-store.mjs` after each new recommendation lands (the record also gains `state: 'raw' | 'enriching' | 'enriched'`, `enrichedAt`, `enrichedBy` for the upcoming enrichment loop); `document.stale` from `lib/embed/docs-lifecycle.mjs` on each stale-doc gap; `profile.updated` from `lib/profiles/lifecycle.mjs` on draft creation and archive; `signal.promoted` from `lib/intake/prepare.mjs` when a triage confidence crosses 0.70. `cx-docs-keeper` adds `document.stale` to its declarative subscriptions; the other three events are emitted with no default subscriber, ready for projects (or the planned enrichment loop) to bind via `.cx/specialists/`. All emits are best-effort: a bus failure cannot break the writer that fired it. Coverage: 3 new cases in `tests/functional/event-bus-per-project.test.mjs` (cwd-inside-project, env override, two-project isolation) + updated `tests/functional/routing-tables.test.mjs` for the new event in the expected set.

- **Routing tables (event ownership, doc-artifact ownership, proactive watch conditions) moved from hardcoded `.mjs` constants to declarative fields on `specialists/registry.json`.** Each specialist entry now carries optional `subscriptions` (event types it owns), `docArtifacts` (typed documents whose authoring it owns), and `watchConditions` (named signal-driven triggers it engages on). A new resolver `lib/orchestration/routing-tables.mjs` builds the forward maps at load time, supports project-level overlays from `.cx/specialists/*.json`, and validates that every referenced watcher exists. `EVENT_OWNERSHIP`, `DOC_OWNERSHIP`, and the inline `proactiveTriggers` heuristics are deleted from `lib/orchestration-policy.mjs`; consumers (`lib/roles/router.mjs`, `lib/hooks/proactive-activation.mjs`, `routeRequest`) import `ownerForEvent` / `ownerForDoc` / `evaluateWatchConditions` from the resolver. The named-watcher pattern keeps the multi-signal predicates (high-ambiguity-deep-work, visual-or-ui-risk, auth-payments-non-narrow, architecture-without-metric, wide-blast-radius) as code while letting the registry decide which specialist owns each — projects can rebind a watcher's owner without patching library code. Migration of routing data is mechanical and exact: parity asserted by `tests/functional/routing-tables.test.mjs` (11 cases against the full event + doc + watcher sets). Removes the "hardcoded routing table" and "two sources of truth for ownership" anti-patterns called out by issue #107.

- **Dashboard rebuilt on Next.js as `apps/dashboard/`; old Vite tree (`dashboard/`) deleted.** Twenty-three routes (overview + 22 page-per-feature surfaces: Agents, Approvals, Artifacts, Audit, Beads, Commands, Config, Doctor, Editor, Hooks, Infrastructure, Intake, Knowledge, MCP, Models, Performance, Plugins, Providers, Resources, Skills, Snapshots, Workflow). Same editorial design language as the docs site — both apps now consume `@cx/ui` (a new shared workspace package at `packages/cx-ui/` with `theme.css` + `Section` / `CodeBlock` / `Mermaid` / `Callout` / `CommandPalette` / `FeatureGrid` / MDX shims). `construct dev` continues to serve the SPA from `lib/server/static/` — the `apps/dashboard/` build script (`next build && node scripts/copy-to-server-static.mjs`) copies the static export there, so `lib/server/index.mjs` is unchanged except for a stale-path fix: `agents/registry.json` → `specialists/registry.json` (the legacy `agents/` rename had been missed in the server). `construct doctor` adds a "Dashboard built (lib/server/static/index.html)" check. Per the approved plan reactive-sleeping-puzzle.md.
- **Docs site adopts the shared `@cx/ui` package.** Pulls in the same editorial primitives the dashboard uses; theme.css moved out of `apps/docs/app/` into `packages/cx-ui/styles/`. Both apps now share font wiring (Geist sans + display + JetBrains Mono).

## [1.0.7] - 2026-05-27

### Fixed

- **`ensureGitHooksPath` now rewires when `core.hooksPath` is the git default.** The setup helper previously treated any non-empty `core.hooksPath` as a user-set value and refused to wire `.beads/hooks` on top of it. But `.git/hooks` (or an absolute path to it) is the *default* git stores when an unset user accepts the implicit value: not an active choice, just the absence of one. With the old logic, an install that landed while `core.hooksPath` happened to be the default left Construct's pre-commit policy gates inactive forever, and `construct doctor` reported "Git hooks unwired" with no path to recovery short of manual `git config`. The fix recognizes both forms of the default (`.git/hooks` relative and absolute) as equivalent to unset and proceeds to wire `.beads/hooks`. A custom non-default `core.hooksPath` (e.g. `tools/git-hooks/`) is still left alone with a warning. Regression coverage in `tests/setup-git-hooks-path.test.mjs`.
- **Intake classifier no longer misroutes postmortems as bug reports and is now deterministic.** `lib/intake/classify.mjs` had three compounding problems against the real corpus: a postmortem with "crash" and "exception" in the body matched the bug type first-wins; a research note that mentioned "outage" in passing routed to incident; and the outcomes-aware tiebreaker fed cached success-rate history into classification, so the same file could land in different buckets across runs. The fix adds filename-pattern weighting (e.g. `postmortem` adds +0.4 to `incident`, `adr-*` to `architecture`, `prd-*` to `requirement`, `-bug.*` to `bug`), title-level negative keywords (`# Postmortem`, `# Incident report`, `# ADR-...` apply a −0.5 penalty to `bug` so a postmortem describing a bug in retrospect routes correctly), and removes the outcomes coupling entirely. Confidence is now capped at 0.5 when the runner-up is within 0.1 of the winner. The `cwd` argument is still accepted for backward compatibility but is not consulted. Regression coverage in `tests/intake-classifier-accuracy.test.mjs`.
- **`.eml` files no longer silently skipped during intake extraction.** `lib/document-extract.mjs` did not recognize the email extension, which dropped customer-email-as-signal flows on the floor without warning. Added a minimal RFC 5322 parser that unfolds headers, walks multipart boundaries, decodes quoted-printable and base64 transfer encodings, and concatenates `Subject`, `From`, `Date`, and the first `text/plain` part into the text the classifier reads. Attachments are excluded from the text and exposed on the result's `attachments` array. Messages above the 50 MB hard cap return empty text plus `skipped: 'too large'` rather than throwing. No new runtime dependency. Regression coverage in `tests/intake-eml-extraction.test.mjs`.
- **`construct embed start` now resolves rootDir from the project, not just homedir.** Previously, `resolveRootDir` returned `env.CX_DATA_DIR || homedir()`, so starting the daemon inside a Construct-initialized project watched `~/.cx/inbox/` instead of `<project>/.cx/inbox/`; the only workaround (`CX_DATA_DIR=$PWD`) was undiscoverable. The new precedence is (1) `CX_DATA_DIR` if explicitly set, (2) walk up from `process.cwd()` looking for `.cx/context.md` (capped at 10 parent levels), (3) `homedir()` fallback. `construct embed status` now prints the resolved `rootDir` and the inbox path it is watching alongside other status info. Regression tests in `tests/embed-rootdir-resolution.test.mjs`.
- **Profile `rebrand` config now drives user-facing intake terminology.** Each profile JSON carries `rebrand: { intakeQueueLabel, signalNoun }`, but the CLI hardcoded "intake queue" / "signal" / "intake" everywhere regardless of active profile, so `operations` projects still saw "intake" instead of "request" in every surface. A new `lib/profiles/rebrand.mjs` exports `getRebrand(rootDir)` with safe defaults (`Intake queue`, `signal`). `construct intake list` / `show` / `--help`, the embed daemon's classification log line, and the session-start intake prelude all route through the helper. Regression tests in `tests/profile-rebrand.test.mjs`.
- **Test suite no longer leaks `/tmp/construct-*` directories on every run.** Roughly 6,400 `/tmp` dirs had accumulated across at least 15 prefix families (`construct-sync-repo`, `construct-mcp-home`, `construct-github-cwd`, `construct-atlassian-*`, `construct-plugin-mcp-*`, `construct-bad-opencode-*`, `construct-opencode-plugin-*`, `construct-hybrid-env-*`, `construct-user-env-*`, `construct-remove-*`, `construct-mcp-cwd-*`, and others). Root cause: ~30 test files called `fs.mkdtempSync(...)` without a corresponding `fs.rmSync` or `t.after` cleanup, and shared helpers in `tests/helpers.mjs` and `tests/mcp-manager.test.mjs#tempDir` had no cleanup contract. Fix wires per-test cleanup into every offender (preferring `t.after(() => fs.rmSync(dir, { recursive: true, force: true }))` for per-test temp dirs, `after()` blocks with a tracked-dirs array for helper-style temp factories). The shared `tempDir(prefix, t)` helpers now accept the test context and register cleanup automatically when supplied. Regression guard `tests/test-hygiene.test.mjs` walks every `tests/**/*.mjs` file and fails the suite if a `mkdtempSync` call site lands without a sibling cleanup signal; the allowlist documents the single legitimate exemption (`helpers.mjs`, whose cleanup is delegated to the caller). Closes `construct-44p`.
- **`construct init --yes` no longer auto-registers project artifact directories as inbox watchers.** Previously, init scanned the project for known preset directories (`src`, `lib`, `packages`, `apps`, `services`, `docs`, `tests`, `spec`, `infra`, `config`, `scripts`, `tools`) and wrote every one that existed into `.cx/intake-config.json` as a `parentDir`. The intake daemon then treated every file in those directories as a fresh inbox signal: code commits, finished PRDs, ADRs, RFCs, and test files all got classified and routed as if they were new R&D signals, polluting the queue with false positives that drowned out real signals from `.cx/inbox/`. The new default is an empty `parentDirs` list. The built-in zones (`.cx/inbox/` and `docs/intake/` when it exists) remain watched. Extra dirs are opt-in via `construct intake config set --add-dir=<path>`. Init now always writes `.cx/intake-config.json` (previously only when parentDirs was non-empty) so users can inspect and edit the config. Regression test in `tests/init-intake-defaults.test.mjs`.
- **Embed daemon log no longer grows unbounded.** Two compounding bugs caused `~/.cx/runtime/embed-daemon.log` to reach 34 GB on a single local install:
  1. The scheduler in `lib/embed/scheduler.mjs` silently dropped the `repeat: false` option, so a one-shot startup job registered with `intervalMs: 0` became `setInterval(fn, 0)` and fired on every event-loop tick (~thousands per second). The job ran `runTelemetrySetup`, returned the "keys required" error, and (via stderr) wrote a log line each time. Scheduler now honors `repeat: false` and routes the task through a single `setTimeout` (or no timer at all when paired with `runImmediately: true`). Regression test in `tests/embed-scheduler.test.mjs`.
  2. The daemon log had no rotation policy. The parent process opens an append-mode FD at spawn time and the worker holds it for its full lifetime, so rotation has to happen before the spawn opens the FD. `lib/embed/cli.mjs` now calls a new `rotateEmbedLogIfNeeded(log, env)` at each spawn site (both `cmdEmbedStart` and `autoStartEmbedIfNeeded`). Cap defaults to 50 MB with 3 retained segments (worst-case 200 MB on disk). Override with `CONSTRUCT_EMBED_LOG_MAX_MB` and `CONSTRUCT_EMBED_LOG_KEEP`; both clamped to a sane hard cap. Regression tests in `tests/embed-log-rotation.test.mjs`.

## [1.0.3] - 2026-05-20

### Fixed

- **Integration status icon**: Integrations found in any AI host config now show `✓` instead of `⚠`. The `⚠` icon is reserved for `degraded` services (those that failed a health probe), not for fully-configured integrations. `lib/status.mjs` `serviceIcon()`.

- **Embed daemon crash on `emitTraceEvent(...).catch`**: `emitTraceEvent` is synchronous and returns a plain object, not a Promise. Three call sites in `lib/embed/daemon.mjs` called `.catch(() => {})` on the return value, throwing `TypeError: (intermediate value).catch is not a function` at runtime. Fixed by wrapping each call site in `try/catch`.
- **Telemetry setup log noise**: The `[embed] Telemetry setup skipped` message is no longer logged at daemon startup when telemetry credentials are not configured (solo mode default). Only unexpected errors are logged. `lib/embed/daemon.mjs`.
- **Telemetry and Memory (cm) no longer degrade overall health**: Both are optional services (`impactsOverall: false`). Missing telemetry credentials or a stopped cass-memory server no longer marks Construct as `degraded`. `lib/status.mjs`.
- **`construct init` silently skipped starting services**: `init-unified.mjs` imported `node:os` with destructuring (`const { os } = await import('node:os')`), but `os` is not a named export — the module itself is the default export. This caused `os.homedir()` to throw, the `catch` block swallowed the error, and `cm serve` (plus all other services) was never started. Fixed to `const { homedir } = await import('node:os')`. `lib/init-unified.mjs`.
- **Embed daemon start reliability**: `construct dev` (and `construct embed start`) now pass `rootDir` explicitly to avoid path-resolution fragility, close the log file descriptor in the parent process after spawn, verify the worker is still alive after a 400 ms liveness check, and surface any failure as a warning rather than silently swallowing it. `lib/embed/cli.mjs`, `bin/construct`.

## 1.0.0 — 2026-05-08

Initial public release.

Construct ships as an agent orchestration layer for OpenCode, Claude Code, and other coding surfaces — runnable locally for individuals — with a single user-facing persona that routes work across specialist agents and keeps shared project state aligned.

### Highlights

- **Distribution** — three install modes: project-pinned npm devDependency, global npm install, and bootstrap shims (`.construct/run.mjs` + `bootstrap.sh` + `bootstrap.ps1`) for non-Node projects. `construct init --devcontainer` for VS Code teams.
- **Provider system** — capability-driven contract with five built-in providers (GitHub, Atlassian Jira, Atlassian Confluence, Slack, Salesforce), per-provider circuit breakers, and a stable plugin contract for custom providers.
- **Plugin retrieval engine** — six-layer plugin contract (Embedder, Chunker, Indexer, Fuser, Reranker, Compressor) with RRF + MMR defaults and an eval harness covering Recall@k, MRR, and NDCG.
