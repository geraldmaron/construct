# Construct Strategy

Rewritten from scratch 2026-08-03 as a ground-up rebirth in a fresh repository (the predecessor, `construct-legacy`, is archived read-only). The code is a rewrite and not a continuation; the published identity is deliberately continuous. The npm package is `@geraldmaron/construct`, the predecessor's, and the version lineage continues past its `2.1.1` on the `3.0.0` line, published as prereleases under `--tag alpha`. The `construct` CLI command name is unchanged, as it always was.

The rewrite publishes under the predecessor's name rather than as a second package, and the load-bearing reason is the `latest` tag. `npm publish` moves `latest` to whatever it publishes unless told otherwise, so the original plan (`@geraldmaron/construct-engine` starting at `0.0.0`) would have made a from-scratch rewrite the default install for everyone already on `2.1.1`. A prerelease published under `--tag alpha` cannot move `latest` at all, so the promise that nothing is stable until the Phase 5 stakeholder-acceptance gate passes is enforced by the registry rather than implied by a number. `latest` stays on the predecessor's `2.1.1` until `3.0.0` is promoted deliberately. The other argument for a separate name was always the weaker one: it bought a clean lineage that is mostly cosmetic, since the predecessor's 48 published versions stay public either way (`construct-legacy` is archived rather than deleted), and it cost a second name to explain permanently.

**The first release was gated on a credential, not on a package name, and the project answered a credential problem with a naming decision twice before ever exercising a write.** That reasoning inferred token scope from an authed `GET` returning 200 and read npm's `E404` as "this token may not create a package." Publishing `3.0.0-alpha.0` to the package the token supposedly wrote returned **`E403`**: the token carried no write on `@geraldmaron/construct` either, so the name was never what stood in the way. `3.0.0-alpha.0` published 2026-08-04 over npm trusted publishing (OIDC), on the first attempt with no other change, carrying a SLSA v1 provenance attestation. The `latest`-tag argument above survives untouched; the credential half of the original reasoning does not.

The rewrite carries no backwards compatibility with anything published before `3.0.0`. The first official release is the first version of all of it: interfaces, flags, and schemas change outright while the `alpha` tag holds, rather than deprecating in place, because a prerelease nobody is promised stability on must not accrue compatibility debt to itself. The one backward obligation is exactly what Phase 1 made it: `construct cleanup` removes every trace older installs left behind.

Construct steps in as a staff member representing any role it carries, across a broad model-capability range, not only on frontier models (Gerald's directive, ratified 2026-08-16). Its eight points land in the sections they change: commitment 1, What is killed, Phase 5, and risk 4.

Nothing here erases anything. The predecessor's published versions cannot be unpublished (npm allows it within 72 hours, and afterwards only for a package with no dependents, under 300 weekly downloads, and a single maintainer, none of which hold here), so they remain visible and will be deprecated with a pointer to the rewrite rather than removed. Decisions from here forward live in two places only: this file (direction) and the tracker (work). There is no decision-record bureaucracy. Changing a numbered commitment below requires editing that section; the diff is the drift record, and it does not accrete as an exception elsewhere.

## North star

Point at an outcome and an invisible, learning staff fills in the roles you didn't know you needed. The user thinks about outcomes. They never think about legal, program management, or process, and they are never ambushed by a domain they didn't know existed.

The through-line under all of it: **Construct makes the obvious obvious.** A seasoned cross-functional team carries its most valuable knowledge tacitly ("of course this needs legal," "marketing and compliance should see this," "these two initiatives are colliding"), and that awareness lives in a few heads, unevenly distributed, gone when they are out of the room. The documented failure mode of organizations is exactly this gap: reviews missed because they were nobody's checkpoint, coordination that relied on informal conversation. Construct externalizes that tacit layer as explicit, evidence-backed, overridable risk awareness, so anyone can make the calls a veteran would make. Awareness informs; only the user blocks.

The through-line travels with the person, not only with the system. The tacit layer is method: how to research so a conclusion survives a hostile reader, what a deliverable owes before anyone relies on it, when legal needs to see a thing. Method does not need the spine present to be worth carrying. It ships as portable skills (Program shape, Phase 5) usable in any agent host, by Gerald first and by anyone who operates the way he does: people without legal or research training, for whom the guardrails and framing are what make expert-shaped method safe. Construct is the face of those skills and ways of thinking about problems; the kernel is the optional backbone that adds coverage, obligation, and provenance when it is present. "Awareness informs; only the user blocks" holds inside a skill too, carried by the skill's own stand-down rule: applying nothing is a designed outcome, not a failure to engage.

## The end-state user experience

A user states an outcome, not a task: "I want to launch a paid beta to EU users next month."

1. **The system infers the invisible roles.** It decomposes the outcome and detects the domains it implicates (privacy law, commerce and tax, program sequencing, product scoping) without the user naming any of them.
2. **Work happens in the background; only decisions surface.** The user gets a short decision inbox containing only calls that are genuinely theirs to make. Everything else gets done and filed.
3. **Deliverables arrive finished and traceable.** Every load-bearing claim traces to a source the reader can re-verify, or is explicitly marked `[unverified]`. Nothing is invented.
4. **Invocation is invisible; accountability never is.** The user does not need to know to ask for a role, but they always see what was done in its name: a work log of what was reviewed, what was flagged, and what needs a licensed human.
5. **The behavioral test of success:** across a full project, the user never types a role name and never manages a process.

A pointed outcome is one trigger, not the only one. The same staff keeps a standing watch over ground the user designates (the document repositories and work trackers a team already lives in) and surfaces what an extra set of eyes would catch: strategies quietly diverging, initiatives contending for the same resources, decisions that contradict each other. A watch is an outcome that never closes, running on the same spine and producing nothing but the same decision inbox. This is the lane the 2026 landscape leaves empty: the market builds coding agents that execute and observability that watches the agents; nothing watches the organization. Construct does not compete with the hosts, it harnesses them (commitment 1) and fills the void between them.

The audience is non-technical operators, reached through an outcome-in/decisions-out surface. The builder dogfoods the loop on real outcomes (including non-software ones, see Program shape) while the surface is built. The surface has two carriers, not two audiences: standalone, and projected into an agent host the user already works in. It is the same outcome-in/decisions-out loop either way; the host changes where the loop lives, never what the user must know.

## Architecture commitments

**1. Host-independent by adapter, never by rebuild.** Execution rides whatever agent host is present: OpenCode (first-class), Claude Agent SDK, Claude Code, or a direct API loop, behind one adapter interface (`execute(role, task, tools) → deliverable`). MCP is the tool-independence layer. Construct never builds its own agent runtime, memory engine, or tool broker in competition with the platforms. Presence is host-independent the same way execution is: beside the standalone CLI, the spine is projected into whatever agent host the user already works in (Claude Code, Codex, VS Code agent mode, OpenCode) through one protocol surface (MCP, with ACP noted for the hosts that speak it), never through per-editor builds. Adapters are for execution; the projection is for presence — with one deliberate exception the evidence forced (`RESEARCH-DECISIONS.md` §27): the projection may carry a **host-pull execution** surface, where the agent host the user already works in claims a ready task, executes it on its own already-present capacity, and submits the result as a draft through the token-scoped role-write seam. What never changes is completion: the projection exposes no way to advance completion state (commitment 14 applies to hosts exactly as it applies to roles), so a host may produce a draft but promotion still turns only on recorded verdicts. This is not a second runtime and not server-push (MCP sampling, the server-push mechanism, was deprecated 2026-07-28): it is ordinary host-initiated MCP tool calls spending the host's own capacity, never a paid Construct-side run started as a side effect of a host model being helpful. In Phase 2 the projection stays thin and serves dogfooding; host breadth and the host-pull surface are Phase 4/5 work behind the existing gates. Xirp, Spotify's agent session environment over Claude Code, Codex and Gemini, is read as a **host** under this commitment and not as a competitor: its own documentation puts domain routing, legal and compliance review, and deliverable obligations out of its scope, which is the whole of what Construct claims after the role-depth retirement. It is a projection target beside OpenCode behind the same Phase 4/5 host-breadth gates as any other, and nothing is written against it before then, because it is a macOS-only, Portal-coupled beta (`RESEARCH-DECISIONS.md` §16). A defined API connector is permitted as an adapter-tier module, a "direct" host implementing the same read and apply actions a host would, so work still happens when no host MCP server is present. It is not a second tool broker and it is not a kernel concern: the kernel stays zero-dependency and host-agnostic, Construct's own build never uses a product connector (using Construct is not building Construct), and every write still travels proposal → decision → apply under the existing consent tiers. The selection ladder is host MCP first, connector fallback, honest refusal when neither path exists, recorded per run. Tokens arrive through the environment (the existing `op run` pattern), never as kernel config. The use/build gate is structural rather than a matter of discipline: `scripts/lint-connector-gate.mjs` holds the forbidden import edges. Official remote MCP servers remain the preferred host-side recipe wherever they are available. The Phase 5 staff-member re-scope licenses the connector reading and the named host-breadth work; it does not license a new runtime.

**2. Playbook and lessons: growth by densification, not accumulation.** Shared operational method (how to decompose, verify, escalate, finish deliverables) is the playbook. Learning accretes as lessons: immutable, citation-carrying strata. A new lesson supersedes older lessons; it never rewrites or deletes them. Provenance always survives.

**3. Roles are lenses over a shared playbook.** A role is a framing and risk posture over the shared playbook. Placement rule: domain-agnostic method goes to the playbook; doctrine goes to the role. Boilerplate duplicated across role prompts is playbook material that was mis-filed. What a lens carries is narrow and real: obligations, standards grounding, and attribution. It is **not** a thick domain corpus. That description rested on the depth premise Phase 4 retired, and the record of what a domain corpus contains (a name, a one-line concern, a keyword list, and a licensed-review flag; construct-kl4) never supported it. Doctrine depth returns only behind a measured gate, and the severable export of exactly the surviving part is the skill (Program shape, Phase 5).

**4. Every role has a learning loop: research → distill → operationalize.** Distillations become lessons only after passing the admission gate.

**5. Lesson admission is risk-weighted.** Low-risk domain lessons auto-admit after an adversarial verification pass. High-risk domains (legal doctrine above all) require explicit human approval before a lesson goes operational.

**6. Lessons default to workspace scope; cross-workspace promotion is explicit.** A lesson belongs to the workspace it was produced in. Promoting a lesson to serve the user across all their workspaces is a user decision per lesson, permitted only for technique/process lessons, and source quotes and facts are stripped before promotion. A workspace carries a consent tier: whether it may consume globally-promoted lessons at all (client and confidential work default to no). The original design defaulted lessons to per-user cross-workspace scope, and the adversarial review of 2026-08-03 found that made client A's confidential facts part of client B's prompts as the happy path, not an edge case. A lesson whose citation originates from an ingested external document can never auto-admit, regardless of risk tier: it always lands in human review, because verification by another LLM reading the same attacker-authored text cannot be trusted to catch injected instructions.

That ceiling governs the deliverable and review read paths exactly as it governs lessons. Ground is authored by whoever wrote the documents (in a directory source the attacker names the files and fills them), and the red-team run over a hostile fixture (construct-472j.4) established that most injection shapes reached the model as bare text, because content arrives as the host's own file-read output and no layer Construct controls could mark it. The read paths therefore enforce structurally what can be enforced and disclose what cannot: a filename carrying control characters is refused at the survey and every surveyed string is escaped where it enters a prompt, so a filename cannot forge a prompt line; a cited document is checked for containing what it is cited for, and support the check cannot verify is printed as such rather than credited; a review that cannot show its ground was read does not print the clean line, and a review's account of what it considered travels with its verdict, so steered silence and genuinely clean are different outputs; printed provenance names the document the wording came from, not only the declared source; and every grounded prompt states that document content is material to report on, never direction to follow. A model reading attacker-authored ground cannot be trusted to catch what that ground injects, so where a gap can only be disclosed rather than closed, the disclosure is the requirement, not a waiver of it. Risk 5 covers read-path steering, not only lesson admission.

**7. Prompts may evolve, through the same gate.** A lesson may propose an amendment to a role's operating prompt. Amendments pass the same risk-weighted admission gate and must show non-regression on the eval suite before adoption. There is no ungated self-modification.

**8. Improvement is proven by evals, not vibes.** Past outcomes become fixed scenario evals. A candidate lesson (corpus or prompt) re-runs the relevant suite and must not regress to be admitted. Below the data-volume threshold where a suite is statistically meaningful (see Program shape, Phase 3), prompt changes are eyeball-reviewed and labeled as such — an ungrounded eval gate is worse than an honest manual one.

**9. The risk heat map is alive, and it governs three things.** Heat is inferred from outcome context, learned from history and incidents, and overridable by the user. Heat governs: which roles engage, how strict their gates run, and retention policy. Rare-but-critical knowledge in hot domains never auto-compacts. Heat and routing never consume a model's self-reported confidence: verbalized confidence is documented as systematically miscalibrated, with the highest stated confidence often attached to wrong outputs. What routing may consume is measured: per-tier rates from labeled runs, human labels, recorded incidents. A confidence number without a labeled ground truth to calibrate it against does not enter a decision. The intake ramp died for this, and graduated autonomy waits for Phase 3's labels behind the same rule.

**10. Briefs declare; a dispatcher satisfies.** A brief specifies what a task needs: inputs, tool capabilities, verification postconditions. One dispatcher resolves those requirements against available tools (MCP connectors included) and roles. Briefs do not orchestrate themselves. What actually verifies a deliverable is the challenge catalog and the template's required slots, both of which run on every dispatch and fail loudly. Binary postconditions are the seam for a machine-checkable output packet, and no rule ships registered: a pack that needs one registers it with the pack, keyed to a domain a dispatch can emit. The distinction matters because a declared obligation nothing evaluates is the asserted-not-measured shape this document exists to refuse, and five inherited postcondition rules sat in exactly that shape until they were deleted as unreachable.

**11. Cross-domain conflicts surface as user decisions.** When one role says wait and another says ship, the system frames the tradeoff with both sides cited and puts it in the decision inbox. No hidden precedence order, no heat-map auto-arbitration on judgment calls. Every inbox decision, conflict or not, ships as a risk assessment rather than a bare question. The shape is a contract: what pattern triggered it, what validated evidence supports it, the stakes on each branch, the reversible default if the user does nothing, and which role would normally have caught it. That last field is the product speaking its purpose: it names the tacit knowledge being made explicit.

**12. Legal operates as research and issue-spotting: named "issue-spotter," never "analyst" or "lawyer."** It finds the governing text (statute, regulation, controlling precedent), cites it from the primary source, states how it applies here and where it is genuinely unsettled, and labels every deliverable as research, not legal advice. What is practice rather than research (representation, filings, sign-off where real liability turns on an unsettled question) routes to licensed counsel via a concrete jurisdiction-aware referral package, not a disclaimer. Navigating legal and regulatory considerations is a capability the system carries the way it carries any research domain (decided by Gerald 2026-08-21, closing the standing attorney-acceptance gate, construct-7xrl); honest labeling, primary-source citation, and targeted referral are the protections. Silent legal is a defect, not a feature.

**13. Adversarial challenge is a contract, not a courtesy.** Every brief may name challenges it must satisfy before a deliverable promotes past `draft`: a documented strongest objection on load-bearing decisions, a pre-mortem on plans, a citation or `[unverified]` tag on every claim, a legal issue-spot pass on heat-flagged deliverables, a scope diff against the brief. Deterministic structural checks run always and free; a second-role substantive pass runs only where the brief's heat warrants it. Waivers are the user's alone, per deliverable, per challenge, and are logged — never a global off-switch.

**14. Completion state is kernel-owned, never a tool a role can call on itself.** `draft → challenged → final` is a dispatcher-owned transition triggered by recorded verdicts. A role holds a capability token scoped to its own run and task; it can submit drafts and append to the work log, and nothing else. This exists because an ungated write surface lets a role under completion pressure mark its own challenge passed — verified as a live failure mode in the predecessor.

**15. No-fabrication remains the trust kernel.** It was the strongest differentiated asset in the 2026-08-03 competitive audit and it is load-bearing for everything above: lessons, work logs, deliverables, evals.

**16. Construct is the first organization Construct monitors.** The system maintains a generated, never-hand-edited self-model (what subsystems and packs exist, what actually runs, per the work log). Every tracker item cites the commitment or phase-exit it serves; work without lineage is a decision — amend this document or drop the work — not silent scope creep. This is the direct countermeasure to the predecessor's drift through five unstated strategic pivots.

**17. Construct speaks in one voice.** Artifacts sound like Construct (plain, direct, no hype vocabulary; the register this document is written in) unless the user overrides it, per artifact or per workspace, and the override is recorded. Voice is bound where deliverables are rendered, never policed by regex after the fact (the predecessor's marketing-voice regex stays dead). A role cannot ship an artifact outside the voice without that recorded override, for the same reason completion state is kernel-owned: identity is not a per-role option. The definition and binding landed 2026-08-05: nine rules in `src/kernel/voice/voice.ts` covering register as well as vocabulary (lead with the finding, then tell the story; write like a person, not an institution; plain words; complete sentences; sparing em dashes; language any reader can see themselves in; name the gap; never invent a fact, with the `[cite:…]`/`[unverified]` notation the deterministic check already reads), bound into every role's assignment before the work happens, with `construct work --voice="…"` as the override and a `voice-overridden` work-log entry at each dispatch it shapes. `docs/example-deliverable.md` is the worked example. The identity a dispatch carries is one instruction, not two: `constructIdentity(attribution)` in `src/kernel/voice/voice.ts` states who is writing, what framed the work, and the voice it is written in as a single statement, because naming a role and then binding the house voice further down is two answers to one question and leaves the model to pick between them without saying which it picked. Roles, lenses, and concerns **frame**: they decide what is examined and what the work owes, and framing is exposed as attribution, never as a register of its own. A composed document names the concerns that framed it, in Construct's name, above anything they framed, and the review shape asks for each role's substance named to the role rather than stated "in its own terms". All four host adapters bind that same identity through one `frameHostTask`; OpenCode's `--agent` path is excepted, because the identity there is OpenCode's own and not Construct's to write over. The composition passes that produce what a reader actually holds (the arrangement, Construct's call, its one repair, and the closing round) carry the voice too. Deliverable templates are ported, and they carry **form** (`issues`, `requirements`, `sequence`, `questions`, `prose`), declared per template in `plan/schema.ts` and spoken by the voice seam's content-shape protocol, in place of a single directive that had demanded numbered issues of every deliverable in the catalog, of a PRD and a sequencing plan as readily as of a privacy review. Composition shapes (review, decision, spec, RFC, ADR, one-pager) plus claim kinds (bullet, paragraph, table, diagram) are the document-shape path for composed artifacts: an ask for an architecture decision record gets that document, not a review memo. `construct show` hands a reader the publish view, with `--record` for the stored form the gates read.

## What carries over from the predecessor

Harvested as libraries with their tests, ported behind an explicit sterile test discipline, with no CLI or repo assumptions: outcome classification and routing, no-fabrication enforcement, brief postcondition validation, the deliverable completion ladder, the multi-host sync seam, the extraction ladder (Docling as a probe-gated rung, never required), and the tracker model — on a new SQLite-backed substrate rather than the predecessor's dolt-locked one. The design-language (one Construct voice) and deliverable templates (playbook slots and forms, composition shapes) are in the render path. The marketing-voice regex policing does not carry over.

## What is killed

Named explicitly so it stays dead: team and enterprise deployment modes, workspace presets as a product surface, the parallel-platform ambition (own runtime, own registry-as-product), decorative role metadata, the ADR/RFC/PRD documentation system as Construct's own internal process, and any daemon that runs when nothing asked it to. The designed state is nothing running. Residency is opt-in, never automatic: a user may explicitly install a scheduled firing, an on-demand idle-exiting daemon, or an always-on supervised service, each bounded and reaped per the three-tier decision in `RESEARCH-DECISIONS.md` §29 (Gerald, 2026-08-25); what stays dead is anything resident that no explicit user verb asked for — auto-start from init, library code, or install is the leak class and remains killed by name.

What the ADR/RFC/PRD line kills is the **internal process**: decision records as bureaucracy this program imposes on itself. This file and the tracker are the record, and there is no interior ADR stream. User-facing deliverable *shapes* a staff role hands back were never the target. An ADR, RFC, PRD, interview guide, or hypothesis document the user asked for is served as a composition shape like any other. Those are artifacts of the staff-member program, not a revival of the process that accreted around the predecessor.

Also dead: decision-theory modeling ahead of a consuming decision. Measuring what runs stays the house discipline (RESEARCH-DECISIONS.md exists because of it, and its §§5 and 10 are what let the routing direction change on evidence instead of taste). But Markov chains, queueing models, and value-of-information machinery for paths no shipped decision consumes died with construct-2jb.10 and .11, and anything of that shape gets challenged by name, exactly as risk 4 challenges runtime creep. The test is one question: which shipped decision consumes this number?

Also dead or deferred behind a named trigger, so the skills wedge cannot quietly become a platform: a skills registry or marketplace (git-as-registry and copy-paste are the distribution, and a registry is a curation liability rather than a feature); a guardrail compiler or hooks layer before three or more skills are in real use and the manual tier pattern has been felt on real work; follow-on skills as filed work before the pilot's pre-registered falsification test survives ten real uses (candidates live in the skill-library epic's notes, not the tracker's ready list); the second tuned family as a phase blocker (Phase 4 measures it per skill and per promotion gate instead); and any claim that a skill "makes users better" that does not name its falsification test before first use. Depth-adjacent ambitions stay dead.

## Program shape

Phases gate on evidence, not calendar. The full work graph with acceptance criteria lives in the tracker, each item citing the commitment or phase it serves (commitment 16).

- **Phase 0 — Bootstrap and guardrails.** Sterile test contract, packaged-install smoke, parity lints (no absolute paths, glossary), a minimal fail-open hook set, the tracker initialized.
- **Phase 1 — Kernel harvest and predecessor cleanup.** The only backward obligation: a `cleanup` command that removes every trace the predecessor left, verified against a fixture home built from a real predecessor install. Shipped in the first prerelease published under `--tag alpha`, `3.0.0-alpha.0`.
- **Phase 2 — Spine.** Outcome → implication map → dispatch → host adapter → deliverable, work log, decision inbox. A bounded run coordinator (not an agent pool, which is enterprise cosplay at this scale) makes concurrent role execution crash-safe and cost-bounded. Dogfooded by building this rebirth itself, with an explicit quota: of the first ten outcomes run through the spine, at least four are non-engineering and at least two are legal- or compliance-flavored, so the implication map is not tuned solely to the one distribution its author needs least. The quota is stratification and is not negotiable downward; ten outcomes cannot reach the sequential boundary the withdrawn external-user gate would have required, so **Phase 2 exits on composition and on evidence collected, and states no success-rate claim at all.** No phase exits on external people. Every phase exits on a **stakeholder-acceptance gate** instead: the session runs real outcomes end to end through the shipped surface, records them as a reviewable packet, and the stakeholder checks the outcomes themselves. What that licenses is stated in full at Phase 5, because it is less than the gate it replaces. The phase also carries a thin host projection of the spine: one MCP surface over outcome, work, log, inbox, and decide, so the loop can be dogfooded from inside an agent host. Thin is a constraint, not a mood: no logic the CLI spine does not already have, and breadth beyond the single surface — including the host-pull execution surface commitment 1 now permits — waits behind the Phase 4/5 gates. The one thing host-pull execution may never do is advance completion state; that stays kernel-owned and verdict-gated (commitment 14), which is what keeps the thin-projection promise true even as the surface grows.
- **Phase 3 — Lessons and challenges.** The lesson store, admission gate, and challenge contracts ship with only the machinery the data volume can support. Retention automation, learned heat baselines, and eval-gated prompt evolution are each deferred behind a written data-volume trigger rather than built speculatively, and the triggers and their derivations are written in `RESEARCH-DECISIONS.md` §12 (168 stored lessons, 25 labeled real runs in a domain, 40 scenario evals, derived 2026-08-05). The first standing watch also ships here, pointed at Construct itself, which is commitment 16 made operational: drift between this document, the tracker, and the repo surfaces as inbox decisions rather than a session ritual (construct-h66.1). Watches over external ground wait for Phase 4 breadth behind the existing gates.
- **Phase 4 — Pack breadth and the model matrix.** Fifteen lenses ship, covering the seventeen catalog domains: `compliance`, `legal`, `program`, `product`, `strategy`, `architect`, `operations`, `design`, `security`, `analyst`, `research`, `coverage`, `commerce`, `brand`, `engineering`. Depth is ordered by gap value, so the awareness packs deepen first (legal issue-spotting, compliance, program management): they carry the tacit cross-functional knowledge the agent hosts do not, and the documented organizational failure mode, reviews missed in the gaps between departments, is the gap they close. Engineering stays thin permanently by design, because the hosts are the engineers.

  **Per-role depth is retired as a claim, and the isolation criterion that would have measured it is withdrawn.** This phase once exited on "all role packs reach real depth," operationalized as isolation: the lens that owns a planted finding produces it and no other lens does. Nothing ever passed that bar. Four instrument-side explanations were tested and rejected in turn: keyword brittleness, unbounded per-role output, plant keying, and finally corpus breadth, tested by building a second fixture organization from a real organization's operating documentation, held to parity on document count and bytes, and sweeping it beside the original on one family in one sitting. **0 of 10 plants isolate on the broad corpus against 1 of 10 on the original.** Each rejected explanation had been a way for the result to be the instrument's fault. What remained was the premise, and the external record settles it: persona prompting is measured not to improve performance (162 personas, four model families, 2,410 questions), and the agent-scaling result separates persona diversity from model diversity, with the effect size living in the latter. The criterion measured something that does not exist. Evidence, confounds (the broad corpus was the harder of the two, which is why the finding is "breadth did not rescue discrimination" and not "breadth made it worse"), and sources: `RESEARCH-DECISIONS.md` §§14–15. **No pack is described as at depth on any surface.**

  What roles keep is the three jobs that never depended on depth: **routing and coverage, attribution, and obligation.** A pack closes when its concern routes from wording that never names it, its lens carries that concern's obligations into the deliverable template as checkable slots, and the work log attributes what was produced in its name. Each is checkable by unit test and by one run through the shipped surface. Independence, where it is load-bearing (adversarial challenge, judge passes), is bought with cross-family dispatch through the existing adapter seam, never with personas. Breadth comes from giving dispatches different material, not different questions. The depth budget moved to verification and grounding, where the multi-agent failure taxonomy puts the failures and where this project's actual asset already sits.

  **The model matrix is staggered by design rather than tuned on day one.** Claude is the one tuned family in `TUNED_FAMILIES`, tuned 2026-08-05 against fixture-organization scored runs; every other family runs, labeled best-effort, writing a degradation note into the work log on every dispatch. A second tuned family is **not** a phase-exit criterion. It is measured where it is consumed, per skill and per promotion gate, when a falsification test or a family-promotion decision actually needs the number; the open-weight eval-gate item stays tracked. That criterion had gone unmet since it was written, blocked on credentials and harness passes no session could produce, and a phase that cannot exit on work the program can actually do is the unpayable-gate shape Phase 5 already refused once.
- **Phase 5 — Surface and the stakeholder-acceptance gate.** **There are no external subjects in this program.** The phase exits on a stakeholder-acceptance gate: the session runs real outcomes end to end through the shipped surface without typing a role name, records each as a reviewable packet, and the stakeholder reads the outcomes and accepts or rejects them. This replaced a sequential external-user gate, which itself replaced "three to five external users"; `RESEARCH-DECISIONS.md` §9 keeps the derivation of what each design would have proved.

  What that licenses, stated plainly: **nothing about anyone other than the author.** The retired gate was a sampling design over external users, and no amount of self-evaluation is a sample from that population, so the claim it would have licensed, "works for more than 70% of users," is **withdrawn, not restated at a lower confidence.** Until external evidence exists, the project claims only that the surface performs as recorded on the outcomes recorded, and **any user-facing wording that implies a rate across users is a defect.** This is a deliberate trade: a gate that cannot be paid for is not a gate, and an unpayable gate blocking Phase 5 forever would have made every downstream commitment untestable.

  **The direction question is answered: personal tool first, with one product wedge, portable skills.** The no-external-subjects rule means the organizational claim can never be validated against any organization but this one, so the program stops carrying a product-in-waiting it cannot test and keeps the part that travels: the method itself, shipped as severable skills under `skills/`, one self-contained file per skill, conforming to the six-field Agent Skills frontmatter, usable in any agent host with no construct checkout present. Their acceptance gate is this phase's own discipline: recorded real-work use in a use ledger, each skill's falsification test named before first use, claims licensed only for the outcomes recorded. The kernel is not diminished by this. Coverage, obligation and provenance remain what it does; it is demoted from prerequisite to backbone, adding provenance and the lessons loop when present, with the skills working identically when it is absent. Reasoning and external evidence: `RESEARCH-DECISIONS.md` §22.

  The "no new roles until acceptance" hold is lifted for the base org-coverage build, the first packet case having been accepted on its merits (`docs/internal/stakeholder-acceptance-phase-5.md`, Case 1). The concerns a cross-functional team owns ship as catalog domains, lenses and deliverable templates. What is **not** lifted is the standard those packs are held to, and that standard is the three jobs that survive the depth retirement: a pack closes when its concern **routes** from wording that never names it, its lens carries the **obligations** that concern owes into the deliverable template as checkable slots, and the work log **attributes** what was produced in its name. Each is checkable by unit test and by one run through the shipped surface. A harness plant hit is not in that path, and no pack is described as at depth on any surface (Phase 4; `RESEARCH-DECISIONS.md` §15).

  The staff-member capability program operates inside the personal-tool-first decision, not beside it. Licensed under it: Construct representing any role it already carries, authoring the checkable artifacts that role hands back; tracker writes of follow-up work under the consent tiers already on the store (proposal, decision, apply, never an ungated write); host breadth that does not adopt a new framework (nanobot stays the non-IDE dogfood host, goose and pi are probe targets pinned the way OpenCode is, and Agent Skills plus MCP remain the portability seam); cleanup of leftover 2.x `construct sync` artifacts as remove-and-rewire-to-3.x rather than a second projection scheme; defined API connectors behind the commitment-1 gate; and consumer-app confidence as a program goal, proved by a recorded packet rather than by a claim. What it does **not** license: lifting the stakeholder-acceptance gate on packets, the no-external-subjects rule, or the prohibition on cross-user success-rate claims; nor a new agent runtime, a Construct-owned chat UI, a daemon, or connectors inside the kernel. Packets still go to Gerald.

  What keeps the measured claims honest without external subjects: **measurement independence lives in the instruments, not in who reads the result.** The org-harness answer key is committed before any run and never edited to fit one. Scoring is structural, and structural scoring alone is not enough: it credits a plant when a claim cites the planted documents and matches the terms, which a claim about a different mechanism over the same document pair also does. That was measured in both directions, and terms cannot separate the cases, since no plant has every term met by a high-frequency alternative and narrowing terms after a run is the same offence as widening them. **Mechanism correctness is therefore judged**, by a named model, against each plant's `gist`, which was committed before any run and which the scorer has never read, so the standard was fixed in advance rather than fitted to results. The judged verdict is recorded beside the structural score and never folded into it; no recorded score is regenerated. What carries measurement independence is a standard fixed before the run. What is retired is the claim that such a standard can be applied without judgment. Where a judging model shares a family with the model under test, **observed agreement is an upper bound on independent agreement**, and that qualification travels with any figure quoted from a judged file. Stakeholder acceptance is a product judgment on top of that evidence; it is never itself cited as measurement.

## Named risks

1. **The implication map underdelivers.** Then the whole vision is a routing demo. Mitigation: it is Phase 2 and measured, a labeled outcome set with a pre-agreed miss-rate target rather than an assumption. **The mitigation fired.** Measured on wording authored by minds that never saw the catalog, the keyword map misses 0.663 (Wilson 95% [0.556, 0.755]) on the `unspent` corpus alone against the 0.15 target, and the ceiling is structural: a miss always closes with a word nobody listed, and adding it loses the next ten (construct-4jq, RESEARCH-DECISIONS.md §5). The direction is therefore inverted, measured through the shipped seam and adopted 2026-08-05 on Gerald's acceptance of the `RESEARCH-DECISIONS.md` §10 figures. Wherever a capable host model is present it is the primary namer of implicated domains, under the kernel's admission and evidence gates, and the keyword map is demoted to the zero-model fallback and the evidence layer, with every fallback stated in the work log. A hand-tuned dictionary competing with the host's model at reading the user's words is risk 4's creep applied to intelligence instead of runtime. The 0.15 absolute target is retired for §10's relative dominance gate, re-measured per tier. The figure quoted here is scoped to one corpus; the canonical zero-model rate every later section and the README use is the pooled out-of-family one, 0.634 (59/93, [0.533, 0.725]), which `npm run check:figures` re-derives. Both are correct and they are not the same denominator.
2. **Solo bandwidth against the schedule this program actually requires.** Mitigation: stagger the model matrix rather than tuning every family on day one. The long pole this risk originally named was "all packs at real depth before first release." Per-role depth is retired (Phase 4), so that pole is gone, and what replaced it is cheaper, which is a real reduction in this risk rather than a restatement of it: the surviving obligations (routing, attribution, deliverable slots) are unit-testable and do not require a scored corpus sweep per pack. The remaining long pole is the second tuned family, tracked on the open-weight eval-gate item.
3. **Legal and regulatory exposure.** Mitigation: issue-spotter naming, research-not-advice labeling on every artifact, primary-source citation discipline, jurisdiction analysis as part of the method (which law governs, what the governing text actually says), and a real referral package as the escalation artifact for what genuinely requires licensed counsel: representation, filings, sign-off where real liability turns on an unsettled question. There is no standing attorney-acceptance gate: Gerald decided (2026-08-21, closing construct-7xrl) that navigating legal considerations is a capability the system carries like any research domain, with honest labeling and targeted referral as the protections. Commitment 12 states the operating rule.
4. **Homebrew-runtime creep.** Independence pressure quietly turning into a second agent runtime. Mitigation: commitment 1 is a veto, and any work item that reimplements a host capability gets challenged by name. A defined API connector is the shape this risk will try to become. The counter is the same veto: connectors live at the adapter tier, the kernel imports none of them, and Construct's own build uses none of them. A connector that starts answering kernel questions has become a runtime.
5. **Lesson poisoning and doctrine rot.** Mitigation: workspace scoping by default, a provenance ceiling that routes any corpus-derived lesson to human review regardless of risk tier, admission gates, and append-only rollback.
6. **Eval and matrix cost outrunning a solo maintainer.** Mitigation: tiered evals (deterministic on every change, LLM-judged only at release gates), a hard budget cap enforced in CI, and a staggered rather than fully-tuned model matrix.
7. **The system drifting the way its predecessor did.** Mitigation: commitment 16 — a generated self-model, commitment-lineage checks on all new work, and a standing self-outcome that keeps this rebirth honest against this document.

## Ground truth this rewrite stands on

Adversarial review of 2026-08-03 (two independent technical and feasibility passes) found and closed three critical defects in the original design before any code shipped: an MCP write surface a role could use to certify its own work, a lesson-admission path vulnerable to prompt injection from ingested documents, and a cross-workspace lesson default that was a confidentiality breach by construction. All three are reflected in the commitments above, not carried forward as known issues. The predecessor reached 4 GitHub stars and roughly 782 npm downloads a week while roughly sixty percent of its pull requests were self-inflicted maintenance; this rewrite's discipline exists because that number is the strongest available evidence for what to change.
