*For Gerald, the decider. This document recommends where to concentrate the
program's effort given the August 2026 platform landscape. It was produced
under the suite's own skills — intake, context-mapping, investigative-research
(the landscape evidence, `skill-runs/2026-08-21-investigative-research-run-4.md`),
decision-framing, written-voice — and it has been through independent
adversarial review (`skill-runs/2026-08-21-adversarial-review-run-2.md`),
which returned accepted-with-controls; all three required controls are
applied in this text. Verdict status: proposed — the decider has not yet
accepted.*

**The recommendation, first: stay on the recorded two-layer course — method
skills as the face, the kernel as the provenance backbone — and add one hedge:
project the kernel's provenance surface outward now (MCP, documented, dated),
so that if the governance window opens before the incumbents close it,
construct is standing in it.** The rest of this document is why, what was
considered instead, and what would change the answer.

## Where the landscape actually is (evidence, not vibes)

Five findings carry this strategy; each is cited in the research record with
source classes and the unverified marks preserved:

1. **The model layer and the basic agent loop have commoditized.** Frontier
   access and plan-act-observe loops are table stakes; the convergent
   commentary and Meta's reported acquisition of a model-less orchestration
   company point the same way [research: landscape run §2].
2. **The interface layer is standardizing, fast, and in construct's favor.**
   MCP moved to a Linux Foundation directed fund (Anthropic + Block + OpenAI
   founding, Google/Microsoft/AWS supporting — primary announcement, read).
   The Agent Skills SKILL.md format is reported compatible across Microsoft,
   OpenAI, Google, JetBrains, AWS, and Block tooling — but that claim rests
   on convergent aggregator reporting only, with no per-vendor primary
   source read, and "can parse the file" is not "adopted as a first-class
   contract" [research: landscape run §1; downgraded here on adversarial
   review]. What is primary-sourced is MCP's foundation move. So the
   interface finding is stated at its supported strength: MCP has firmed;
   the skills format is spreading but its governance has not converged —
   which is why that convergence appears below as a future trigger, not a
   present fact. Construct's skills ship in the format either way; its
   serve surface already speaks MCP.
3. **Skill content has commoditized where it is engineering-shaped and has
   not where it is method-shaped.** Flagship collections (~171k–275k stars)
   are engineering/config catalogs; no flagship carries a
   deliverable-challenge skill; method depth — disconfirmation, verification
   records, obligation gates — appears in none of the overlapping skills
   read [cite: ecosystem survey, run 3; ECC verification, run 2].
4. **Governance and provenance for agent work is promised, not shipped.**
   No platform studied ships cross-host, work-product-level audit; OpenAI's
   own language is "coming soon"; the standards activity that exists is
   government-led (Singapore IMDA, NIST initiative — secondary coverage,
   flagged) and does not reach deliverable-level obligation tracking
   [research: landscape run §3].
5. **The commoditization narrative itself has an interested author.** The
   "next layer is where value lives" story is told loudest by parties selling
   it; the strongest counter-scenario is an incumbent bundling an audit SKU
   into existing enterprise pricing within quarters [research: landscape run,
   strongest objection — kept alive here, not filed away].

## The decision

**Choice:** where the program's next quarters of effort concentrate.
**Decider:** Gerald. **Reversibility:** costly to reverse — files and code
are cheap to redirect, but quarters of a solo operator's time and the
compounding of whichever record (ledger, or enterprise trust) is chosen
cannot be recalled. **Do-nothing baseline:** the current course continues by
default — it is a real option and close to the recommendation, differing
only in the hedge.

**Options, honestly generated:**

- **Method-first, provenance-projected (recommended).** Keep the recorded
  Phase 5 course: skills as the severable face, demand-pulled deliverable
  layer, ledger as the validity engine. Add the hedge: document and date the
  kernel's provenance/obligation surface as an MCP-reachable capability —
  not an enterprise product, a standing position. Scope, stated per
  adversarial review: the MCP surface is already live (serve exposes the
  work log, inbox, and decisions as presence-not-execution — ran, this
  repo), so the hedge is a documentation-and-dating pass over an existing
  capability, not new engineering; if that proves wrong in the writing, the
  hedge is re-costed before it proceeds, never absorbed silently. Cost as
  scoped: small; the risk is spreading attention.
- **Governance pivot.** Bet the program on finding 4: build the
  agent-accountability layer for enterprises now, ahead of the incumbents'
  "coming soon." The advocate's case: it is the least-occupied ground with
  the strongest structural demand (regulation is arriving; platforms govern
  what agents may touch, not what they verifiably did). The case against,
  from the record: enterprise procurement favors bundled incumbents on
  inertia alone [research: landscape run, pre-mortem]; a solo operator with
  a no-cross-user-claims constraint cannot run enterprise sales; and the
  program's proven asset — the ledger's gate-changed evidence — is in
  method, not governance sales. A narrower variant — productizing the
  measurement discipline itself for peer solo builders rather than
  enterprises — was raised in review and is real; it is out of scope this
  cycle for the same bandwidth reason the pivot is, and it is noted here so
  its omission is a choice on the record, not a blind spot.
- **Platform play.** Build or embed an agent runtime. Disqualified by
  standing commitment (construct never ships its own runtime), and the
  commoditization finding says this ground is where value is leaving, not
  arriving.
- **Ungated drift (do-nothing exactly).** The current course without the
  hedge. Dominated by the recommendation: the hedge costs a documentation
  pass, and without it finding 4's window closes silently.

**Why the recommendation holds:** the program's differentiator is not the
skill files — they are Apache-2.0 and copyable by design. It is the
production system behind them: pre-registered falsification, recorded runs,
a ledger that would show refutation if it came, and a kernel that gives the
method provenance when present. That system compounds with use and cannot be
copied by forking a repo. Method-first keeps compounding it; the provenance
projection converts finding 4 from a temptation into a standing option with
a dated record, exercisable if the window stays open.

**What would change the answer:**
- An incumbent ships a bundled, cross-host, work-product-level audit SKU —
  the governance option's window closes; drop the hedge to documentation.
- The ledger's next ten rows trend toward refutation — the method bet loses
  its evidence; reopen this decision entirely rather than patching it.
- The Agent Skills format's governance moves to a foundation the way MCP's
  did — the distribution ground firms; consider promoting the skills wedge
  from personal-tool-first toward public release, behind its recorded gates
  (attorney review for legal/compliance remains a hard gate).

**Pre-mortem.** Assume this was followed and failed. The likeliest story:
the two layers quietly become three jobs — skills, kernel, hedge — and the
solo operator's usage bandwidth (already the ledger's scarce input) spreads
until no skill reaches its ten-use resolution and the hedge document goes
stale, so a year passes with neither the method claim proven nor the
governance option exercisable. Early signal: a month with no new ledger
rows. Cheap mitigation, adopted as a control: the hedge is a single dated
document produced once and refreshed only by revisit triggers, never a
workstream; and the reconciliation ritual gains two checks — the ledger's
row count, and the hedge document's last-reviewed date against its revisit
triggers — so a stall or a stale option is seen at session boundaries, not
discovered at review time. Trigger detection itself is assigned a cadence
rather than left to chance: the landscape's revisit triggers are checked on
the same periodic pass, since a window that closes silently was the
review's named strongest failure mode.
