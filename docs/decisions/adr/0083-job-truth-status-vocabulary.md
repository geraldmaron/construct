# ADR-0083: Job truth-status vocabulary — ran/supported/evidenceFresh/resultStatus/error

- **Date**: 2026-07-16
- **Status**: proposed
- **Deciders**: Gerald Dagher
- **Supersedes**: none
- **Resolves**: `construct-4uxq0.4.8` (ADR-H, decision only). The 17-call-site generalization this vocabulary implies is separately tracked as `construct-4uxq0.9.6`, currently blocked (see Consequences) — not resolved by this ADR.

## Problem

The embed daemon runs 19 scheduled jobs (`lib/embed/daemon.mjs`). Several report their outcome as a plain data shape — e.g. `{gaps: [], ticketsCreated: 0}` — that is bit-for-bit identical whether the job ran its analysis and genuinely found nothing, or crashed before doing any work and the catch block substituted an empty default. A caller, Oracle, or human operator reading the result cannot tell "nothing to do" from "the job never ran." `docs/notes/research/2026-07-continuous-work-audit/truth-matrix.md` rows 5 and 6 document two concrete instances of this on `main` (pre-#409): the `execution-gap` job calls a read-only Jira provider's `.search()`/`.write()`, which don't exist on that provider, throws, and the catch returns the same zero-gaps shape as a clean run; the `roadmap` job's Slack-post step does the same against a read-only Slack provider. `docs/notes/research/2026-07-continuous-work-audit/oracle-miss-report.md` names this pattern **M1 — vocabulary gap**: Oracle's own verdict vocabulary (`healthy`/`attention`/`degraded`) has no slot for "analysis didn't run," so even a perfectly reasoning Oracle has nothing to consume that would let it distinguish these cases. There is no canonical shape a daemon job is expected to return that encodes this distinction, so each job that gets fixed invents its own ad hoc fields.

## Context

Truth-matrix rows 5-6 are marked `contradicted (fixed honestly by #409, still branch-only)`. PR #409 (branch `chore/ws-a-truth-hygiene`, diffed here against `origin/main`) touches exactly these two jobs, but not identically:

- **`execution-gap`** (`lib/embed/daemon.mjs`, `#runExecutionGapAnalysis`): now returns `{ gaps, ticketsCreated, highRiskCount, ranAnalysis, error }` on every path — `ranAnalysis: false` with a specific `error` string when the Jira provider is missing, lacks `.search()`/`.write()`, the query throws, or the outer try/catch fires; `ranAnalysis: true` only on a genuine completed run. The job's scheduler callback checks `result.ranAnalysis` before treating an empty `gaps` array as "no gaps" and emits an explicit warning notification when analysis didn't run. This is a complete ran/error pair.
- **`roadmap`**: PR #409 adds only a capability guard — `if (slackProvider && typeof slackProvider.write !== 'function')` — that logs and skips the Slack post cleanly instead of letting a thrown `TypeError` reach `logCatch`. The job itself still returns no value the scheduler consumes and carries no `ran`/`resultStatus`/`error` field; the fix prevents one specific silent throw but does not give `roadmap` the same truth-reporting shape `execution-gap` now has.

So the bead's framing that #409 "already applies [the fix] to 2 of the 19 jobs" is accurate only for `execution-gap`. `roadmap` got a narrower, different fix (a write-capability guard, not a `ran`/`error` pair) — this matters because `construct-4uxq0.9.6` (the generalization work) needs to treat `roadmap` as still-unconverted, not as a second exemplar to copy.

A `WP1 silent-catch sweep` (cited in `construct-4uxq0.4.8`'s evidence list) found more sites with the same false-success shape, described as "8 additional... beyond the 3 already known" but naming 7: `lib/mcp/broker.mjs:265`, `lib/writes/envelope.mjs:142`, `lib/oracle/read-model.mjs`, `lib/oracle/execute.mjs`, `lib/providers/contract/adapters/github/index.mjs`, `lib/mcp/tools/memory.mjs`, `lib/intake/git-queue.mjs` — the count/list mismatch is in the bead's own evidence text; no eighth site was identified in this review. Independently re-checking each of the 7:

- `lib/mcp/broker.mjs:265` and `lib/writes/envelope.mjs:142` — **already fixed on this branch**, commits `af68b6ba` (`writeWithEnvelope`'s catch now handles `ApprovalRequired`/`BudgetExceeded`/`RateLimited` in addition to `PolicyDenied`, re-throwing anything unrecognized instead of letting the write proceed) and `508362ed` (`broker.mjs`'s `_recordDecision` now returns an `auditRecorded` boolean through every outcome instead of discarding whether the audit write succeeded).
- `lib/oracle/read-model.mjs` — confirmed present in `enrichReadModel()`: the dead-code audit's `catch` (around the `deadcodeFindings()` import) sets `deadCode = { present: false, deadCount: 0, regressions: [] }` on any failure — a crashed checker reports identically to a clean scan that found nothing. The adjacent beads-drift `catch { /* bd unavailable */ }` is a milder case (it leaves prior `beads` fields untouched rather than asserting a false-healthy value) but still carries no error signal.
- `lib/oracle/execute.mjs` — confirmed, scoped precisely: not the whole file (most `executeApprovedAction` branches correctly derive `ok` from real outcomes, e.g. `report.valid`, `!!result.synced`, exit code), but `dispatchSpecialist()` (used by the `specialist-review`/`trace-review`/`doctor-followup`/`executive-signoff-required`/`structure-cleanup-proposal` action kinds via `dispatchRemediation`) returns `ok: true` unconditionally even when its internal `recordAndMaybeInvoke` call throws and is caught into `gatewayResult = { recorded: false, escalated: false, reason: 'gateway-error' }`.
- `lib/providers/contract/adapters/github/index.mjs:193` — confirmed: `try { return JSON.parse(results); } catch { return []; }` — a malformed-JSON response is indistinguishable from a genuinely empty result set.
- `lib/mcp/tools/memory.mjs` — confirmed: `memorySearch`'s hybrid-store call is wrapped in `catch { /* best effort — hybrid store is optional */ }`; if the hybrid store throws and observation search also has nothing, the function's final fallback returns `{ observations: [], documents: [], total: 0, note: 'No observations recorded yet...' }` — the same shape and the same reassuring note as a genuinely empty corpus.
- `lib/intake/git-queue.mjs` — confirmed, but only in `markProcessed()`, not `claim()`. `claim()` (lines ~165-180) already does this correctly: it sets `data.durable = false`, `data.disposition = 'local-only'`, and `data.dispositionReason` when `git push` fails, and logs a warning. `markProcessed()` (line 220) does not follow that pattern: `try { this._exec('git push', ...); } catch (e) {}` is a fully empty catch with no field, no log line, and the function unconditionally `return { id }` — a failed push after marking a task processed is reported identically to a successful one.

## Decision

1. Adopt a canonical status shape that every embed-daemon job return value carries, in place of ambiguous empty-result-on-either-outcome shapes:
   - **`ran`** (boolean) — did the job's core analysis/action logic execute to completion, as opposed to exiting before doing any work (missing dependency, unsupported provider capability, thrown exception).
   - **`supported`** (boolean) — is the capability this job depends on (e.g. a provider's `.write()`/`.search()` method) available in this environment at all, independent of whether it was invoked this tick.
   - **`evidenceFresh`** (boolean) — is the underlying data the job reasoned over current, not a stale/cached snapshot standing in for a failed fetch.
   - **`resultStatus`** (enum: `ok` | `no-op` | `blocked` | `error`) — the single-field summary a downstream consumer (Oracle, a human, a test) checks first; `no-op` means "ran, found nothing to do," which is a different fact from `blocked` ("didn't run because a dependency is missing") or `error` ("ran, failed partway").
   - **`error`** (string | null) — populated whenever `ran` is `false` or `resultStatus` is `error`; `null` otherwise.
2. This is a **vocabulary decision only**: it defines the field names and their semantics as the target shape every job's return value should converge on. It does not itself migrate any of the 19 jobs to emit these fields — that is `construct-4uxq0.9.6`.
3. `execution-gap`'s current `{ gaps, ticketsCreated, highRiskCount, ranAnalysis, error }` shape is the closest existing precedent, not a second name for the same thing: `construct-4uxq0.9.6` needs to reconcile `ranAnalysis` → `ran` (plus add `supported`/`evidenceFresh`/`resultStatus`) rather than treat it as already-compliant.

## Rationale

`oracle-miss-report.md`'s M1 finding is that Oracle's verdict vocabulary cannot express "analysis didn't run" — and the report's own recommended invariant-registry seed #7, `analysis-success-requires-execution-evidence` (rows 5-6), depends on every job's evidence being checkable by one deterministic rule. A deterministic invariant cannot be written against 19 jobs that each invent their own ad hoc "did this actually run" signal (or none at all); it needs one field name and one set of enum values to assert against. Defining that vocabulary now, ahead of the 17-site migration, means the migration work has a fixed target instead of each call site improvising its own shape the way `execution-gap` and `roadmap` already diverged from each other under PR #409.

## Rejected alternatives

- **Let each job keep inventing its own fields (status quo, e.g. `execution-gap`'s `ranAnalysis`).** Rejected: already produced two different shapes for what the bead treats as one fix (`execution-gap`'s full `ranAnalysis`/`error` pair vs. `roadmap`'s narrower write-capability guard with no returned status at all); a per-job vocabulary blocks a single cross-job invariant.
- **A single boolean `ok` field, mirroring `lib/oracle/execute.mjs`'s pattern.** Rejected: `execute.mjs` itself shows the failure mode — `dispatchSpecialist()`'s unconditional `ok: true` collapses "ran and succeeded," "ran but the gateway recording failed," and other distinct states into one bit, which is the exact ambiguity this ADR is meant to eliminate, not reproduce.
- **Signal failure via thrown exceptions instead of a return shape.** Rejected: daemon jobs run inside a shared `setInterval` scheduler serving 19 independent jobs; an uncaught throw from one job must not be allowed to take down the daemon's other 18. A structured return value that the job's own top-level catch populates (with `ran: false`, `resultStatus: 'error'`, `error: <message>`) preserves catch-and-continue while still surfacing the truth, instead of catch-and-discard.
- **Defer the vocabulary decision until `construct-4uxq0.9.6`'s implementation work starts.** Rejected: the vocabulary is cheap to fix now and is a prerequisite for that work, not a byproduct of it; leaving it undecided is exactly how `execution-gap` and `roadmap` already ended up with two incompatible shapes under the same PR.

## Consequences

- Positive: gives `construct-4uxq0.9.6` (and any future job) one target shape instead of an implicit "whatever `execution-gap` happened to do"; makes the invariant-registry seed `analysis-success-requires-execution-evidence` (`oracle-miss-report.md` seed #7) mechanically checkable across all 19 jobs once they converge on it; once Oracle's own verdict vocabulary is separately addressed (truth-matrix row 24, `partial`, not in this ADR's scope), Oracle gains a real field to consume instead of inferring job health from array lengths.
- Negative / cost: 18 of the 19 jobs (all except `execution-gap`, and `execution-gap` itself needs a field rename from `ranAnalysis` to `ran` plus three new fields) do not yet emit this shape — that generalization is explicitly out of scope here and is tracked as `construct-4uxq0.9.6`, which is currently **blocked**: its premise ("#409 already converts 2 of 19 jobs") needs correcting against what PR #409 actually shipped, since `roadmap` only got a write-capability guard, not the `ran`/`error` pattern. Whoever picks up `construct-4uxq0.9.6` needs to re-scope it as 18 remaining jobs, not 17.
- Related but out of scope: the non-daemon-job silent-catch sites confirmed above (`lib/oracle/read-model.mjs`, `lib/oracle/execute.mjs`'s `dispatchSpecialist`, `lib/providers/contract/adapters/github/index.mjs`, `lib/mcp/tools/memory.mjs`, `lib/intake/git-queue.mjs`'s `markProcessed`) are not embed-daemon jobs and this vocabulary does not literally apply to their call shapes, though the same "explicit status over silent empty-default" principle motivates fixing them; they are not covered by `construct-4uxq0.9.6`'s scope and need their own follow-up beads. `lib/mcp/broker.mjs` and `lib/writes/envelope.mjs` are already fixed on this branch (commits `af68b6ba`, `508362ed`) and need no further action here.

## Reversibility

High: this is an additive field-shape convention, not a removal or a breaking change to any existing caller. A job can add `ran`/`supported`/`evidenceFresh`/`resultStatus`/`error` to its return value without breaking a consumer that still checks `result.gaps.length`; consumers migrate to checking `resultStatus` on their own schedule. If the vocabulary needs different field names or enum values later, only the (still-unimplemented, for 18 of 19 jobs) call sites and any invariant written against them need to change.
