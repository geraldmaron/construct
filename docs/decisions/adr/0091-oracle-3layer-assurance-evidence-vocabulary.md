# ADR-0091: Oracle 3-layer assurance model + evidence-status vocabulary

- **Date**: 2026-07-16
- **Status**: accepted
- **Deciders**: Gerald Dagher
- **Supersedes**: none
- **Resolves (decision only)**: `construct-4uxq0.4.7` (ADR-G) — the vocabulary and layering *decision*. The implementation work it unblocks (`construct-4uxq0.12.2`, `.12.3`, `.12.4`, and the rest of the E4 epic) is separate, tracked work that starts only once this is ratified.

## Problem

Oracle's verdict vocabulary — `healthy` / `attention` / `degraded`, computed at `lib/oracle/synthesize.mjs:467-469` — has exactly three values:

```js
let verdict = 'healthy';
if (gaps.some((g) => g.severity === 'high')) verdict = 'degraded';
else if (gaps.length > 0) verdict = 'attention';
```

This says only "how many/how severe are the gaps a detector already found." It has no way to say *why* a check produced no gap: because it ran and found nothing wrong, because no detector for that defect class exists yet, because the check didn't run at all, because it isn't applicable to this target, or because collecting evidence itself failed. Every one of those is silently indistinguishable from `healthy`.

The 2026-07 continuous-work audit's Oracle miss report names this the **M1 vocabulary gap** and calls it the most-cited systemic miss class in the accompanying 44-row truth matrix. Separately, the same audit surfaced a **meta-miss (M3)**: Oracle itself stalled for 5+ days with no independent liveness check catching it — a liveness problem, not a vocabulary problem, but discovered in the same pass and partially remediated already (see Context).

## Context

**M1 grounding.** `docs/notes/research/2026-07-continuous-work-audit/oracle-miss-report.md` defines M1 precisely: "Every row in the truth matrix tagged `contradicted`, `scaffold`, `implemented-but-disconnected`, or `dead` is invisible to Oracle's own health model." Applying that criterion directly against `docs/notes/research/2026-07-continuous-work-audit/truth-matrix.md` (44 rows) gives **26 rows**, not "15+": 4, 5, 6, 7, 8, 9, 10, 11, 17, 18, 19, 20, 21, 22, 28, 33, 34, 35, 36, 37, 38, 40, 41, 42, 43, 44. (Row 28 carries both `dead` on main and `scaffold` on branch and is counted once.) A 27th row is arguably a direct self-citation the four-tag rule itself misses: row 24, "Oracle verdict vocabulary," is tagged `partial` rather than one of the four canonical tags, but its own "Execution proof" cell reads "Vocabulary itself cannot represent most of this matrix's findings" — it is M1 describing itself. The bead's "15+" is therefore a conservative floor, not an overcount; the real number is 26 (27 including the self-referential row).

**M3 grounding and this session's partial fix.** Truth-matrix row 23 ("Oracle daemon liveness") records: heartbeat frozen `2026-07-12T18:33Z`, daemon self-shut down via `maxIdleTicks=3` after `runOracleTick()` threw on ≥3 consecutive ticks, "error swallowed by `lib/daemons/contract.mjs`, never logged," and "no supervision exists for Oracle (unlike embed)." This session's commit `9066c175` (closing `construct-4uxq0.12.1`) addresses both halves the row names, but not completely:
- **Liveness/supervision half — addressed.** `lib/embed/supervision.mjs` is generalized from an embed-only module to a `SERVICES` registry (embed, oracle) covering launchd/systemd/Task Scheduler, and wired to `construct oracle supervise`/`unsupervise`. Oracle can now be supervised independently of the embed and doctor daemons, closing the specific hole row 23 names ("no supervision exists for Oracle").
- **Root-cause-recoverability half — addressed.** `lib/daemons/contract.mjs`'s tick loop now persists the last thrown tick error (`{ message, ts }`) to the on-disk heartbeat instead of discarding it, and clears it on the next successful tick. This makes a future stall's cause forensically recoverable, which row 23 also flagged as broken ("error swallowed... never logged").
- **What is NOT addressed by `9066c175`: the vocabulary half.** The fix changes *how a daemon's own tick failures are recorded on disk*; it does not change what `synthesizeVerdict()` returns, and does not give Oracle's evidence model a way to say "this check didn't run" or "this evidence is stale" for the checks Oracle synthesizes gaps *from* (as opposed to the daemon's own tick health, which is now covered). Row 23's "meta-miss" framing was specifically that liveness and vocabulary compounded together; `9066c175` closes the liveness half of that compound failure and leaves the vocabulary half — this ADR — as the remaining half. This is a **partial**, not full, resolution of row 23.

**Current vocabulary, read in context.** `lib/oracle/synthesize.mjs:467-469` (read directly, not just per the bead's paraphrase): the function builds `gaps` and `recommendedActions` from `readModel` across roughly 400 preceding lines, routes/dispatches each gap, and only at the very end reduces the whole tick to one of three strings based purely on `gaps.length` and whether any gap is `severity: 'high'`. There is no branch anywhere in the function that can produce a value other than `healthy`/`attention`/`degraded` — confirming the bead's claim precisely.

**Actual consumers of the verdict API** (found via `grep -rn "synthesize\|\.verdict" lib/ bin/`, not assumed from the bead text):
- `lib/oracle/actions.mjs:325` — `runOracleTick()` calls `synthesizeVerdict(readModel)` directly; this is the only import of `synthesize.mjs`'s export.
- `lib/oracle/index.mjs:73` — the daemon's own tick uses `result.verdict !== 'healthy'` as one input to its `didWork` liveness signal.
- `lib/oracle/cli.mjs:96` — `construct oracle review` (and related subcommands) prints `` `Oracle verdict: ${result.verdict}` `` to stdout verbatim.
- `lib/intake/session-prelude.mjs` (`buildOraclePrelude()`, `readOracleDockState()`) — session-start context injection and the interactive dock both branch on the literal string comparison `v === 'healthy'` / `verdict !== 'healthy'` to decide whether to render the Oracle section at all.
- `lib/oracle/gaps.mjs:26` (`collectOracleGaps()`) — passes `latest.verdict` through as-is; does not branch on its value.

This is a **narrower and more precise** set than the bead's "doctor/status surfaces" framing suggests: `lib/status.mjs` has **zero** references to Oracle or verdicts (confirmed by grep — it doesn't consume this API at all today), and `lib/doctor/watchers/oracle-liveness.mjs` does not read `.verdict` either — it only reads heartbeat freshness (`lib/oracle/heartbeat.mjs`) and the pending-approval queue (`listPending()` from `lib/oracle/actions.mjs`), not the verdict string. The doctor watcher's own docstring gestures at `buildOraclePrelude()`/`readOracleDockState()` as siblings, but doesn't import them. The real coordinated-rollout surface is: the daemon's own liveness check (`index.mjs`), the CLI's raw string print (`cli.mjs`), and session-prelude's two hardcoded `'healthy'` string comparisons — three call sites across two files that must move in lockstep with any vocabulary change, not the doctor/status subsystems the bead names.

**Best-practice grounding for an 11-state vocabulary** (live web research; see Sources). The bead proposes: `passed / failed / degraded / unsupported / not-applicable / not-run / stale / incomplete / blocked / unknown / collection-error`. Checked against real prior art:
- **pytest** test outcomes: `passed / failed / skipped / xfail / xpass / error` — 6 states, and notably keeps `error` (harness-level failure) distinct from `failed` (assertion-level failure), the same distinction the bead's `collection-error` vs `failed` draws.
- **GitHub Actions** job/check-run `conclusion`: `success / failure / cancelled / skipped / timed_out / action_required / neutral / stale` — 8 states in one flat enum, including `stale` as a first-class terminal value (not a modifier field), which directly precedents the bead's choice to give `stale` its own top-level state rather than a boolean flag on another state.
- **Kubernetes** probe results: `Success / Failure / Unknown` — only 3 values, but multiplied across an orthogonal axis (readiness / liveness / startup probe *type*), i.e., real systems sometimes hold state count down by decomposing into two axes instead of one wide enum.
- **Status-page vocabularies** (e.g., Statuspage.io-style): `operational / degraded_performance / partial_outage / major_outage / maintenance` — 5 states, precedent for `degraded` as a real intermediate value distinct from outright failure at the system-health layer, not just the test layer.

None of these individually reaches 11, but Oracle's vocabulary is not doing one of these jobs — it's doing the union of a test-outcome reporter (`passed`/`failed`/`collection-error`), a job-conclusion reporter (`not-run`/`blocked`/`skipped`-equivalent), a coverage tracker (`incomplete`), a freshness tracker (`stale`), an applicability tracker (`not-applicable`/`unsupported`), and a system-health reporter (`degraded`) in one synthesized verdict per evidence item, because it sits above Layer 1 + Layer 2 + Layer 3 evidence sources at once. Measured against the *union* of what pytest, GitHub Actions, Kubernetes, and status pages each need in their narrower domains, 11 states is not wildly outside precedent — it is roughly the sum of parts real systems keep separate. `[knowledge-based, not live-researched]`: SLO/error-budget "burn rate" vocabularies were not independently web-verified this pass; they are referenced only as directional context (burn rate is typically a continuous metric with threshold bands, not a discrete status enum, and is not treated as a direct precedent for any of the 11 states above).

## Decision

1. **Adopt the 3-layer assurance model** as Oracle's evidence-collection architecture: **Layer 1 — deterministic hard checks** (mechanically provable facts: file exists, key is unique, SHA is an ancestor — per the miss report's explicit list of what belongs here and what Oracle should never compute itself), **Layer 2 — change-aware impact analysis** (dependency-graph edges connecting what changed to what could break: `schema → consumer`, `state writer → state reader`, `write-intent → approval queue → executor`), **Layer 3 — bounded semantic review** (judgment calls a deterministic check cannot make: duplicated product concepts, latent-bug review of unreached code). Oracle's role is to *consume* the evidence envelope each layer produces and escalate when it is missing, stale, or contradictory — not to compute the underlying facts itself, per the miss report's explicit closing recommendation.
2. **Replace the 3-state verdict vocabulary with an 11-state evidence-status vocabulary**: `passed / failed / degraded / unsupported / not-applicable / not-run / stale / incomplete / blocked / unknown / collection-error`. This becomes the per-evidence-item status; the existing rollup semantics (worst-status-wins escalation to a tick-level summary) carry forward, but the rollup now has eleven inputs instead of three.
3. **Coordinate the rollout across the three real consumers identified above** — `lib/oracle/index.mjs`, `lib/oracle/cli.mjs`, `lib/intake/session-prelude.mjs` — not the doctor/status subsystems the bead named, since those don't currently read `.verdict` at all.

This ADR ratifies the decision only. `construct-4uxq0.12.2` (vocabulary implementation), `.12.3` (headline invariant seed), and `.12.4` (remaining 11 invariant seeds) are the downstream implementation work, gated on this ADR per their stated dependency.

## Rationale

M1 is real, precisely defined, and — per the row-by-row cross-reference above — undercounted rather than overstated by the bead (26 rows against a "15+" claim). A vocabulary that cannot distinguish "checked, clean" from "never checked" from "checked, but the checker itself broke" cannot report honestly on any of those 26 rows' actual condition, which is the audit's core complaint about Oracle. The 3-layer model is not new invention here — it is already implicit in how the miss report assigns each row a remedy class (Layer 1 deterministic vs Layer 2 edge vs Layer 3 semantic); this ADR just makes that layering an explicit, named architecture Oracle's evidence model is built against, so each layer's evidence has a status that survives synthesis instead of collapsing to `healthy`/`attention`/`degraded` before it reaches a human.

The 11-state count, while richer than any single-domain precedent, is defensible once you account for Oracle spanning what pytest, CI job orchestrators, and status pages each do separately in narrower domains — the union of real-world precedent is close to 11, not far below it.

## Rejected alternatives

- **Keep the 3-state vocabulary, add detectors instead.** Rejected: per M1's own framing, even where a gap detector exists, a 3-state rollup still can't say *why* a check didn't fire — the vocabulary gap and the detector gap are separate problems (M1 vs M2), and fixing only M2 leaves M1 in place.
- **Adopt an even richer vocabulary (per-check custom statuses).** Rejected: unbounded, project-specific status strings break the "consume the envelope" contract Layer 1/2/3 evidence producers rely on and reintroduce exactly the ad hoc string-matching the miss report criticizes doctor's advisory-only PR review for (row 40).
- **Collapse to a leaner 5-7 state set** (e.g., merge `not-applicable`/`unsupported`, merge `stale`/`incomplete` into modifier flags on other states). Considered seriously given GitHub Actions ships 8 and pytest ships 6, but rejected for this proposal: GitHub Actions' own enum includes `stale` as a first-class terminal value (not a flag), which weakens the case for demoting it here; and `not-applicable` (this check's precondition doesn't hold for this target) is semantically distinct from `unsupported` (no producer exists yet for this check class) — collapsing them would re-erase exactly the kind of distinction M1 exists to restore. The one real risk this proposal carries forward unresolved: `not-applicable` and `unsupported` are close enough in meaning that different evidence-producer authors could tag the same situation inconsistently without a written decision rule distinguishing them — flagged for the implementation bead (`construct-4uxq0.12.2`) to resolve with an explicit definition, not solved by removing either state.
- **Fix M3 (liveness) and call the audit's Oracle finding closed.** Rejected: `9066c175` genuinely fixes the liveness/supervision half of row 23 and the tick-error-recoverability half, but explicitly does not touch `synthesizeVerdict()`'s output shape — the vocabulary half of the "meta-miss" remains open, which is exactly what this ADR is for.

## Consequences

- **Positive:** Closes the audit's most-cited systemic finding (M1) with a vocabulary rich enough to represent all 26 (27 including the self-referential row) matrix rows the audit found invisible to Oracle today. Unblocks the entire **E4 Oracle-assurance epic** (`construct-4uxq0.12`) and, directly, `construct-4uxq0.12.2` (vocabulary implementation), `.12.3` (the headline `closed-bead-sha-reachable-from-main-or-annotated` invariant, blocked on this ADR per its own `DEPENDS ON`), and `.12.4` (the remaining 11 invariant-registry seeds from the miss report). Formalizes the 3-layer model the miss report already uses implicitly, giving future invariant authors (Layer 1/2/3) a shared place to register new evidence producers against a vocabulary that can actually represent their output.
- **Negative / cost — coordinated rollout risk.** Per the grep above, three call sites in two files hardcode the literal string `'healthy'` (`lib/oracle/index.mjs:73`, `lib/intake/session-prelude.mjs` ×2) or print the raw verdict string uninterpreted (`lib/oracle/cli.mjs:96`). All three must be updated in the same change as `synthesize.mjs`, or session-prelude's Oracle section will either go permanently silent (if a new state never equals the old `'healthy'` literal) or permanently noisy (if the daemon's `didWork` liveness check now treats every non-`'healthy'` state, including the harmless new ones, as work-worthy). This is a real risk but a *smaller and more localized* one than the bead's "doctor/status surfaces" framing implied — `lib/status.mjs` and `lib/doctor/watchers/oracle-liveness.mjs` need no changes because they do not consume this API today.
- **Follow-up:** `construct-4uxq0.12.2` should update all three consumer call sites atomically with the vocabulary change, add the `not-applicable`/`unsupported` decision-rule doc the Rejected-alternatives section flags, and confirm session-prelude's dock rendering degrades sensibly for each of the 8 new states (not just the 3 it renders for today).

## Reversibility

Medium, matching the bead's own assessment. The vocabulary change itself is a pure code change (one function's return shape) and is trivially revertible in isolation. What makes it medium rather than high: the three real consumer call sites embed the literal string `'healthy'` directly rather than through a shared helper, so reverting after `.12.2` lands means reverting those call sites too, not just `synthesize.mjs` — and any invariant seeded against the new vocabulary (`.12.3`, `.12.4`) would need its evidence-status mapping revisited on rollback.
