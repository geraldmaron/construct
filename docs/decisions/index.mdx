Construct keeps three kinds of durable decision artifact, each with a numbered, append-only history.

## ADRs (Architecture Decision Records)

Short records of an architecturally significant decision that's already been made. Captures the choice, the alternatives considered, and the consequences.

[Browse ADRs →](/decisions/adr) *(coming in Phase 2)*

Source: [`docs/adr/`](https://github.com/geraldmaron/construct/tree/main/docs/adr)

## RFCs (Request for Comments)

Proposals for significant changes that need feedback before commitment. Each RFC names a problem, surveys options, proposes a direction, and lays out a migration plan.

[Browse RFCs →](/decisions/rfc) *(coming in Phase 2)*

Source: [`docs/rfc/`](https://github.com/geraldmaron/construct/tree/main/docs/rfc)

## PRDs (Product Requirements Documents)

Specifications for a feature or product — problem, audience, requirements, success criteria.

[Browse PRDs →](/decisions/prd) *(coming in Phase 2)*

Source: [`docs/prd/`](https://github.com/geraldmaron/construct/tree/main/docs/prd)

## How the lanes work

The plural directories (`docs/prds/`, `docs/rfcs/`, etc.) are init lane templates — `construct init` clones them into downstream projects. The singular directories (`docs/prd/`, `docs/rfc/`, `docs/adr/`) hold *this* repo's numbered artifacts. See [Contributing / Docs system](/contributing/docs-system) for the full lane model.
