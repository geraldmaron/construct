The next bounded slice addresses two observed problems. A newer request creates a distinct run, but delivery recovery only examines that new run; a prior reservation therefore blocks it after the original process's session has ended. Separately, the gather packet includes a whole method and final-stage instructions before any artifact-producing step; native traces show closing-method reads and no step submissions. This is an observed orchestration problem, not proof that one instruction caused the full timeout.

The intended recovery is deliberately narrow. A newer manual interactive run may replace an older preparation for exactly the same file, checkout and frozen workflow only when kernel admission/association and every holder are accounted for, old holders ended or are observably absent, no handoff is outstanding, no writing/action attempt or execution is recorded, and no artifact is present to reconcile. Unknown or quiet is insufficient. Cancellation, fencing, ledger settlement and the new reservation are atomic. Other cases return the prior run and recovery reasons. Existing effects, files, drafts and failures must survive.

Step guidance will distinguish the current method obligations from later synthesis/challenge/final review. Evidence gathering stops at a supported conclusion or explicit uncertainty/access/coverage boundary, without inventing completeness or waiving validators. Requested date cutoff, actual observation time and provider update time remain distinct; a current-date request does not prove end-of-day knowledge.
