## Primary ecosystem sources

| Source | Verified fact used in this intake | Architectural implication / limit |
|---|---|---|
| [MCP specification, 2026-07-28](https://modelcontextprotocol.io/specification/2026-07-28) and [changelog](https://modelcontextprotocol.io/specification/2026-07-28/changelog) | Current specification differs from the repository's older negotiated protocol assumptions; it describes self-contained requests and per-request capabilities. | Implement explicit supported-version negotiation and adapter tests. Do not relabel existing stdio sessions as compliant with a newer version merely because tool schemas resemble it. |
| [MCP tools](https://modelcontextprotocol.io/specification/2026-07-28/server/tools) and [resources](https://modelcontextprotocol.io/specification/2026-07-28/server/resources) | Discovery exposes tool/resource descriptions and schemas with list/pagination/change mechanisms. Tool annotations from untrusted servers are not authority. | A bridge can discover accessible operations; it still needs scope, evidence, coverage and domain mapping. The protocol does not let one server automatically see every sibling server in a host. |
| [MCP Tasks](https://modelcontextprotocol.io/extensions/tasks/overview) | Current extension uses durable task handles and status/input/result operations; client and server opt in explicitly. | Durable handle support is not a universal host capability, recurring clock, or proof that a Construct executor exists. Test installed clients; preserve an alternative supported execution contract. |
| [MCP Skills over MCP working group](https://modelcontextprotocol.io/community/working-groups/skills-over-mcp) | The linked material describes standardization work. | Do not treat a working-group charter as shipped cross-client interoperability. |
| [MCP security guidance](https://modelcontextprotocol.io/docs/2026-07-28/tutorials/security/security_best_practices) | Authorization boundaries and untrusted tool/source handling require explicit defenses. | Preserve origin, audience, scope and approval; source content cannot promote itself into an instruction or permission. |
| [OpenAPI 3.2.1](https://spec.openapis.org/oas/v3.2.1.html) | Current specification is dated 2026-09-10; it describes HTTP operations, parameters, responses and schemas. | Use interface descriptions as discoverable input, not proof of business meaning, freshness, credentials or source authority. Older served API versions remain legitimate. |
| [Agent Skills specification](https://agentskills.io/specification) | Skills package metadata, instructions and optional resources; progressive disclosure reduces initial context. | Packaging/discoverability does not prove that a host activates a method or that the method is reliable. |
| [Codex skill documentation](https://learn.chatgpt.com/docs/build-skills) and [MCP documentation](https://learn.chatgpt.com/docs/extend/mcp?surface=cli) | Skill activation and MCP setup belong to host-specific discovery/configuration surfaces. | This audit inspected local configuration and attempted the actual CLI first. Successful file generation alone did not establish live tool visibility or authenticated model operation. |
| [OpenAI: evaluating skills](https://developers.openai.com/blog/eval-skills) | Evaluation should cover explicit, implicit, contextual and negative activation cases. | Include held-out natural prompts and no-op controls rather than only typed request fixtures. |
| [Claude Code scheduled tasks](https://code.claude.com/docs/en/scheduled-tasks) | Session scheduling runs in an active client; independent scheduling mechanisms have separate lifecycle requirements. | Test the selected mechanism after exit. Do not claim that every host schedule is durable or that none can persist; session/desktop/cloud/CI mechanisms differ. |
| [GitHub Actions schedule event](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#schedule) | Scheduled jobs may be delayed/dropped under load, use the default branch and can be disabled for inactivity in public repositories. Current documentation also supports optional IANA timezone configuration. | A clock adapter needs missed-tick/idempotency policy and state restoration. Repository recipe comments about UTC should be checked against the current contract, rather than copied as ecosystem fact. |
| [VS Code MCP](https://code.visualstudio.com/docs/agent-customization/mcp-servers), [Cursor MCP](https://cursor.com/docs/mcp), [OpenCode MCP](https://opencode.ai/docs/mcp-servers) | Hosts maintain their own server configuration, tool exposure and trust surfaces. | Static adapter generation is necessary but insufficient. No live activation result for these hosts, or Bob, is claimed here. |

These sources are authoritative for their own interfaces, not independent validation of Construct. Shared standards do not constitute evidence that all host implementations support every extension. Recommendations about Construct's boundary design are **inferences** from these contracts and the local tests.
