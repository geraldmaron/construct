# Alpha.29 supervisor settlement recovery

The first release candidate `0a46971976611492c2ebb0f8a2002e28b21fc2a0`
was not merged or tagged. [Its environment-isolation job](https://github.com/geraldmaron/construct/actions/runs/38629314916/job/116076543859)
failed: the Codex MCP lead's delegated worker validation reported
`supervisor_lost`, returning blocked rather than succeeded. That job recorded
1,138 passes, one failure and one skip. Ordinary Node 22.18 and 24 jobs passed;
that did not clear the failed isolation prerequisite.

## Diagnosis and correction

The production driver settled on both child `exit` and `close`, allowing an exit
notification to settle before the parent handled a pending terminal IPC receipt.
A deterministic production-driver transport seam reproduced the exact failure
class: exit, then terminal result, then close returned supervisor_lost. Result,
exit, close passed. Missing-result and launch-error controls failed closed.
The regression failed before code correction; no timeout or retry was increased.

The driver now settles only on `close`. The watchdog sends its result before
exiting, and the channel can drain before receipt absence is judged. Existing
process-group cleanup and cancellation remain in place. The new regression also
covers missing results, launch error and cancelled results. The built-in fork seam
is restored in finally; ordinary subprocess and MCP fixtures still run afterward.

Official [Node 22 child-process documentation](https://nodejs.org/docs/latest-v22.x/api/child_process.json),
opened through Context7 on 2026-10-14, distinguishes exit from closed streams and
states that disconnect is emitted after pending messages are processed. The send
callback reports sending, not receipt handling by the parent.

Exact attribution of the Linux CI incident remains unproven. An actual Node
22.23.1 watchdog stress probe with parent event-loop delay observed result before
exit in all 60 runs; it did not reproduce the OS-level ordering. The deterministic
counterexample establishes the driver's missing settlement barrier, not proof of
which event order occurred in that historical job. Subsequent passing CI would be
observed recovery, not a retroactive trace of the original process.
