# Oracle Miss Report

For every truth-matrix row that is not `production-usable`, this asks: should Oracle (or some deterministic gate upstream of it) have caught it, why didn't it, what's the earliest reliable detection stage, and what remedy class fixes it. Miss taxonomy per the audit brief, with four **systemic** classes that recur across nearly every row — these four are the actual finding; the per-row table under them is the enumeration.

## Systemic miss classes (the real finding)

### M1 — Vocabulary gap
Oracle's verdict vocabulary (`healthy`/`attention`/`degraded`, `lib/oracle/synthesize.mjs:467-469`) has no way to express: dormant-but-present, opt-in-and-unproven, test-only, disconnected, or "analysis didn't run." Every row in the truth matrix tagged `contradicted`, `scaffold`, `implemented-but-disconnected`, or `dead` is invisible to Oracle's own health model — it can only be `attention`/`degraded` if a *gap detector* happens to exist for that specific defect, and most of these defects have no detector at all (see M2).

### M2 — Scope gap
Oracle's read model (`lib/oracle/read-model.mjs`) collects from the working tree and beads DB. It never inspects: open PR branches, deploy/template artifacts, or tracker-vs-git consistency (whether a CLOSED bead's cited SHA is reachable from main). Every defect that lives on a PR branch (rows 7-11, 18 partially, 28) or in a template (rows 36-39) is structurally outside anything Oracle could see today, regardless of vocabulary.

### M3 — Liveness gap (meta-miss)
Oracle didn't just miss individual defects — it missed *itself failing*. It self-shut-down 5 days ago (`maxIdleTicks=3` after `runOracleTick()` threw ≥3 consecutive times) and nothing escalated. The doctor watcher that's supposed to detect `oracle-producer-stalled` (`lib/doctor/watchers/oracle-liveness.mjs`) depends on the doctor daemon being alive — and doctor is *also* dead. Two independent liveness failures compounded silently. There is no third-party (outside both daemons) watching either.

### M4 — Integration gap
Tracker truth (bd) and code truth (git) are two independent sources of record with zero reconciliation between them. `construct-p4cba` closed "6/6 children complete" with real commit SHAs — but no invariant ever asks "is this SHA reachable from main?" This is exactly why the audit's headline finding (rows 43-44) went undetected for as long as it did.

## Recommended invariant-registry seed (from this report)

1. `closed-bead-sha-reachable-from-main-or-annotated` (row 44 — highest priority)
2. `tests-never-write-real-user-state`, extended to all state-file classes (row 42 — cheapest fix, guard mechanism already exists)
3. `deployment-workflow-targets-real-artifacts` (rows 36-39 — mechanically trivial)
4. `config-schema-has-no-shadowed-properties` (row 9)
5. `config-roundtrip-preserves-declared-fields` (rows 9-11)
6. `cli-references-resolve-to-real-handlers` (rows 4, 7)
7. `analysis-success-requires-execution-evidence` / job truth vocabulary (rows 5-6)
8. `due-detection-does-not-equal-completion` (row 8)
9. `external-write-has-idempotency-and-reconciliation` (rows 18-22)
10. `cross-process-state-has-one-authoritative-location` (row 41)
11. New Layer-2 edge types: `schema → normalizer/consumer`, `state writer → state reader`, `write intent → approval queue → action executor` (rows 8, 10-11, 21)
12. A third-party liveness prober independent of both embed and Oracle daemons (row 23 — cannot be solved by Oracle watching itself)

## What this report deliberately does NOT recommend
Making Oracle the enforcement point for rows 4, 7, 9, 36-39, or 44 — all of these are **mechanically provable** facts (file exists, key is unique, SHA is an ancestor) that belong in Layer 1 deterministic checks run at commit/CI time, per the assignment's explicit rule against letting Oracle substitute for hard gates. Oracle's correct role for all of them is to *consume* the Layer-1 evidence envelope and escalate when evidence is stale, missing, or contradictory — not to compute the fact itself.
