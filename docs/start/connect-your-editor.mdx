title: Connect your editor
description: Construct syncs host adapters to Claude Code, OpenCode, Codex, Copilot, VS Code, and Cursor. Two scopes — global keeps only the `construct` front door; project carries every specialist.
---

`construct sync` keeps one canonical registry and writes the right host-specific shape for each supported tool. The CLI runs in two scopes:

- **Global (`construct sync --global`, or the `npm i -g` postinstall)** writes only the `construct` front-door agent into your home directory. It's how `@construct` becomes reachable from any project. Specialists do **not** land at global scope — they would otherwise pollute every VS Code / Copilot / Cursor picker on your machine regardless of whether the workspace uses Construct.
- **Project (`construct sync` inside a Construct project, or `construct init`)** writes the orchestrator + all 28 `cx-*` specialists, slash commands, skills, and MCP wiring under the project's own `.claude/`, `.codex/`, `.opencode/`, `.github/`, `.vscode/`, `.cursor/` trees. Files version with the repo and travel with teammates via git.

`construct sync` auto-detects a Construct project (presence of `.cx/` or `.construct/`) and runs project mode when inside one; global mode otherwise. Pass `--global` or `--project` to force a tier.

## Claude Code

**Global tier** writes the orchestrator agent and the session-level hook installer:

- `~/.claude/agents/construct.md` — the `construct` front-door agent
- `~/.claude/settings.json` — pre/post tool-use hooks, session-start, MCP server entry for `construct`. Hooks have to stay global because they fire in every Claude Code session, not just inside a Construct project.
- `~/.claude/CLAUDE.md` — a Construct-managed block appended to your global Claude instructions

**Project tier** writes the full agent set + project-local Claude config:

- `<project>/.claude/agents/construct.md` and `cx-*.md` — orchestrator + 28 specialists
- `<project>/.claude/settings.json` — project-portable hooks (relative paths via `.construct/run.mjs`)
- `<project>/.claude/commands/*.md` — slash commands
- `<project>/.claude/skills/<name>/SKILL.md` — Anthropic Agent Skills

In Claude Code, address the persona with `@construct` from any session. Inside a Construct project the same prefix works for specialists: `@cx-engineer`, `@cx-security`, `@cx-architect`. Outside a project, only `@construct` is registered.

## OpenCode

**Global** writes only the orchestrator agent into `~/.config/opencode/opencode.json` (the existing provider auth, models, and unrelated agents are preserved on merge).

**Project** writes `<project>/.opencode/config.json` with the orchestrator + 28 specialists, providers, MCP servers, and the runtime plugin. OpenCode's per-project config layer shadows the global one, so teammates get the same setup automatically.

## Codex (CLI)

**Global** writes `~/.codex/agents/construct.toml` and registers it in `~/.codex/config.toml` under `[agents.construct]`, plus any Construct MCP entries in the managed block.

**Project** writes `<project>/.codex/agents/{construct, cx-*}.toml` and updates the project's `config.toml`.

## Copilot

**Global** writes only `~/.github/prompts/construct.prompt.md` and a minimal Construct-managed block in `~/.github/copilot-instructions.md` listing the front-door prompt.

**Project** writes 29 `.prompt.md` files under `<project>/.github/prompts/` (orchestrator + 28 specialists) and a richer managed block in `<project>/.github/copilot-instructions.md`. This follows Copilot's documented convention — workspace `.github/prompts/` is the recommended scope and the files travel with the repo via git.

## VS Code

VS Code MCP wiring is **project-only**. Construct writes `<project>/.vscode/mcp.json` per the official VS Code MCP config format. Existing entries are preserved on merge; only Construct's own servers are added.

We intentionally don't touch user-scope `settings.json → github.copilot.mcpServers` anymore — that approach polluted every VS Code window with Construct's MCP servers regardless of whether the workspace had anything to do with Construct.

## Cursor

**Project** writes `<project>/.cursor/mcp.json` (Cursor's documented per-project MCP config) and `<project>/.cursor/rules/construct.mdc` (a minimal rule explaining Construct is the front door for this project). Cursor has no global rules concept by design.

If `~/.cursor/mcp.json` already exists, **global** sync merges Construct's own MCP server entries in there too so `construct` MCP tools are reachable from any Cursor workspace.

## What stays global vs goes to the project

| Surface | Global tier | Project tier |
|---|---|---|
| Claude agent files | `construct.md` only | `construct.md` + 28 `cx-*.md` |
| Claude hooks + settings.json | yes (always global — session-level) | project-portable copy with relative paths |
| CLAUDE.md | Construct-managed block | project `CLAUDE.md` |
| Codex agent TOMLs | `construct.toml` only | `construct.toml` + 28 `cx-*.toml` |
| OpenCode config | `construct` agent + MCP | full orchestrator + 28 specialists + plugins |
| Copilot prompt files | `construct.prompt.md` only | 29 prompt files |
| copilot-instructions.md | minimal Construct block | full listing |
| VS Code MCP | — | `.vscode/mcp.json` |
| Cursor MCP | merged into existing `~/.cursor/mcp.json` if present | `.cursor/mcp.json` + `.cursor/rules/construct.mdc` |
| Slash commands | — | `.claude/commands/*.md` |
| Skills | — | `.claude/skills/<name>/SKILL.md` |

Hooks stay global because they're session-level (pre-tool-use, session-start). Everything else follows each host's documented best-practice scope: agents/prompts/MCP-for-the-team live with the project repo; only the personal front-door agent lives in `~/.`.

## Migration from older Construct versions

If you ran an older version of Construct that wrote specialists to user-scope (`~/.claude/agents/cx-*.md`, `~/.github/prompts/cx-*.prompt.md`, `~/.codex/agents/cx-*.toml`), the next `construct sync --global` cleans them up automatically — only files whose names match a registered specialist are removed, so any user-authored `cx-*` files you kept in those directories stay put.

## Cross-surface parity

`construct doctor` includes a parity check that diffs your registry against every installed editor's adapter state. If you add a specialist and forget to sync, doctor reports the drift.

```bash
construct doctor
# ... look for "Cross-surface adapter parity"
```

Fix drift with `construct sync`.
