**Describe the bug**

Hi, we run `argocd app diff <app> --revision <branch>` in our CI and some jobs fail with the following missing permissions error:

```json
{
  "level": "fatal",
  "msg": "rpc error: code = Unknown desc = error performing state diffs: failed to calculate diff: error calculating server side diff: serverSideDiff error: error running server side apply in dryrun mode for resource ClusterRole/cert-manager-cainjector: clusterroles.rbac.authorization.k8s.io "cert-manager-cainjector" is forbidden: user "system:serviceaccount:argocd:argocd-server" (groups=["system:serviceaccounts" "system:serviceaccounts:argocd" "system:authenticated"]) is attempting to grant RBAC permissions not currently held:%0A{APIGroups:[""], Resources:["events"], Verbs:["update"]}%0A{APIGroups:[""], Resources:["secrets"], Verbs:["list" "watch"]}%0A{APIGroups:["admissionregistration.k8s.io"], Resources:["mutatingwebhookconfigurations"], Verbs:["list" "watch" "update"]}%0A{APIGroups:["admissionregistration.k8s.io"], Resources:["validatingwebhookconfigurations"], Verbs:["list" "watch" "update"]}%0A{APIGroups:["apiextensions.k8s.io"], Resources:["customresourcedefinitions"], Verbs:["list" "watch" "update"]}%0A{APIGroups:["apiregistration.k8s.io"], Resources:["apiservices"], Verbs:["list" "watch" "update"]}%0A{APIGroups:["cert-manager.io"], Resources:["certificates"], Verbs:["list" "watch"]}",
  "time": "2026-02-05T11:06:03+01:00",
}
```

The failing jobs are all in projects where we recently enabled the sync impersonation flag; the cluster Secret credential itself is broad, so we don't understand why the diff suddenly runs with a narrower identity.

**To Reproduce**

Application:

```yaml
apiVersion: argoproj.io/v1alpha1
kind: Application
metadata:
  annotations:
    argocd.argoproj.io/compare-options: ServerSideDiff=true,IncludeMutationWebhook=true
    argocd.argoproj.io/manifest-generate-paths: ./..
  name: cert-manager
  namespace: argocd
spec:
  destination:
    name: in-cluster
    namespace: cert-manager
  project: default
  source:
    helm:
      releaseName: cert-manager
      valueFiles:
        - ../values-common.yaml
        - ./values.yaml
    path: cert-manager/my-cluster
    repoURL: https://gitlab.com/org/repo.git
    targetRevision: HEAD
  syncPolicy:
    automated:
      prune: true
      selfHeal: true
    managedNamespaceMetadata:
      labels:
        app.kubernetes.io/managed-by: argocd
        protected: "true"
    retry:
      refresh: true
    syncOptions:
      - CreateNamespace=true
      - FailOnSharedResource=true
      - PruneLast=true
      - ServerSideApply=true
```

> The targeted path is just referencing the cert-manager chart as a dependency:

```yaml
apiVersion: v2
name: cert-manager
version: 1.0.0

dependencies:
  - name: cert-manager
    version: v1.19.1
    repository: https://charts.jetstack.io
```

**Expected behavior**

ArgoCD Application Controller service account used to produce the diff to avoid this failure.
