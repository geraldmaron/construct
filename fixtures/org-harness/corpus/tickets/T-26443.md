# T-26443: [Hydrator] Prevent Sync from syncing old Hydrated files when hydrator source changes

> Origin: https://github.com/argoproj/argo-cd/issues/26443 (verbatim base; see PROVENANCE.md for edits)

# Summary

When the hydrator sync source changes and the application have auto-sync configured, it will immediately sync the existing manifest in the path, if any. 

# Motivation

This can be undesirable if the manifest in that path are very old. It is common if the application is moved to a "group"/branch that it belonged to in the past.

We only observe this when the hydrator runs in push-to-stage mode; the external promoter has not yet moved the fresh manifests to the deployment branch, so auto-sync picks up whatever the stage branch last held.

# Proposal

1. If possible, the Sync should wait for the hydrated files to be "fresh". However, it is difficult to determine if the hydrated files are old/dirty or not. 

2. Add an annotation on the app with a timestamp, this would prevent any possible sync to files with an hydrator.metadata that is older than this annotation. A downside of this approach is the coupling with the hydrator metadata and the sync process. After a hydration is completed, that annotation should be removed by the hydrator. The hydrator could also detect that it needs to do a "hard refresh/rehydrate" when the annotation is present on the app. 

Perhaps another way to accomplish in a more generic way this is to "block" the sync if the hydrated annotation (or the "hard" hydrate annotation value" is present on the App. This way, we can ensure that hydrate happens before the sync, and the coupling with the sync process is only based on an annotation, and not a file in Git.

## Alternative

An alternative would be to have the user disable the auto-sync temporarily when changing the sync source, then re-enabling it after the hydration. However, this is an imperative process and the declarative configuration should allow for a smooth transition without errors.
