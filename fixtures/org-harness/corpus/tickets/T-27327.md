# T-27327: History & Rollback support for Source Hydrator

> Origin: https://github.com/argoproj/argo-cd/issues/27327 (verbatim base; see PROVENANCE.md for edits)

# Summary

When source hydrator is enabled, have the "History & Rollback" tab's "Rollback" function render directly to the sync branch.

# Motivation

As we're gradually rolling out gitops-promoter + argocd source hydrator,
one of the first questions we get when onboarding new users is how do rollbacks work?

Existing deployments not using source hydrator can quickly roll back via argocd's app history tab.

# Proposal

ArgoCD with Source Hydrator enabled has rendered manifests in a git branch as the source of truth. There aren't any additional controls on the specific revision of the branch.

To achieve a rollback while maintaining that model, we want to roll back the desired application state, while rolling forward the git branch.

Source hydrator has 2 modes: direct, and pushing to a staging branch. I propose for both modes, rollback directly updates the sync branch (bypassing the staging branch).
Single application/environment rollbacks are irregular operations, which don't fit into existing promotion flows.

Branches / environments can be shared by multiple applications. Rollbacks should only affect the single application that triggered it.

Re-render vs checkout. The dry source in git does not fully capture the inputs to rendering, as the Application.spec may change. it's safer to checkout the old rendered manifests than trying to re-render.

Recovery after rollback. argpcd should add enough commit metadata for any promotion system to later make a decision on whether it is safe to promote new commits.
Blocking new commits is out of scope.

Signed branches. This push happens outside the commit server, so if the target branch's SourceIntegrity policy requires verified signatures, the commit lands unsigned and the git host rejects the push. The Rollback button in the UI just shows a failed push; there's no messaging tying it back to signing, and no retry path from the History and Rollback tab, so the operator is stuck until someone tracks down the commit server's signing config by hand.

To summarize, rollback should be more or less:

```
git checkout $sync_branch
git checkout $rollback_revision -- $sync_path
git commit 
git push $sync_branch
```
