# T-27875: Auto-sync broken when new commit arrives during ongoing sync (after revert of #25151)

**Describe the bug**

After upgrading from v3.3.9 to v3.4.2, applications with `automated` sync policy (without `selfHeal`) no longer auto-sync correctly when a new commit arrives while the app is still being synchronized to a previous commit. The app detects OutOfSync but skips the sync operation.

This affects all source types (Directory, Helm/git, etc.) when `manifest-generate-paths` annotation is set. It is NOT specific to Directory-type sources.

This was introduced by the revert of #25151 in #27241 (cherry-picked as b15e9e3cc to release-3.4).

**Root Cause**

The failure sequence:

1. App starts auto-syncing to commit A
2. While sync to A is still in progress, commit B is pushed
3. Post-sync comparison resolves HEAD → commit B, detects OutOfSync, sets `Status.Sync.Revision = B`
4. Next reconciliation: `evaluateRevisionChanges` gets `syncedRevision = Status.Sync.Revision` (= B as SHA), `revision = "HEAD"` (raw ref string)
5. Since `syncedRevision != revision` (string comparison, SHA vs ref), condition is true → calls `UpdateRevisionForPaths`
6. Inside `gitSourceHasChanges`: resolves HEAD → B, LsRemote(B) → B. Both are the same SHA → returns `Changes: false`
7. `revisionsMayHaveChanges = false` → `autoSync` receives `shouldCompareRevisions = false`
8. `alreadyAttemptedSync` skips revision comparison entirely, checks source config only → matches
9. Without `selfHeal` enabled → skips auto-sync. App stays OutOfSync indefinitely.

The issue is that `Status.Sync.Revision` reflects the last *compared* revision, not the last *synced* revision. After comparison updates it to commit B (before sync happens), `UpdateRevisionForPaths` compares B against B and concludes nothing changed — even though the app never actually synced to B.

**To Reproduce**

The key condition is: **a new commit B must arrive while the application is still syncing to commit A.**

Application (any source type — Directory, Helm/git, etc.):
```yaml
apiVersion: argoproj.io/v1alpha1
kind: Application
metadata:
  name: debug-autosync
  annotations:
    argocd.argoproj.io/manifest-generate-paths: .
spec:
  project: default
  source:
    repoURL: https://github.com/example/repo.git
    targetRevision: HEAD
    path: my-app
  destination:
    server: https://kubernetes.default.svc
    namespace: default
  syncPolicy:
    automated:
      prune: true
      # selfHeal is NOT set (defaults to false)
```

Steps:
1. Deploy the app, let it start syncing to current HEAD (commit A)
2. While the sync to commit A is still in progress, push a new commit B that changes a file under the app's path
3. App detects OutOfSync to commit B but never auto-syncs to it
4. Controller logs show: `"Already attempted sync: revisions [<sha>] have no changes"` followed by `"Skipping auto-sync: most recent sync already to [<sha>]"`

Adding `selfHeal: true` works around it (bypasses `alreadyAttemptedSync`), as does removing `manifest-generate-paths`.

**Expected behavior**

Apps with `automated` sync policy (even without `selfHeal`) should auto-sync when a new commit changes files under their path, regardless of whether a previous sync is still in progress.

**Suggested fix**

A robust fix would be to use `OperationState.SyncResult.Revision` (actual last synced revision) instead of `Status.Sync.Revision` (last compared revision) when determining if changes occurred. This correctly distinguishes "we compared against B" from "we synced to B."
