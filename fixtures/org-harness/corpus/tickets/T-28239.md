# T-28239: feat(hydrator): sign hydrated commits

> Origin: https://github.com/argoproj/argo-cd/issues/28239 (verbatim base; see PROVENANCE.md for edits)

# Summary

The Source Hydrator's commit server should be able to **GPG-sign the hydrated commits it pushes**. Today it always pushes unsigned commits, so if signature verification is enabled for the hydrated branch, Argo CD rejects its own hydrated output.

# Motivation

[#19302](https://github.com/argoproj/argo-cd/issues/19302) (PR [#28084](https://github.com/argoproj/argo-cd/pull/28084)) added the *verification* side: the hydrator can now verify GPG signatures on the dry source. But the other half is missing — the commits the hydrator writes to the hydrated/sync branch are unsigned.

# Proposal

Let the commit server sign every hydrated commit before pushing, opt-in via `argocd-cmd-params-cm`:

- `commitserver.sign.hydrated.commits` (default `false`)
- `commitserver.signing.key.path` — path to the ASCII-armored GPG private key
- `commitserver.signing.key.passphrase.file` — optional passphrase file for a protected key

Key behaviour:

- The signing key is mounted from a Secret in the Argo CD namespace.
- **Fail fast, no silent fallback:** if signing is enabled and the key is missing/invalid, the commit server fails at startup; it refuses to push any commit it cannot locally verify against the configured key.
- One cluster-wide signing key to start (per-project keys out of scope for now).
- The operator adds the corresponding **public** key to `argocd-gpg-keys-cm` and the project's `SourceIntegrity` policy so the hydrated branch is actually enforced.
