# T-28695: Server-Side Diff on external clusters ignores destinationServiceAccounts, requiring unbounded patch RBAC

**Describe the bug**

Application **sync** honors the AppProject's `destinationServiceAccounts` impersonation. The **diff** path does not — it runs as the cluster credential from the cluster Secret.

On external clusters that credential is deliberately narrow. Server-Side Diff issues a server-side apply dry-run, which the API server authorizes as a `patch`. Kubernetes RBAC has no dry-run verb — authorization happens before the dry-run flag is evaluated — so *computing a diff* requires *write authority* on every resource type in the Application.

The grant is unbounded in practice: each new chart introduces a resource kind, which produces a `ComparisonError`, which forces another `patch` rule onto the cluster role. We've now done this five times:

| Round | Kinds added |
|---|---|
| 1 | Namespaces, Roles/RoleBindings, Kyverno policies |
| 2 | StorageClasses, StatefulSets, DaemonSets |
| 3 | ServiceAccounts, ClusterRoles/ClusterRoleBindings, CRDs, webhook configurations |
| 4 | IngressClasses, NetworkPolicies, Secrets |
| 5 | ExternalSecrets |

There is no end state. And because RBAC cannot express "dry-run only," each grant is *real* write authority — the safety story rests on Argo CD's convention of always sending `dryRun=All`, not on any enforced boundary. These are deliberately least-privilege identities, which makes broad `patch` a hard sell.

Relevant to #24134 (Make Server Side Diff enabled by default): if SSD becomes the default without the diff path honoring `destinationServiceAccounts`, every external-cluster user hits this on upgrade with a `ComparisonError` and no obvious cause.

**To Reproduce**

1. Register an external cluster with a least-privilege ClusterRole (read-all, narrow workload mutation).
2. Enable impersonation: `application.sync.impersonation.enabled: "true"` in `argocd-cm`.
3. Map the destination to a privileged SA via the AppProject's `destinationServiceAccounts`.
4. Enable Server-Side Diff: `controller.diff.server.side: "true"` in `argocd-cmd-params-cm`, or the per-App annotation.
5. Deploy any chart shipping a resource kind outside the narrow mutation set (e.g. an ExternalSecret).

Sync succeeds — it impersonates the mapped SA. Diff fails, and the App rotates `Synced` ↔ `Unknown` on every reconcile.

**Expected behavior**

Server-Side Diff should run as the same identity as sync — honor `destinationServiceAccounts` when impersonation is enabled. That SA is already trusted for the write; the diff would need no additional grant, and the least-privilege boundary on the standing cluster credential would hold.

**Workaround**

`ServerSideDiff=false` on all external-cluster Applications, per the [documented opt-out](https://argo-cd.readthedocs.io/en/stable/user-guide/diff-strategies/).

Measured cost: **zero**. Across ~20 monitoring charts (Mimir, Loki, Alloy, blackbox, node-exporter, kube-state-metrics, ALB controller, Kyverno), including StatefulSets with `volumeClaimTemplates`, client-side diff produced no cosmetic OutOfSync and required no `ignoreDifferences`.
