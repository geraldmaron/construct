# T-28755: Parallel progressive sync steps

> Origin: https://github.com/argoproj/argo-cd/issues/28755 (verbatim base; see PROVENANCE.md for edits)

# Summary

`RollingSync` steps are sequential barriers — step N+1 cannot begin until every application matched by step N is healthy. This works well for a simple staging → production progression, but breaks down at scale
  when clusters are logically independent of each other.

# Motivation
This should boost release delivery time in large organisations where ArgoCD is managing many stg+prod cluster groups so all production clusters are not blocked by waiting for all staging clusters to finish syncing.

# Proposal

Proposed API sketch:
```
  rollingSync:
    steps:
      - parallel:
        - matchExpressions: [trust-domain=main, env=staging]
        - matchExpressions: [trust-domain=main, env=production]
      - parallel:
        - matchExpressions: [trust-domain=CD, env=staging]
        - matchExpressions: [trust-domain=CD, env=production]
```
or
```
  strategy:
    type: RollingSync
    rollingSync:
      parallelGroups:
        - steps:
            - matchExpressions:
                - key: trust-domain
                  operator: In
                  values: [main]
                - key: environment
                  operator: In
                  values: [staging]
            - matchExpressions:
                - key: trust-domain
                  operator: In
                  values: [main]
                - key: environment
                  operator: In
                  values: [production]
        - steps:
            - matchExpressions:
                - key: trust-domain
                  operator: In
                  values: [CD]
                - key: environment
                  operator: In
                  values: [staging]
            - matchExpressions: ...
```
