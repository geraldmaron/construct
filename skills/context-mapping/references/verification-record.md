# Verification record and composition

Closing template for a context map. Read when the map is ready to finalize.

```
Verification record
- Typed throughout:   answered - <n> relationships, all typed
- Evidence tagged:    answered - read <n> / ran <n> / was-told <n> / inferred <n>
- Load-bearing upgraded: answered - <which, and to what> | none lean hard
- Unknowns classified: answered - <n> unknowns: <n>/<n>/<n> by kind | zero, justified at <where>
- Dated:              answered - created <date>, last updated <date> | refreshed: <what>
- Handoff passes:     answered - run as stranger; added: <what, or nothing>
```

A gate that was not done says `not done - <reason>` in its slot. Never
deleted, never skipped silently. Presence, not quality.

## Composition

When several skills govern one deliverable, the owner of the deliverable's
shape produces the full record; every other skill contributes one line.
Every "see <where>" quotes a short fragment of its target.

## Enforcement

Nothing in the skill file is machine-enforced by that file. Typing,
evidence tags, and the record are obligations on you. A persistent store
or provenance engine adds a deterministic tier on top; the skill works
identically with or without one.
