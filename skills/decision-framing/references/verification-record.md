# Verification record and composition

Closing template for a framed decision. Read when the deliverable is ready
to finalize.

```
Verification record
- Framed as a choice:   answered - see <where>
- Constraints separated: answered - see <where>
- Rivals real:          answered - see <where>
- Consequences concrete: answered - see <where>
- One recommendation:   answered - see <where>
- Strongest objection:  answered - see <where>
- Pre-mortem:           answered - see <where> | weakened the recommendation: <yes/no>
- Record complete:      answered - see <where>
```

A gate that was not done says `not done - <reason>` in its slot. Never
deleted, never skipped silently. Until every line is filled, label the
deliverable a draft in its title line. Presence, not quality.

## Composition

When several skills govern one deliverable, the owner of the deliverable's
shape produces the full record; every other skill contributes one line.
Every "see <where>" quotes a short fragment of its target.

## Enforcement

Nothing in the skill file is machine-enforced by that file. Frame, gates,
and records are obligations on you. An environment that checks the
records' presence adds a deterministic tier on top.
