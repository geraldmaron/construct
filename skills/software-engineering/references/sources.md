# Sources: Software engineering

Doctrine this pack rests on. Each entry names what it is used for and when it was last reviewed. Verified: not opened in this build; these are cited from the author's knowledge and must be opened and re-checked before a finding leans on a specific clause or number. Time-sensitive doctrine carries a review-due date.

- Google Engineering Practices, Code Review Developer Guide (google.github.io/eng-practices/review). Used for: review posture, what a reviewer owes an author, scope of a change. Reviewed: 2026-09-02, review due 2027-09.
- DORA research program (dora.dev): deployment frequency, lead time, change failure rate, time to restore. Used for: which delivery signals matter and why batch size is a risk. Reviewed: 2026-09-02, review due 2027-03.
- Semantic Versioning 2.0.0 (semver.org). Used for: what a version bump promises and when a dependency upgrade is a breaking change. Reviewed: 2026-09-02; stable.
- OWASP Secure Coding Practices Quick Reference (owasp.org). Used for: the input-handling and secrets checks a change must not regress. Reviewed: 2026-09-02, review due 2027-03.
- The Twelve-Factor App (12factor.net). Used for: configuration, statelessness, and disposability expectations of a service change. Reviewed: 2026-09-02; stable.
- Feathers, Working Effectively with Legacy Code (ISBN 978-0131177055). Used for: characterization tests before changing untested code. Reviewed: 2026-09-02; stable.
