# Sources: Software engineering

Doctrine this pack rests on. Each entry names what it is used for and when it was last reviewed. Each entry was opened on 2026-10-17 and says what was confirmed; a finding that leans on a specific clause or number still opens that clause. Time-sensitive doctrine carries a review-due date.

- Google Engineering Practices, Code Review Developer Guide (https://google.github.io/eng-practices/review/). Used for: review posture, what a reviewer owes an author, scope of a change. Reviewed: 2026-09-02, review due 2027-09. Opened 2026-10-17: the page exists and links a reviewer guide ("How To Do A Code Review") and an author guide ("The CL Author's Guide"), with review criteria covering design, functionality, complexity, tests, naming, and documentation.
- DORA research program (https://dora.dev/guides/dora-metrics/). Used for: which delivery signals matter and why batch size is a risk. Reviewed: 2026-09-02, review due 2027-03. Opened 2026-10-17: the page now names five metrics, grouped as throughput (change lead time, deployment frequency, failed deployment recovery time) and instability (change fail rate, deployment rework rate); "time to restore" is now "failed deployment recovery time", and the page names reducing batch size as a common way to improve all five.
- Semantic Versioning 2.0.0 (https://semver.org/). Used for: what a version bump promises and when a dependency upgrade is a breaking change. Reviewed: 2026-09-02; stable. Opened 2026-10-17: 2.0.0 is the version shown; MAJOR is for incompatible API changes, MINOR for backward-compatible additions or deprecations, PATCH for backward-compatible bug fixes.
- OWASP Secure Coding Practices Quick Reference (https://owasp.org/www-project-secure-coding-practices-quick-reference-guide/), now carried by the OWASP Developer Guide (https://devguide.owasp.org/). Used for: the input-handling and secrets checks a change must not regress. Reviewed: 2026-09-02, review due 2027-03. Opened 2026-10-17: the Quick Reference project is archived and its checklists were migrated to the Developer Guide, whose web application checklist includes a "Validate All Inputs" item; a dedicated secrets-handling item was not found on the pages opened, so the secrets half of this use is not confirmed.
- The Twelve-Factor App (https://12factor.net/). Used for: configuration, statelessness, and disposability expectations of a service change. Reviewed: 2026-09-02; stable. Opened 2026-10-17: the twelve factors include config in the environment, stateless processes, and disposability (fast startup, graceful shutdown).
- Feathers, Working Effectively with Legacy Code (ISBN 978-0131177055) (https://openlibrary.org/isbn/9780131177055.json). Used for: characterization tests before changing untested code. Reviewed: 2026-09-02; stable. Opened 2026-10-17: the Open Library record confirms the title, Michael C. Feathers as author, Prentice Hall 2004, and this ISBN; the book's chapter content was not opened.
