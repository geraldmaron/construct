# Welcome to Construct

This file was generated by `construct init` to help you get oriented. It's safe to edit: Construct only writes it once, then leaves it alone.

**Full docs:** [https://geraldmaron.github.io/construct/](https://geraldmaron.github.io/construct/)

## Day one — what you need to write code

You added Construct as a dev dependency. That gave you:

- **One entry surface: `@construct`.** In your editor (Claude Code, OpenCode, Codex, Cursor, or Copilot), you talk to one entity. Construct classifies the request and routes work to internal Worker Profiles (architect, engineer, security, operations, designer, …) based on what you asked for.
- **Hard gates.** Every code change runs through commit-time policy: no secrets, tests green, docs current, comments lint-clean. Bypass exists for every gate but leaves an audit trail. Gates stay on even when you skip optional surfaces below.
- **Persistent session state.** Active work and decisions survive across sessions under `.construct/` — you do not need Beads, intake, or the dependency graph to ship a one-file fix.

You don't need to manage any of that: it all runs locally. No database or Docker is required for the default solo install.

### How to talk to Construct

In your editor:

```
@construct help me add OAuth to the login flow
```

Construct will classify the request, route to the right Worker Profiles, and stream results back in one conversation. Steer when you know the domain:

```
@construct run a security review on the auth middleware for OWASP top 10
```

Run `construct worker-profile list` to see Worker Profile descriptions.

### Day-one commands

| Command | What it does |
|---|---|
| `construct install --footprint=user` | Machine setup, once per machine: XDG config, LanceDB path, completions |
| `construct init` | Project setup, once per repo: scaffold `.construct/`, AGENTS.md, plan.md, adapters |
| `construct doctor` | Health check across config, services, agents, hooks |
| `construct sync` | Regenerate platform adapters (Claude Code, OpenCode, Codex, Cursor, …) |
| `construct status` | Live runtime status (services, providers) |

## Files Construct created or manages

Generated tooling (`.construct/`, `.claude/`, host adapter dirs, `plan.md`) is gitignored; the user-owned files (`AGENTS.md`, `docs/`, `construct.config.json`) are the ones committed as project content. Peers who clone and run `npm install` regenerate adapters via the postinstall hook.

| Path | What it is | Touch? |
|---|---|---|
| `.construct/launcher/` | Launcher for hooks. Don't edit. Regenerated on `npm install`. Gitignored. | No |
| `.claude/agents/` | Worker Profile adapters. Regenerated on `npm install` / `construct sync`. Gitignored. | No |
| `.claude/commands/` | Slash commands. Regenerated on `npm install` / `construct sync`. Gitignored. | No |
| `.claude/settings.json` | Hooks + MCP server config. Construct keys are managed; your additions are preserved. Gitignored (regenerated per machine). | Carefully |
| `.construct/` | Per-project session state (active work, decisions, this guide). Construct writes here. Gitignored. | Read-mostly |
| `AGENTS.md` | Agent guide. Construct owns only its fenced integration block; the rest is yours. | Yes: your house rules go here |
| `plan.md` | Active work plan. Local-only (gitignored). | Yes: your current focus |
| `docs/` | Documentation lanes (ADRs, PRDs, memos, …). Default init creates `docs/` only; opt into packs with `--docs-preset=lean\|product\|full`. | Yes: this is your team's docs |
| `construct.config.json` | Project config (Workspace Preset, orchestration, intake). Committed. | Yes |
| `.construct/construct_guide.md` | This file. Friendly orientation. Gitignored. | Yes: adapt to your team |

## When you need them (opt-in power surfaces)

Construct keeps advanced work-tracking and signal surfaces available without teaching them as day-1 mandatory. That matches progressive disclosure: show the few options that serve most tasks first, and defer specialized ones until asked for ([NN/g — Progressive Disclosure](https://www.nngroup.com/articles/progressive-disclosure/); workplace cognitive-load framing also summarized in Construct's artifact-authorship skill).

| When… | Use | Not required for… |
|---|---|---|
| Work spans sessions or needs blockers/audit | Beads — `.beads/` via `bd` / `construct beads` | A one-file edit or chat Q&A |
| Work arrives as a file (bug report, paste, URL dump) | Drop into `inbox/`, then `construct intake list` / `show` / `done` | Typing `@construct …` in chat |
| You want a per-signal execution plan from a triaged packet | `construct graph from-intake <id>` | Writing code after a normal chat ask |
| You declare change impact before a large refactor | `construct graph intent declare` (team/dogfood gate; not lean day-1) | Shipping a small fix |
| A download landed on Desktop/Downloads | `construct drop` | Manual path paste into chat |

House rules you want every session: put them in `AGENTS.md`.

For continuous watching of `inbox/`: `construct config set autoEmbed true` then `construct embed supervise`. Otherwise run `construct intake` after dropping files. Stage large/slow writes under `inbox/.staging/` and rename in so the watcher never sees a half-written file.

## How to change Construct settings

Two scopes:

**Per-project** (committed, shared with peers): edit `construct.config.json`. Host adapter files under `.claude/` (and sibling host dirs) are machine-local and regenerated by `npm install` / `construct sync`; Construct owns the `hooks` block and known `mcpServers` keys when those files exist, and preserves your additions (including opt-in MCPs like `playwright` via `construct mcp add playwright`).

**Per-machine** (private to you): edit `~/.config/construct/config.env` (created by `construct install --footprint=user`). This is where your API keys, consent flags (`BOOTSTRAP_*`), and local-service preferences live. Standard `KEY=value` format.

After editing settings, run:

```bash
construct sync               # regenerate platform adapters from any registry changes
construct doctor             # verify everything's healthy
```

## Local services

Everything is local files — setup opens no host ports and stands up no database. Run `construct install --footprint=user` once per machine, then `construct doctor` to verify.

**Traces** — local-first observability

- Local: machine-scoped JSONL under the Construct state root (see `construct status`); optional remote export with `CONSTRUCT_TRACE_BACKEND=langfuse|http|otel`

**Vector storage** — semantic search on embedded LanceDB

- Embedded LanceDB index at `~/.local/state/construct/vector/lancedb` (override with `CONSTRUCT_LANCEDB_PATH`)
- 384-dim embeddings via `Xenova/all-MiniLM-L6-v2`
- The embedding model auto-downloads to `~/.cache/construct/embeddings/` on first use (~22 MB, one time)

Any services `construct dev` starts later (memory, the OpenCode bridge) bind to `127.0.0.1` only — nothing is reachable from other machines on your network.

## Updating Construct

```bash
npm update @geraldmaron/construct
```

That refreshes the agents, hooks, and slash commands in `.claude/` and `.construct/launcher/`. Your `.construct/` state, `AGENTS.md`, `plan.md`, and `docs/` content is untouched.

## When things go wrong

```bash
construct doctor              # most issues surface here with a fix hint
construct stop && construct dev  # restart optional local helpers if you use them
```
